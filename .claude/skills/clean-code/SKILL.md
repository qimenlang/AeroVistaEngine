# clean-code

原则在 `cpp-vsg-style`、`clean-code-guardrails`、`engine-complexity-gates`、`build-test-discipline`。这里只写判定和步骤。

只看本次 agent 新写或新改的 C++，路径限 `engine/`、`thirdparty/sync/`、`thirdparty/config/`。其余 `thirdparty/`（含 `thirdparty/vsg`）不动。不扫全库，不回溯本次没改的文件。

本轮若是验收测试轮、用户还没说「开始实施」：不改生产代码。要报告就走只读入口。

## 入口

**写代码。** 不必等用户点名。先判定死分支并删除，再做下面的清理，然后按 `build-test-discipline` 验证。回复里每次都打完整报告，用「已删 / 已改」。这次没有删改，也要写出保留、跳过和验证。

**要报告。** 用户点名要 clean-code 报告，或只要求审查、还没授权修改。用同一套判定列出「会删 / 会改 / 保留 / 跳过」。不改文件，不跑构建、测试、tidy、lizard，也不跑 `coverage_engine.py`。

## 死分支

死分支只由调用链判定。`scripts/coverage_engine.py` 的分支覆盖只说明测试有没有走到；计数为 0 不是可删证据。代码一改，旧的 `out/coverage/coverage.profdata` 就作废。不为判定去跑它。

对本次新增或改过的 `if`、提前返回、以及只为「别崩」而写的失败路径：

1. 写出它守卫的状态。
2. 把现有直接调用方读全。调用方不在本次改动里，只读不改。不要为了让分支变死而去改调用方。
3. 每个调用方标明：能造出该状态，或不能。
4. 全部不能，才是死分支。连同只为它服务、且在本次改动文件里的代码一起删。只读入口则标「会删」。
5. 调用没追完（函数指针、虚调用、注册表、回调还没读到）就跳过，不算死分支。

有来源就保留：

- 外部报文、协议字段、第三方 API 的返回值
- 套接字、驱动、配置文件读入、操作系统调用

以后也许会有的调用方、「理论上可能为空」、调用方刚刚创建或检查过的对象，都不是来源。

测试、配置或设计文档若把这条路径写成契约，保留，并在报告里写明。

`return` / `throw` / `break` / `continue` 之后的语句是局部不可达，归清理第 1 条，不必做调用链追溯。

```cpp
// 两个调用方都是刚 create 成功后传入。没有人传空。删掉。
if (!device) {
    return false;
}

// 报文来自外部 Host，长度不由本仓库保证。保留。
if (packet.size() < headerBytes) {
    return RejectReason::SHORT;
}
```

## 清理

死分支处理完后，对同一批文件按顺序做。拿不准就跳过。可观察行为不变：输入、输出、副作用、错误行为、公开接口不动。

测试文件不改断言、场景注释和验收措辞。生成文件不碰。排版交给 `clang-format`，不手排 include。

1. `return` / `throw` / `break` / `continue` 之后不可达的语句。
2. 整段注释掉的代码。
3. 没有副作用的空 `if` / `else`。
4. 未使用的 `#include`、局部变量、私有函数。公开接口或 `override` 上的未使用参数保留原名。
5. 不改变行为的卫语句：深层嵌套收成提前返回。
6. 表达式：`== true` / `== false`，`if (cond) return true; else return false;`，双重否定，整数的 `* 1` / `+ 0`，自我赋值，只为马上返回而存在的临时变量。浮点 `* 0` 跳过。
7. 同一个函数里、两边文本一致的重复分支，提到条件外面。

只读入口对第 1–7 条标「会改」，不动文件。

## 不做

- 不把未覆盖分支当成死分支，不为判定去跑 `coverage_engine.py`。
- 不扫全库，不回溯本次没改的文件里同类的 `if`。
- 不把签名改成 `std::optional`，不拆 boolean 入参，不跨文件搬代码，不改名。
- 不拆只转发一次的薄适配层。
- 不把重复字面量抽成常量。
- 不加功能、不补注释或文档、不加依赖、不改算法。

## 验证

只读入口不验证。

写代码入口按 `build-test-discipline`。删分支或改控制流算逻辑改动。`engine/source` 跑全量构建、测试，以及对改动文件跑 tidy / lizard。`thirdparty/sync`、`thirdparty/config` 同样跑对应测试和复杂度门禁。只删注释掉的代码、且没动到 token 时，可以只做增量编译。没跑的验证在报告里写明。

## 报告

写代码入口每次都打下面这份完整报告，用「已删 / 已改」；没有删改也要打，对应小节写「无」。只读入口用「会删 / 会改」，验证行写「未跑（只读报告）」。

```text
[clean-code] 模式：<写代码 / 只读>
[clean-code] 范围：<本次改动里实际看过的文件>
[clean-code] 死分支：
- <文件:符号>：<已删 / 会删>。直接调用方都造不出该状态
- <文件:符号>：保留。<外部报文 / 协议字段 / 第三方返回 / 套接字 / 驱动 / 配置 / 系统调用 / 契约>
[clean-code] 清理：
- <文件>：<不可达 / 注释代码 / 空块 / 未使用 / 卫语句 / 表达式 / 重复分支>，<已改 / 会改>，净改 <N> 行
[clean-code] 跳过：<处>，<调用未追完 / 拿不准 / 不在本次改动>
[clean-code] 验证：<命令与结果；只读则写未跑>
```
