# 文档同步核查（doc-sync）

权威原则见 `CLAUDE.md` §5 / `.cursor/rules/doc-sync.mdc`（同源）。本 skill 是它的**可执行流程**：
规则管「原则与硬约束」，本 skill 管「一步步怎么核查、用什么命令、怎么报告」。

## 工具脚本

机械核查由 `scripts/doc_sync_check.py` 承担，三个子命令。exit 语义：`0` = 干净/无命中，`2` = 扫描出错（读失败/正则非法）。

- `python scripts/doc_sync_check.py --list` — 列全 `doc/design/` 设计文档（决策日志标 `[只读]`）
- `python scripts/doc_sync_check.py --stale "<旧符号|旧术语>"` — 在 `doc/design/` + `doc/notes/` 检索残留（正则，`|` 分隔多词）。**报告型**：命中不影响 exit，因为命中可能是「已否决/已删除」的合法说明性上下文，由你判断
- `python scripts/doc_sync_check.py --index` — 校验 `doc/private/README.md` 清单 vs 实际文件。**门禁型**：失效链接 / 未登记文件是客观事实，命中 exit 1，可接入 CI

脚本只负责「列全、检索、比对」这些机械动作；「是否触及、怎么改、命中是否属说明性上下文」由你判断。

## 何时触发

判断标准（对所有模块通用，不按「改的是哪个模块」枚举）：
本次改动是否**改变了 `doc/design/` 任一文档描述的行为、协议或 API**——是则触发。

- 触及的典型形态（示例，非完整清单）：公开接口签名、协议 / 载荷布局、线程 / 执行模型、
  时序、网络收发、写死的行为决策
- 不只新功能：重构、修 bug 改行为、收敛 / 合并机制同样触发
- 纯命名 / 格式改动（不改变行为）不触发

另两种触发：

- 更新 `doc/` 下任一文档（新增 / 删除 / 改名 / 改章节标题 / 改文件名）
- 用户显式 `/doc-sync`

## 流程 A：改代码后，同步设计文档

按序执行：

1. **列全** `doc/design/` 下所有设计文档：`python scripts/doc_sync_check.py --list`。
2. **逐份判断**：本次改动是否触及该文档描述的行为 / 协议 / API。触及 → 更新；未触及 → 跳过。
3. 更新时逐项核对七项：
   - **签名**：公开 API（`sendCommand`、回调、注入接口）与文档 §API 表一致
   - **载荷布局**：协议字节布局与文档一致；测试 helper 与实现两端一致
   - **执行/线程模型**：文档描述与实际线程结构一致；目录锚点文本 = 实际 § 标题
   - **行为决策**：写死决策有记录；废弃机制标注「已否决」
   - **实现状态表**：§「与实现关系」表的待实现 / 已实现反映现状（按标题引用，不写编号——该节在各文档编号不同）
   - **跨文档引用**：各设计文档互引与措辞一致
   - **已删除符号**：文档不引用已删除的类 / 函数名，改用行为描述替代
4. **自查残留**（交差前必做）：

   ```bash
   python scripts/doc_sync_check.py --stale "旧函数名|旧术语|旧行为描述"
   ```

   期望：无命中，或命中仅为「已否决 / 已删除」的说明性上下文。
5. **报告**（见「输出格式」）。

## 流程 B：改文档后，同步关联文档

1. 找出所有引用处：
   - 索引与交叉引用：`python scripts/doc_sync_check.py --index`（失效链接 / 未登记文件）
   - 锚点与编号：`rg` 该文档的**文件名、标题、章节编号**：

     ```bash
     rg "被改文件名|被改标题|§数字" doc/
     ```

2. 逐项同步：
   - **索引**：`doc/private/README.md` 文件清单与实际文件一致（新增 / 删除 / 改名都要更新）
   - **交叉引用链接**：路径随移动 / 改名变化，须改
   - **锚点 / 编号**：§ 标题或编号变了，指向它的锚点与「详见 §X」要同步
3. 触及则更新，未触及跳过。
4. **报告**。

## 硬约束：决策日志只读

- 文件名含「决策日志」（如 `决策日志.md`）或位于 `**/决策日志/` 目录 → AI **只读**，不改写 / 追加 / 删除。
- **按文件名 / 目录匹配，不按内容判断**（设计文档里大量出现「决策」「否决」，按内容会误伤）。
- 用户要求「同步 / 更新决策日志」时，提醒：决策日志由用户亲手维护，AI 不代写。

## 输出格式

完成后按此模板报告：

```text
[doc-sync] 本次改动触及的设计文档：
- <文件>：改了 <签名/载荷/执行模型/行为决策/状态表/引用/删除符号 哪几项>
- <文件>：未触及，跳过
[doc-sync] 关联文档同步：
- doc/private/README.md：<更新了什么>
- <文件>：<交叉引用/锚点 更新了什么>
[doc-sync] 自查残留：
- 命令：python scripts/doc_sync_check.py --stale "<旧符号|旧路径|旧编号>"
- 结果：无命中 / 命中如下（附上下文，含是否「已否决/已删除」的说明性上下文）
[doc-sync] 决策日志：只读，未改动
```

## 通用原则

- 自查用 `rg` / 脚本，不凭记忆判断「应该没别处引用」。
- 纯命名 / 格式改动（不改变行为）不需同步文档；但目录锚点随 § 标题变更要同步。
- 文档与文档之间、文档与代码之间，改动后必须一致，不留指向旧名 / 旧路径 / 旧编号的失效引用。
