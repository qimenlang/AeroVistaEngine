# 重构书籍清单

每本一两句：这本书讲什么、读完能带走什么。只列值得读的；口碑分化、只值得部分读的，单独一节标明。

## 核心

| 书 | 一两句话 |
| --- | --- |
| 《软件设计的哲学》（John Ousterhout，2018） | 全书围绕 complexity：三个症状（放大、认知负荷、未知的未知）、两个成因（dependencies、obscurity），然后是 deep modules、information hiding、pull complexity downward。短、密度高、观点鲜明。`重构技能总结.md` 里 depth / shallow 的词汇源头就在这里。 |
| 《重构》（第 2 版，Martin Fowler） | 重构手法的目录：每个手法有动机、步骤、示例，可以当工具书查。前半部分的「坏味道清单」回答「该重构什么」，手法回答「怎么安全地改」。 |
| 《修改代码的艺术》（Michael Feathers，2004） | 讲最难的一段：给没有测试的遗留代码加测试。seam 的概念出自这里。示例语言陈旧，概念全部经住了时间考验。当工具书查，不必通读。 |
| 《整洁代码》（Robert C. Martin） | 讲好代码长什么样：命名、函数、注释、错误处理。与 Fowler 互补——这本给目标形态，Fowler 给从现状走过去的路径。部分观点有争议（函数越小越好），带着批判读。 |

## C++ 专属

| 书 | 一两句话 |
| --- | --- |
| 《C++ Software Design》（Klaus Iglberger，2022，O'Reilly） | 用现代 C++（11/17）重讲设计原则与模式，核心主张「继承不是唯一的多态」：type erasure、value semantics、variant Visitor。最出色的是 value semantics 和 type erasure 两章。讲设计成什么样，不讲怎么改过去；对照 `vsg::Inherit` 继承体系读，能判断哪些继承是实的 seam。 |
| 《大型 C++ 软件设计》（John Lakos） | 物理设计：头文件依赖、编译防火墙、模块边界。引擎这类大工程的跨模块重构先看这本的分层思路。 |

## 只取一瓢

| 书 | 一两句话 |
| --- | --- |
| 《架构整洁之道》（Robert C. Martin，2017） | 公认有价值的内核只有一个：依赖规则（依赖指向内）加 boundary，policy 与 detail 分离。其余篇幅冗长、说教、示例是 Web 业务域，对引擎这类领域映射不好。不整本读，只取依赖规则。 |

## 进阶

| 书 | 一两句话 |
| --- | --- |
| 《重构与模式》（Joshua Kerievsky） | 把重构和 GoF 打通：讲怎么一步步演化出模式，而不是一次画完大图。适合已经熟悉 Fowler 手法之后读。 |

## 综合排序（结合本工程）

| 优先级 | 书 | 理由 |
| --- | --- | --- |
| 1 | 《软件设计的哲学》 | 短、密度最高；`重构技能总结.md` 词汇的源头 |
| 2 | 《重构》 | 手法目录 + 坏味道清单，怎么安全地改 |
| 3 | 《C++ Software Design》 | 唯一一本现代 C++ 设计书；对照 VSG 继承体系 |
| 4 | 《修改代码的艺术》 | 遗留代码加测试，工具书用法 |
| 5 | 《架构整洁之道》 | 只取依赖规则一瓢饮 |

## 读法建议

先读《软件设计的哲学》（一天能读完，词汇直接对上 `重构技能总结.md`）；再读 Fowler 第 2 版前半（原则 + 坏味道 + 核心手法）；Feathers 当工具书按处境查；《架构整洁之道》只读依赖规则相关章节；Clean Code 挑函数、命名、注释三章精读即可。
