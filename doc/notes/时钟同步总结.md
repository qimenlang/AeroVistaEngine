# 时钟同步知识总结

多通道同步中「时间」相关的通用知识与本项目选型结论。本项目初步方案见 [时钟同步方案.md](../design/多通道同步/时钟同步方案.md)；多通道整体设计见 [多通道同步模块设计.md](../design/多通道同步/多通道同步模块设计.md)。

## 1. 时钟偏差的本质：offset 与 skew


| 概念               | 含义                         | 单位     | 特性                               |
| ---------------- | -------------------------- | ------ | -------------------------------- |
| **offset（相位偏差）** | 两台机器本地时钟的**绝对差值**（"现在差多少"） | 秒 / ms | 可被 NTP/PTP 校正；与"流逝时长"无关          |
| **skew（频率偏差）**   | 两台机器晶振**跑速的比值差**（"一快一慢"）   | ppm    | 消费级晶振典型 ±20~±100 ppm；随温度/电压/老化漂移 |
| **drift（漂移率）**   | skew 本身的变化率                | ppb    | 温度变化引起，所以需要周期测量                  |


```text
offset(t) = 初始相位差 + ∫ skew(t) dt
```

- 「快的永远快、慢的永远慢」只在**外在条件不变**时成立（skew 近似恒定 → offset 线性累积）；实际中温度变化使偏差是曲线而非直线。
- **时钟同步不是"设成同一个起点"**，而是**持续校正**，让两台机器在任意时刻都对齐——PTP/NTP 周期测量并校正 offset 与 skew 两个量。



## 2. 墙上时钟 vs 单调时钟


| 时钟       | C++ 对应                      | 特性                                             | 用途            |
| -------- | --------------------------- | ---------------------------------------------- | ------------- |
| **墙上时钟** | `std::chrono::system_clock` | 与真实世界时间（UTC）对齐；**可被 NTP/PTP 校正、可能回跳**（闰秒/手动改时） | 显示"几点"；时间戳对时  |
| **单调时钟** | `std::chrono::steady_clock` | 单调递增、测量间隔准确；**不受系统时间调整影响**；起点是开机时间             | 测"流逝时长"（外推增量） |


**关键**：测流逝时长（外推）必须用单调时钟。若用墙上时钟，NTP 恰好回跳 500ms 时外推会瞬间倒退。

本项目：`vsg::clock = std::chrono::steady_clock`（`thirdparty/vsg/include/vsg/ui/UIEvent.h`），`engine.cpp` 用它测帧耗时——已用对。

## 3. NTP 与 PTP



### 3.1 NTP（Network Time Protocol）

- **原理**：客户端-服务器往返测量，一次交换取 4 个时刻，假设单向延迟对称：

```text
offset = ((t1 - t0) + (t2 - t3)) / 2
delay  = (t3 - t0) - (t2 - t1)
```

- **结构**：分层（stratum 0 原子钟/GPS → stratum 1 → …），每层累积误差。
- **打戳**：软件层；周期轮询（几十秒级）；slew 平滑调整避免跳变。
- **精度**：LAN 软件打戳 **毫秒级**（1–10ms）；内核时间戳可到 100µs–1ms；加 PPS 才 µs 级。
- **硬件要求**：无。



### 3.2 PTP（IEEE 1588）

- **原理**：主从结构，BMC 算法选出 grandmaster。两步模式：

```text
Master 发 Sync → 网卡 PHY 硬件打戳记录 t1 → 随后发 Follow_Up 携带 t1
Slave  硬件打戳记录 t2 → 发 Delay_Req 记录 t3 → Master 回 Delay_Resp 记录 t4
offset = t2 - t1 - delay；delay = ((t2-t1) + (t4-t3)) / 2
```

- **核心差异**：**硬件打戳**（网卡物理层），消除操作系统调度与协议栈抖动；配合边界时钟/透明时钟修正交换机驻留时间。
- **精度**：亚微秒级（几十 ns ~ 1µs）。
- **硬件要求**：PTP 网卡，最好支持时钟的交换机；部署复杂。
- **适用**：工业控制、广电、仿真产线（CIGI 常见）。



### 3.3 两者对比与定位


| 维度   | NTP       | PTP                |
| ---- | --------- | ------------------ |
| 精度   | 毫秒级       | 亚微秒级               |
| 硬件要求 | 无         | 硬件打戳网卡 + 支持时钟的交换机  |
| 部署   | 简单普适      | 复杂、网络设备要配合         |
| 适用   | 通用 IT、广域网 | LAN 实时系统（仿真/工控/广电） |


> **注意**：PTP/NTP 的核心产出是 **offset（时钟偏差）**，不是"传输链路耗时"。链路耗时（delay）只是推导 offset 的中间量。业务 UDP 报文的实际时延通常**标定为常量**（LAN 内 <1ms）或直接忽略，不是 PTP 实时测出来的。



## 4. 消费时间戳的两种模式（关键）


| 模式               | IG 怎么用                        | 是否需要时钟同步                            |
| ---------------- | ----------------------------- | ----------------------------------- |
| **模式 A：逐帧消费** | 把「本帧收到的最新 `simTimeMs`」当**基准**，消费时刻用本地单调时钟补偿流逝（`基准 + (now - 收到时刻)`） | **不需要**——Host 下发的数值就是权威基准，本地时钟只用于测流逝增量 |
| **模式 B：本地外推/插值** | 两次包之间用本地时钟推算"Host 现在应该是多少" | **需要**——本地时钟必须与 Host 对齐，误差直接进推算 |


- 本项目初步方案 = **模式 A**（权威时间戳基准 + 本地流逝补偿）。
- 模式 A 下，两台 IG 时钟快慢差多少、偏差累积多少，**对仿真时间数值毫无影响**——host 说 1000ms 就是 1000ms。本地时钟只当"节拍器"决定渲染节奏，以及测"距基准的流逝时长"。



## 5. 外推的误差分析

丢包时外推公式：

```text
估计 simTime = 上一帧 Host simTimeMs + (IG 本地流逝时长) × (1 + skew 校正)
```


| 误差源                      | 量级       | 对短窗口外推的影响                                           |
| ------------------------ | -------- | --------------------------------------------------- |
| **相位偏差 offset**（几百 ms 级） | 秒级       | **不进入公式**——基准是 Host 权威数值，只用增量，起点无所谓                 |
| **频率偏差 skew**            | ±100 ppm | 乘在流逝时长上：外推 100ms → 误差 ≈ 10µs；1 秒 → 100µs；10 秒 → 1ms |
| **host 帧节奏波动**           | 毫秒级      | FreeRun 下每帧增量非恒定（渲染卡顿会漂），**是外推的主导误差**               |
| 链路时延                     | <1ms     | LAN 内相对帧周期可忽略；通常标定常量或忽略                             |


**结论**：

- 短窗口外推（1~2 帧）时，时钟偏差影响微乎其微（ppm 级），**PTP 收益接近零**；
- 长窗口外推（秒级）时，频率偏差累积 + host 帧节奏波动占主导——PTP 都解决不了后者；
- 所以正确策略是**外推设上限，超时冻结等恢复**，而不是追求长窗口外推精度。

> **更重要的边界**：外推的不只是时间，还有**眼点**。长时间没包意味着网络故障或 host 挂了——光把时间推准，画面还停在旧位姿，时间与位置对不上，本身就是错乱的。



## 6. 行业先进多通道方案：三层分离

高端 IG（CAE / L3Harris 级）不是"host 时间戳为准"或"PTP 为准"二选一，而是三个维度三种机制同时成立：


| 维度      | 同步什么      | 机制         | 行业做法                       |
| ------- | --------- | ---------- | -------------------------- |
| **状态**  | 位姿/实体/环境  | host 下发权威值 | **以 host 为准**（CIGI 实体/控制包） |
| **时间**  | 各机"现在是几点" | 本地时钟对齐     | **PTP / house sync**       |
| **帧呈现** | 同一帧同时上屏   | swap 对齐    | **Genlock / Framelock 硬件** |


- **host 时间戳 = 帧的标签**（这一帧的仿真时刻）；**PTP 对齐的本地时钟 = IG 渲染过程的实时时间轴**（渲染要好几 ms，光照/动画要连续时间）。
- 两者不冲突，各司其职。

## 7. 本项目结论

- **初步方案（已定）**：以 host 时间戳为准（模式 A），收不到时短窗口外推（单调时钟增量 + 上限冻结）。**不需要 PTP/NTP**。
- **PTP 定位**：不是被淘汰，而是被"以 host 时间为权威"推迟/规避了；未来做延迟标定 / 高精度时间对齐时按需追加（`doc/design/多通道同步/时钟同步方案.md` §7）。
- **行业对标**：CIGI 协议本身不强迫上 PTP；当前阶段用 host 时间戳方案是对的，架构留扩展位即可。
