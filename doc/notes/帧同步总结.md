# 帧同步知识总结

多通道同步中「帧呈现」相关的通用知识与本项目选型结论。本项目初步方案见 [帧同步设计.md](../design/多通道同步/帧同步设计.md)。四层总览与 VSync / 撕裂深入见 [多通道同步业务梳理.md](./多通道同步业务梳理.md)。CIGI **Message Synchronization**（报文节拍，不是本层）见 [状态同步总结.md](./状态同步总结.md)；节拍设计见 [状态同步设计.md](../design/多通道同步/状态同步设计.md) §3。

---

## 1. 帧同步在四层里管什么

```text
时钟同步：大家手表一致            （时间基准）
状态同步：大家算同一个世界        （数据内容）
帧同步：  大家同时 Present 同一帧 （应用换帧时刻）
显示同步：显示器扫描相位一致      （物理扫描时序）
```

- **本质**：各通道把已经渲染好的**同一逻辑帧 N**在同一时刻 `Present` / `SwapBuffers`。
- 逻辑帧号标识「哪一帧」；Present 对齐才是帧同步。两者常一起做，但不是同一层。
- **不是**状态同步（眼点/实体内容），**不是**时钟同步（仿真时间数值），**不是**显示同步（扫描/VBlank 相位），**不是** CIGI Message Sync（谁决定何时发下一包）。
- 硬件上 Swap Barrier 依赖垂直回扫已经对齐（Framelock）；概念上仍可分开讲。

---

## 2. NVIDIA 分层（Present vs 扫描）

按 NVIDIA Quadro Sync / `WGL_NV_swap_group` 手册，不是「Frame Lock = 目标、Swap Group = 手段」：

```text
（可选）Genlock / External Sync
        → 锁到外部 house sync                         显示同步
        Framelock
        → 锁各 GPU 输出的扫描起止（VRetrace 同相）      显示同步
        Swap Group
        → 本机多窗口同时 SwapBuffers                   帧同步
        Swap Barrier
        → 跨组 / 跨机等齐后再 Present                   帧同步
          （规范：垂直回扫未对齐则不保证跨组同时发生）
```

| 概念 | 同步的是 | 归属 |
| --- | --- | --- |
| **Genlock** | 锁到外部 house / 投影机 | 显示同步 |
| **Framelock** | 多 GPU **输出光栅**起止 | 显示同步 |
| **Swap Group** | 本机多个窗口同时 Present | 帧同步 |
| **Swap Barrier** | 跨组/跨机等齐后再 Present | 帧同步 |

口语义：AMD 示例里口头 “Framelock” 常直接指 SwapBuffers 对齐；NVIDIA 把 Framelock 与 Swap sync 分成两步。OpenGL Present 接口是 `wglJoinSwapGroupNV` / `wglBindSwapBarrierNV` 等（**没有** `wglQueryFrameLockNV`）；Vulkan 为 `VK_NV_present_barrier`；D3D 走 NvAPI，不是 `IDXGISwapChain::Present` 本身。

撕裂是**单屏**问题（换帧发生在扫描中途，VSync 管）；多通道看到的接缝错位是**通道间相位差或帧号不一致**。软件 Barrier 开了各机 VSync 后通常不撕，仍可能接缝错位（最多约半帧）。

## 3. CIGI 没有 Present 栅栏

ICD §4.2 标题是 Message Synchronization：包的**节奏**，不是何时一起 Present。SOF 是帧**开头**心跳；Barrier 在渲**完**。详解、§4.2.1 / §4.2.2 译文见 [状态同步总结.md](./状态同步总结.md)。

统一 Host 帧号扇出不依赖 §4.2.2。用 SOF 放行「这一帧上屏」= 用「开始」当「结束」。

## 4. 软件 vs 硬件帧同步

| 实现 | 手段 | 精度 | 场景 |
| --- | --- | --- | --- |
| **软件** | 统一逻辑帧号 + 网络 Barrier + 再 Present（各机仍跟本地 VSync） | 帧号级，跨机仍可能差数 ms | 研发 / 非严格拼接 |
| **硬件** | Swap Group / Swap Barrier | 亚帧 / 亚 ms | 拼接墙、多投影 |

软件方案管线：

```text
同一逻辑帧 N（通常 = Host Frame Number）
  → 各 IG 渲完 N
  → 互报 ready / 汇总后放行
  → 一起 Present（仍等各自 VBlank，除非再上 Framelock）
```

无 Barrier / 有 Barrier（含「本口 VBlank 早于 `release`、该 IG 再等一帧」）时序见 [帧同步设计.md](../design/多通道同步/帧同步设计.md) §2.1。

掉帧策略（丢帧 / 重复帧 / 外推）是软件 Barrier 的配套，不是 Message Sync 的职责。UDP 上 IGCtrl / SOF / `ready` / `release` 用 **同号连发** 降丢包率（不改 TCP、不停等 ACK），见 [帧同步设计.md](../design/多通道同步/帧同步设计.md) §3.5；连发不替代超时。连发是拷贝快照，与时钟方案 C（同号改戳）互斥；Barrier 开着时不要走 C。

`ready`/`release` 额外耗时、贴满 60fps 时不要开软件 Barrier：见帧同步设计 §3.6。

## 5. 与 Message Sync 的关系（本层视角）

**不是同一层，也不是无关。** 节拍影响「N 何时出现在各 IG 入口」；本层决定「已经是 N 之后何时一起翻页」。两种节拍上都能做软件 Barrier。SofGated 只把 master 对齐到帧头；其它通道仍各刷各的 VSync。接缝要齐：软 Barrier 或硬件 Swap/Framelock。

本项目：Barrier **未做**。节拍缺省 FreeRun、SofGated 待做，见状态同步设计。选型：Barrier 与节拍正交；对比时一次只动一个旋钮。开发前基线见 [多通道同步验收测量设计.md](../design/多通道同步/多通道同步验收测量设计.md)。
