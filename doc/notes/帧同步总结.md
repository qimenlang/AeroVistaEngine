# 帧同步知识总结

多通道同步中「帧呈现」相关的通用知识与本项目选型结论。本项目初步方案见 [帧同步设计.md](../design/多通道同步/帧同步设计.md)。四层总览与 VSync / 撕裂深入见 [多通道同步业务梳理.md](./多通道同步业务梳理.md)；CIGI 报文节拍见 ICD SISO-STD-013-2014 §4.2 与 [cigi梳理.md](./cigi梳理.md)。

---

## 1. 帧同步在四层里管什么

```text
时钟同步：大家手表一致            （时间基准）
状态同步：大家算同一个世界        （数据内容）
帧同步：  大家同时 Present 同一帧 （应用换帧时刻）
显示同步：显示器扫描相位一致      （物理扫描时序）
```

- **本质**：各通道把已经渲染好的**同一逻辑帧 N**在同一时刻 `Present` / `SwapBuffers`。
- 逻辑帧号标识「哪一帧」；Present 对齐才是帧同步。两者常一起做，但不是同一层。
- **不是**状态同步（眼点/实体内容），**不是**时钟同步（仿真时间数值），**不是**显示同步（扫描/VBlank 相位）。
- 硬件上 Swap Barrier 依赖垂直回扫已经对齐（Framelock）；概念上仍可分开讲。

---

## 2. NVIDIA 分层（Present vs 扫描）

按 NVIDIA Quadro Sync / `WGL_NV_swap_group` 手册，不是「Frame Lock = 目标、Swap Group = 手段」：

```text
（可选）Genlock / External Sync
        → 锁到外部 house sync                         显示同步
        Framelock
        → 锁各 GPU 输出的扫描起止（VRetrace 同相）      显示同步
        Swap Group
        → 本机多窗口同时 SwapBuffers                   帧同步
        Swap Barrier
        → 跨组 / 跨机等齐后再 Present                   帧同步
          （规范：垂直回扫未对齐则不保证跨组同时发生）
```

| 概念 | 同步的是 | 归属 |
| --- | --- | --- |
| **Genlock** | 锁到外部 house / 投影机 | 显示同步 |
| **Framelock** | 多 GPU **输出光栅**起止 | 显示同步 |
| **Swap Group** | 本机多个窗口同时 Present | 帧同步 |
| **Swap Barrier** | 跨组/跨机等齐后再 Present | 帧同步 |

口语义：AMD 示例里口头 “Framelock” 常直接指 SwapBuffers 对齐；NVIDIA 把 Framelock 与 Swap sync 分成两步。OpenGL Present 接口是 `wglJoinSwapGroupNV` / `wglBindSwapBarrierNV` 等（**没有** `wglQueryFrameLockNV`）；Vulkan 为 `VK_NV_present_barrier`；D3D 走 NvAPI，不是 `IDXGISwapChain::Present` 本身。

撕裂是**单屏**问题（换帧发生在扫描中途，VSync 管）；多通道看到的接缝错位是**通道间相位差或帧号不一致**。软件 Barrier 开了各机 VSync 后通常不撕，仍可能接缝错位（最多约半帧）。

## 3. CIGI §4.2 不是帧同步

ICD 标题是 **Message Synchronization**：谁决定 Host↔IG **何时发下一包**。

| ICD | 管什么 |
| --- | --- |
| **§4.2.1 Asynchronous** | Host 按自己的间隔发 IGCtrl；IG 自持帧率；建议用 Timestamp 纠延迟 |
| **§4.2.2 Synchronous** | IG 的 SOF（常挂这台 IG 的 VSync）卡住 Host；每帧一对报文 |
| **§4.3 帧号** | 丢包检测 / Last Host、Last IG 回显；CIGI 3.2 起 Host 帧号与 IG 帧号**独立** |

SOF 典型含义是「我这一显示帧**开始了**」（heartbeat），不是「第 N 帧已渲完、可以一起 Present」。

ICD 默认一对 Host–IG；多 IG 组播时建议只认一台 **master** 的 IG→Host 包。那是「共用一份 Host 状态」，不是各 IG 等齐上屏。

状态在包**里**；§4.2 是包按什么**节奏**走。Present 栅栏 CIGI **没有**。

## 4. 软件 vs 硬件帧同步

| 实现 | 手段 | 精度 | 场景 |
| --- | --- | --- | --- |
| **软件** | 统一逻辑帧号 + 网络 Barrier + 再 Present（各机仍跟本地 VSync） | 帧号级，跨机仍可能差数 ms | 研发 / 非严格拼接 |
| **硬件** | Swap Group / Swap Barrier | 亚帧 / 亚 ms | 拼接墙、多投影 |

软件方案管线：

```text
同一逻辑帧 N（通常 = Host Frame Number）
  → 各 IG 渲完 N
  → 互报 ready / 汇总后放行
  → 一起 Present（仍等各自 VBlank，除非再上 Framelock）
```

掉帧策略（丢帧 / 重复帧 / 外推）是软件 Barrier 的配套，不是 Message Sync 的职责。

---

## 5. SOF 与 Barrier 相位相反

```text
master SOF（§4.2.2）  → 发状态之前（帧开头）
软件 Present Barrier  → 上屏之前（渲完）
```

用 SOF 放行「这一帧上屏」= 用「开始」当「结束」。§4.2.2 只能当**上游节拍**（何时 mint 第 N 帧），不能当 Barrier。

统一 Host 帧号扇出**不依赖** §4.2.2：Host 一次 `flush` 给全体 IG 填同一个 `Host Frame Number` 即可（本项目 FreeRun 已如此）。

---

## 6. 两种 Message Sync 与帧同步的关系

**不是同一层，也不是无关。** Message Sync 影响「N 何时出现在各 IG 入口」；帧同步决定「已经是 N 之后何时一起翻页」。

| | §4.2.1 Asynchronous / FreeRun | §4.2.2 Synchronous（通常认一台 master SOF） |
| --- | --- | --- |
| 同一 Host 帧号扇出 | 可以（本项目已有） | 同样可以 |
| Present Barrier | 都要另做 | 都要另做 |
| Host 与显示心跳 | Host 自走，与各 IG VSync 会 creeping（一帧 0 包或 2 包） | Host 跟 **master** 帧头对齐，master 上少 `Ln`、少 creeping |
| 对 Barrier 的影响 | N 到达更抖 →「渲完 N」更散 → 常被最慢通道拖住 | N 发放更匀，等待更可预期；Slave 仍有 VSync 相位差 |
| 能不能做软件帧同步 | **能** | **能**（不是前提） |

§4.2.2 只把 master 对齐到帧头；其它通道仍各刷各的 VSync。接缝要齐：软 Barrier 或硬件 Swap/Framelock。同一 VSync 沿只有硬件扫描锁。

等齐**所有** IG 的 SOF 再发下一包，接近仿真步进 lockstep，仍不是 Present 栅栏，且 SOF 相位仍不对。

## 7. 本项目结论

- **Message Sync 现状**：数据面**缺省** CIGI **§4.2.1 Asynchronous**（Host FreeRun）。两种模式都计划实现，由 `hostConfig.messageSync` **初始化选定、不运行时热切**（[帧同步设计.md](../design/多通道同步/帧同步设计.md) §4）。SOF 每条 IGCtrl 回一条；FreeRun 下不门控，SofGated 只认 master。
- **帧号**：逻辑帧钥匙是 IGCtrl 的 **Host Frame Number**（一次扇出全通道相同）。IG Frame Number 独立，不作 Present 钥匙。
- **帧同步现状**：**未做**（无软件 Present Barrier，无 Swap Group/Barrier，无 Framelock/Genlock）。
- **选型**：软件 Barrier 与 Message Sync **正交**；默认 FreeRun 上即可做 Barrier。SofGated 是节拍同伴，不是 Barrier。硬件 Present/扫描锁留拼接墙。对比实验：改配置重启 Host，一次只动一个旋钮。
- Timestamp / 仿真时间消费见 [时钟同步方案.md](../design/多通道同步/时钟同步方案.md)，不替代本层。
