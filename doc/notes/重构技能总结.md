# 重构技能用词

讨论重构时用这几个词。它们描述「调用方要学多少、改一处能不能盖住全部」，不描述类的继承关系。

## seam

seam 是换行为时不用改调用方那一行的位置，也就是 module 的 interface 所在的地方。

调用方写下一次调用。这次调用后面的队列、线程、解包可以换，这一行可以不动。这个位置就是 seam。

`Engine` 每帧调用 `IgSync::drainIncoming`，`HostDriver` 的虚 IG 调用 `takeIncomingTcp`。这两处调用是两条 seam：背后的实现可以换，调用那一行可以不动。

### 和 C++ 多态的关系

虚函数是放下一条 seam 的一种办法：基类上的声明保持不变，换一个子类就换行为，调用方仍然写同一次调用。

seam 不要求继承。函数调用、回调、模板参数、构造时传入的对象，都可以是 seam。上面 `drainIncoming` 和 `takeIncomingTcp` 是普通成员函数调用，没有第二个子类。

一条 seam 要有两个真正不同的实现，才算实的。只有一个子类时，虚函数只是预留，背后还没有可替换的行为。

## depth 和 shallow

depth 看的是：调用方学一点 interface，能带动多少行为。

| | 调用方要学的 | 背后的行为 | 判断 |
| --- | --- | --- | --- |
| depth（深） | 少 | 多 | 要保留 |
| shallow（浅） | 多，和实现几乎一样宽 | 少，多半是转发 | 要收掉 |

深的例子：`IgSync::connect` 只收一个 `IgConfig`。背后有 TCP 重试、HELLO、UDP 确认、两条 I/O 线程。调用方不用学这些步骤。

浅的例子：`IgSync::sendTcpMessage` 收一段字节，做空检查后交给套接字。学会这个函数，几乎等于读完它的实现。

depth 不是代码行数。把一个浅函数包进新类，行数变多，调用方要学的东西没变少，仍然是浅的。
