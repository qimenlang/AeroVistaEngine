## 1. 笛卡尔与「世界坐标系」

**笛卡尔坐标系**是互相垂直的轴、用直线距离（通常为米）描述位置的直角坐标。三维空间中一点记为 `(X, Y, Z)`：原点固定、轴正交，可直接做加减、插值、旋转矩阵与欧氏距离运算。

| | 笛卡尔（ECEF、本地 World） | 非笛卡尔（如 LLA） |
| --- | --- | --- |
| 坐标含义 | 沿轴的长度 | 角度 + 高度 |
| 两点「距离」 | 可直接当米用 | 不能直接当米用 |
| 渲染 / 矩阵 | 直接适合 | 须先换成笛卡尔 |

在图形引擎中，场景 **World** 一般就是笛卡尔系：原点在场景根（或约定点），轴正交、单位多为米；`Transform`、`LookAt.eye`、mesh 顶点最终都落在这套直角坐标里。本地小场景与地球大场景的 World **都是笛卡尔**，差别只在原点与轴的约定：

| 场景 | 「World」实际是什么 |
| --- | --- |
| 本地小场景（如 `lz.vsgt`） | **本地笛卡尔**（本项目约定：Y-forward、Z-up） |
| 地球瓦片场景 | **ECEF**（地心笛卡尔，量级约 6.3e6 m） |

**LLA / 经纬高不是世界坐标系**，只是描述位置的标签；进渲染前要变成笛卡尔 World。

```text
本地小场景:   World = 任意原点的笛卡尔
地球大场景:   World = ECEF（地心笛卡尔）
```

## 2. VSG 中与「坐标」相关的几套机制

VSG 中与坐标相关的能力分三层，不宜混为一谈：

| 层级 | VSG 概念 | 解决什么 |
| --- | --- | --- |
| 轴约定 | `CoordinateConvention` | 谁朝上（资产导入） |
| 地球几何 | `EllipsoidModel` → LLA / ECEF / ENU | 地球上的位置与局部朝向 |
| 数值精度 | `CoordinateFrame` + `ViewMatrix::origin` | 坐标过大导致的精度问题 |

另有 `AbsoluteTransform`：往 modelview 栈直接推矩阵（不乘父变换），是变换栈语义，不是独立地理坐标系。

### 2.1 `CoordinateConvention`（轴朝向）

定义于 `vsg/maths/transform.h`（Collada 习惯，右手系）：

| 值 | 含义 |
| --- | --- |
| `X_UP` | X 向上 |
| `Y_UP` | Y 向上 |
| `Z_UP` | Z 向上 |
| `NO_PREFERENCE` | 不指定 |

只描述轴向，不涉及经纬高或 ECEF。本项目同步约定的 Y-forward / Z-up 是应用层约定，不是靠该枚举自动切换。

### 2.2 `CoordinateFrame`（大坐标精度）

节点上的 `origin` + `rotation`，配合相机 `ViewMatrix::origin`，相对该原点做变换，减轻天文/行星尺度下的精度问题。不定义经纬或椭球语义。地球瓦片主路径一般靠 ECEF + 双精度 `LookAt`；本引擎目前未用这套。

### 2.3 `EllipsoidModel`（地球椭球）

默认 **WGS-84**（赤道 / 极半径常量）。提供：

- `convertLatLongAltitudeToECEF` / `convertECEFToLatLongAltitude`
- `computeLocalToWorldTransform` / `computeWorldToLocalTransform`（局部切平面 ↔ ECEF）

地球瓦片场景通过 ref object 键 `"EllipsoidModel"` 挂到场景上。详见下一节。

## 3. EllipsoidModel：LLA / ECEF / ENU

三者描述的是同一空间点（或同一点处的姿态基准），差别在原点、轴与单位习惯；由 `EllipsoidModel` 换算。

```text
        LLA (lat°, lon°, alt m)
              │
              │ convertLatLongAltitudeToECEF / 反向
              ▼
        ECEF (X, Y, Z) 米，地心原点
              │
              │ computeLocalToWorld(lla) / WorldToLocal
              ▼
        ENU (e, n, u) 米，钉在某个 LLA 上的局部系（东-北-天）
```

| | **LLA** | **ECEF** | **ENU** |
| --- | --- | --- | --- |
| **全称含义** | 大地坐标（Geodetic） | 地心地固直角坐标（Geocentric Cartesian） | 局部切平面（East–North–Up） |
| **原点** | 椭球面 + 经纬网格（概念上） | 地心 | 选定的某个 LLA 点 |
| **量** | 度、度、米 | 米、米、米 | 米、米、米 |
| **轴** | 纬 / 经 / 高 | 地固直角系 | 东 / 北 / 天 |
| **是否线性** | 否（球面几何） | 是（全局笛卡尔） | 局部近似线性 |
| **VSG 类型** | `dvec3`，无单独类型名 | `dvec3`（米） | 由 `LocalToWorld` 矩阵隐含 |
| **适合表达** | 「在哪」（人读、导航） | 「渲染/物理里的绝对位姿」 | 「相对跑道/机场怎么偏」 |

概括而言：LLA 是地理标签；ECEF 是地球场景的全局笛卡尔 World；ENU 是钉在某 LLA 上的本地笛卡尔。航空常用 **NED**（北-东-地）；VSG 局部是 **ENU**，轴约定不同，换算时需注意。

## 4. 渲染管线：三种地球坐标如何进 GPU

需要区分两个「世界」：

1. **图形学 World**：场景根下的笛卡尔坐标，用来算 View / Model / MVP。
2. **地理语义**：LLA / ECEF / ENU。

LLA、ENU 不会直接进入 GPU。进管线前都要变成场景的笛卡尔 World：无地球时为本地 World（现状）；有地球时，这个 World 就是 ECEF。ENU 通常先经 `LocalToWorld * 局部点` 转到 ECEF，再参与渲染。

```text
配置 / Host 报文:  LLA 或 ENU 或 ECEF
        │  EllipsoidModel 换算
        ▼
场景 World（地球时 = ECEF）→ LookAt / Transform
        │
        ▼
View / Proj → Clip → NDC → 屏幕
```

带 `EllipsoidModel` 的地球场景中：瓦片几何最终摆在 ECEF；相机 `LookAt::eye/center/up` 也按 ECEF 理解；投影常用 `EllipsoidPerspective`，Trackball 可带 `EllipsoidModel`（含贴地夹持）。

## 5. 用途选型：常用场景与飞模需求

按用途分工时，没有单一「永远最常用」的坐标：

| 用途 | 更常用 |
| --- | --- |
| 人读、配置、地图、任务点 | **LLA** |
| VSG 地球渲染、`LookAt`、场景图 | **ECEF** |
| 机场 / 跑道 / 多通道相对主视点偏移 | **ENU**（或本地 YPR offset） |

库与示例里真正驱动绘制最多的是 ECEF；业务与 UI 最多的是 LLA。

飞行模拟中三套坐标通常都要使用，职责不同：

| 需求 | 更贴哪套 |
| --- | --- |
| 本场、仪表、航路点、任务脚本 | **LLA**（姿态常相对真北 / 天） |
| 出视景、大地形、Host→IG 绝对位姿上屏 | **ECEF**（或等价场景 World） |
| 相对跑道、编队、多通道视锥拼接 | **ENU / NED** |

视景引擎内部的主表示宜取 ECEF；飞行员与任务系统表述位置宜取 LLA。

多通道「共用眼点 + 本地 `offsetDeg`」在椭球上的常见做法：Host 权威眼点用 LLA + 姿态（或 ECEF + 姿态）；各 IG 通道偏航等在 ENU / 局部叠加，再变 ECEF 写相机。

## 6. 瓦片几何（Tile）与「有地球」

### 6.1 瓦片几何

瓦片几何本质是一块块 **mesh（网格）** 加上影像纹理，合起来相当于会按需加载的「地球模型」。它不是单个 `teapot.vsgt` 那种一次性静态整模，而是按经纬 / 投影把地球表面切成许多 Tile：每块含地形网格与卫星/地图贴图，近处细、远处粗（LOD），并随相机可见范围从网络或磁盘加载。

```text
地球表面按经纬 / 投影切成很多 Tile
  → 每块 = 地形网格（顶点）+ 卫星 / 地图贴图
  → 近处细、远处粗（LOD）
  → 边看边从网络 / 磁盘加载
```

本仓库示例：`engine/resources/models/readymap.vsgt`（及 `openstreetmap*.vsgt`）。根节点为 `vsg::TileDatabase`；挂载 `vsg::EllipsoidModel`（ref key `"EllipsoidModel"`）；`imageLayer` 指向在线地图瓦片 URL。运行时按相机可见范围生成 / 加载瓦片，内部用 `computeLocalToWorldTransform` 把局部网格挂到 ECEF。对 GPU 而言与普通 mesh 相同，差别在来源、LOD 与椭球放置。

### 6.2 「有地球」与 ECEF

「有地球」并不是单独打开一个坐标系枚举开关，而是同时满足：场景内容为椭球瓦片（几何在 ECEF），且相机 / 同步位姿与瓦片使用同一套地心笛卡尔（ECEF）。

**加载带 `EllipsoidModel` 的地球场景**，例如：

```text
model: models/readymap.vsgt
```

Engine 已检测 `"EllipsoidModel"`：有则用 `EllipsoidPerspective` + 椭球 `Trackball`；无则普通 `Perspective`。

**几何已在 ECEF，不必再「打开 ECEF 开关」。** `TileDatabase` 创建瓦片时即把网格变换到 ECEF 米制；加载地球瓦片后，场景 World 自然就是 ECEF。

**相机与同步需按 ECEF 书写：**

| 本地世界（现状） | 地球 / ECEF |
| --- | --- |
| `LookAt.eye` 量级：几十～几千米 | `LookAt.eye` 量级：~6.3e6 m |
| `setCameraPose(xyz, ypr)` 直接写 | 先 `LLA → ECEF`（或直接 ECEF），再写 `LookAt` |
| 普通 `Perspective` | `EllipsoidPerspective`（已部分接入） |

最小路径：

```text
1. 配置加载 readymap.vsgt（或同类）
2. 确认场景有 EllipsoidModel → 椭球投影 / Trackball 生效
3. EllipsoidModel::convertLatLongAltitudeToECEF(lat, lon, alt)
   → eye 的 ECEF，再设 LookAt（up 用局部天向更稳）
4. Host→IG：传 LLA（或 ECEF），IG 同样转到 ECEF 写相机
```

## 7. 本引擎现状与演进建议

### 7.1 现状

| 项 | 状态 |
| --- | --- |
| Host→IG 相机同步 | 已实现；假设 **本地世界笛卡尔**（position + YPR，Y-forward / Z-up） |
| 椭球场景加载 | 若模型带 `"EllipsoidModel"`，已切 `EllipsoidPerspective` + 椭球 Trackball |
| `setCameraPose` / 同步 | **无** LLA↔ECEF / ENU 转换；仍按本地 XYZ 写 `LookAt` |
| `CoordinateFrame` | 未使用 |
| 设计文档原约定 | 初步同步「暂不使用椭球坐标系」——椭球跟拍为后续能力 |

默认配置 / 多数测试模型（如 `lz.vsgt`）无椭球；`readymap*.vsgt` / `openstreetmap*.vsgt` 为地球瓦片样例。

### 7.2 椭球模式下的位姿接口

椭球模式下，宜先将 **LLA** 定为对外 / 同步位姿语义，内部立刻落到 ECEF 再写 `LookAt`；不宜只做「会显示 LLA」却不接通 ECEF。

| 步骤 | 建议 | 原因 |
| --- | --- | --- |
| 1 | 引擎具备 `EllipsoidModel`，提供 LLA↔ECEF、LLA→LocalToWorld | 地球渲染本来就需要 |
| 2 | Host→IG 报文优先 **LLA + 姿态**（或明确标注的 ECEF） | 飞模 / 任务侧自然；与「假世界 XYZ」解耦 |
| 3 | IG / `setCameraPose` 椭球路径：**LLA→ECEF→LookAt** | 与瓦片场景同一 World |
| 4 | 通道 `offsetDeg`：在 **ENU / 局部** 叠加后再变 ECEF | 多通道仍是「同眼点 + 局部偏航」 |

概括：椭球模式以 LLA 为权威接口，以 ECEF 为渲染 / LookAt 工作坐标；ENU 作为通道偏移与局部场景的下一层，不必比 LLA 更早做成主同步格式，但合成公式应提前约定。

### 7.3 模式对照（演进目标）

```text
本地模式（已有）:
  Host 眼点 = 世界 XYZ + YPR
  IG: XYZ ⊕ offsetDeg → setCameraPose → LookAt（本地 World）

椭球模式（目标）:
  Host 眼点 = LLA + 姿态（或 ECEF + 姿态）
  IG: LLA→ECEF；通道偏移在 ENU/局部叠加 → LookAt（World = ECEF）
```
