# 位姿配置设计

通道 JSON 用 **`injectEllipsoidIfMissing` + 双轨 pose** 描述实体/相机初始位姿。与 Host→IG 运行时眼点正交（[lla位姿传输设计.md](./lla位姿传输设计.md)）。装配示意见 [坐标系统模块设计.md](./坐标系统模块设计.md) §2；**pose 双轨与默认相机以本文为准**。

实体目录文件、启动预建、运行时 `Entity`、显隐状态机见 [实体管理设计.md](../引擎基础功能/实体管理设计.md)。通道 JSON **不再内嵌 `entities[]`**，以 `entitiesFilePath` 指向独立 `entities.json`；`pose` 对 IG 仍是「初始默认位姿（启动预建时套一次）」；Host 权威表另读 `pose.ellipsoid`（[实体与运动控制设计.md](./实体与运动控制设计.md) §3.2）。

## 1. 方案

```text
injectEllipsoidIfMissing?: bool   // 缺省 false；仅单机渲染（无 igConfig）生效；见下

entities: [                        // 位于独立 entities.json，非通道 JSON；目录契约见 实体管理设计.md §4
  {
    id / name? / model / initialEntityState?   // 目录字段，权威见 实体管理设计.md §4
    pose?: { local?: LocalPose, ellipsoid?: EllipsoidPose }  // 双轨以本文为准
  },
  …
]

camera? {
  pose?: { local?: LocalPose, ellipsoid?: EllipsoidPose }
}

LocalPose      { position[x,y,z], eulerYprDeg[yaw,pitch,roll] }      // 米 / 度；各数组长度须为 3
EllipsoidPose  { lla{lat,lon,alt}, eulerYprDeg[yaw,pitch,roll] }     // 度°/°/m；YPR 在 ENU
```

- **`injectEllipsoidIfMissing`（2026-09 取代 `coordFrame`）**：场景模型无自带 `EllipsoidModel` 时是否注入 WGS-84 椭球。**仅单机渲染（无 `igConfig`）需要此开关**；启用 IG 同步（有 `igConfig`）时引擎**自动注入**，无需配置。
- 两半可并存、不互校；运行时按「场景有无 `EllipsoidModel`」选消费半（2026-09：加载期不再强制选半）。
- 单项 `pose` 可缺 → 引擎默认放置；`camera` / `camera.pose` 可缺 → **场景 AABB 默认初始相机**（§4）；有 `camera.pose` 则覆盖 LookAt。
- **顶层 `model`、单对象 `entity` 与 `entities` 互斥**（通道 JSON 已改为 `entitiesFilePath`，不再内嵌数组；混写必须失败）。空数组拒绝（目录契约见 [实体管理设计.md](../引擎基础功能/实体管理设计.md) §4）。
- **`shaderCube` 与 `model` / `entitiesFilePath` 互斥**（运行时 GLSL 立方体探针，见 [引擎加载与渲染.md](../引擎基础功能/引擎加载与渲染.md)）。
- 方案 A：未知键拒绝。
- 目录项 `id` / `name` / `model` / `initialEntityState` 的校验以 [实体管理设计.md](../引擎基础功能/实体管理设计.md) §4 为准。
- 若某项 `pose` 或 `camera.pose` 出现：该半字段齐全（含数组长度 3 / `lla` 三字段）。
- 位姿**不含 scale**（不写、不测）。
- `camera` 仍为单个，不数组化。
- 其余通道字段不变。

YPR：`Rz*Rx*Ry`，与 `setCameraPose` / LLA §3.2 一致。

运行时 `Entity`、按 id 查表、Switch / 共享几何见 [实体管理设计.md](../引擎基础功能/实体管理设计.md) §5 / §8。`injectEllipsoidIfMissing` 属通道，不进入 `Entity`。

运行时同步只支持 LLA（命令实体 + 眼点，2026-09 收敛）：参与同步（有 `igConfig`）的场景必须有椭球，引擎**自动注入**（无需 `injectEllipsoidIfMissing`）；该开关只用于单机椭球渲染。判据的权威定义见 [lla位姿传输设计.md](./lla位姿传输设计.md) §2；命令实体报文见 [实体与运动控制设计.md](./实体与运动控制设计.md) §4.2；引擎写入见 [实体管理设计.md](../引擎基础功能/实体管理设计.md) §9。

## 4. 默认初始相机（无 `camera.pose`）

**目标**：仅 `entities`、未配相机位姿时，Local / Ellipsoid 均用场景 AABB 取景，尽量框住当前内容。有 `camera.pose` 只覆盖 LookAt；Host 眼点仍可再覆盖。多实体相距很远时画面会稀疏——要好看请显式配 `camera.pose`。

**与 `lla位姿传输设计.md` 的关系**：本文 §4 定义默认初始相机的行为，覆盖 `lla位姿传输设计.md` §2.3 中写死的默认 LLA 值。两文档冲突处，以本文为准。

**流水线**：

```text
ComputeBounds(_scene) → centre, radius
→ createInitialLookAt(ellipsoid?, centre, radius)
→ createInitialProjection(…)
→ 若有 camera.pose → 覆盖 LookAt
```

### 4.1 Local（世界笛卡尔）

```text
radius = 0.6 * |max - min|                    // 外接球半径的 60%
eye = centre + (0, -k_back·radius, 0)        // 后退取景，k_back = 3.5
center = centre
up = (0, 0, 1)
Perspective(fov=30°, aspect, near=0.001·radius, far=4.5·radius)
```

`k_back = 3.5` 与 VSG 惯例一致（见 `vsgviewer.cpp`）。`fov=30°`、`aspect` 由窗口尺寸决定。

**fallback**（radius ≈ 0 或 AABB 计算失败）：使用绝对兜底位姿 `eye=(0,0,10)`、`center=(0,0,0)`、`up=(0,0,1)`，`near=0.1`、`far=100`。此阈值判定为 `radius < 0.1` 米。`ComputeBounds` 得到无效 `dbox`（无顶点，例如全部实体 Switch OFF）时按 **radius = 0** 处理，走同一 fallback——不可把 `min/max` 的默认极值直接相减（会得到 inf）。

**有 `camera.pose` 时重算 near/far**：仅覆盖 LookAt 时，若配置的 eye 位置远离 AABB 原始范围，静态的 `near=0.001·radius, far=4.5·radius` 可能裁掉场景。应改为 `far = max(4.5·radius, |eye - centre| + radius)`，near 保持 `0.001·far`。

### 4.2 Ellipsoid（禁止对 `centre` 套 Local 公式 / 世界 Z-up）

```text
centre_ecef, radius ← AABB                      // centre 是场景盒子中心，≠ 地心
lla_c = ECEF→LLA(centre_ecef)                   // 取该点 ENU（east / north / up）
eye = centre_ecef - north·(k_back·radius) + up·(k_up·radius)
LookAt(eye, centre_ecef, up)
EllipsoidPerspective(lookAt, ellipsoidModel, fov=30°, aspect, nearFarRatio=0.001, horizonMountainHeight=0)
```

- `k_back = 3.5`，`k_up = 0.3`
- ENU 基由 `ellipsoidModel->computeLocalToWorldTransform(lla_c)` 的列 0/1/2 给出
- `EllipsoidPerspective` **每帧动态计算 near/far**（见 `thirdparty/vsg/include/vsg/app/ProjectionMatrix.h:210-234`），由 eye 的海拔 H 和视线角度决定，不受配置直接控制

**fallback 判据**（以下任一条件触发）：
1. AABB 空（`ComputeBounds` 无有效顶点）
2. `radius < 0.1` 米
3. `|centre_ecef| < ellipsoidModel->radiusPolar * 0.9`（场景中心落入地底，≈ alt < -600km）
4. `ECEF→LLA(centre_ecef)` 换算失败

**fallback 行为**：写死 LLA `(lat=39.9°, lon=116.4°, alt=500m)`、YPR=0（朝北，当地水平），并打 `[WARN]` 日志。此 fallback 的 near/far 仍由 `EllipsoidPerspective` 动态计算（H=500m 时 far 量级为几公里，足以框住地面场景）。

**无 pose 实体摆放陷阱**：在 Ellipsoid 通道下，实体缺 `pose` 时默认摆放在 ECEF 原点（地心）。此时 AABB centre ≈ 地心，radius 很小，会触发 fallback 判据 3，落到北京上空 —— 这是预期行为。要模型可见，必须显式配置 `pose.ellipsoid.lla`。

### 4.3 同配置同场景的一致性

各 IG 进程使用相同 `entities` 配置时，默认初始眼点应一致（均由同一 AABB 计算）；随后由 viewhost Host 眼点 ⊕ `offsetDeg` 覆盖相机（[lla位姿传输设计.md](./lla位姿传输设计.md)）。场景不同则默认可不同。**不再依赖写死北京作唯一默认**。Host（viewhost）无 `entities` 配置，不参与本一致性。

### 4.4 每帧重算 near/far 的 trade-off（Ellipsoid 专有）

`EllipsoidPerspective::transform()` 每帧读取 `lookAt->eye` 和视线方向，动态计算：

```text
H = eye 的海拔
alpha = acos(R / (R + H))                      // 地平线张角
theta = acos(-dot(lv, v) / (|lv|·|v|))          // 视线与地心方向夹角
l = R * (tan(alpha) + tan(beta))               // beta 由 horizonMountainHeight 决定
farDistance = cos(theta + alpha - PI/2) * l
nearDistance = farDistance * nearFarRatio      // nearFarRatio 固定为 0.001
```

**优点**：高度变化时远裁面自适应，飞行仿真下必要。
**缺点**：
1. **深度精度损失**：far 被推到几百公里时，near 也会到几百米（`near = 0.001·far`），深度缓冲精度下降，近处 Z-fighting 风险增加。这是浮点深度缓冲的物理限制。
2. **数值边界 corner case**：eye 降到地底（H < 0）或穿模到模型内部时，公式可能得到非预期的 near/far。这些场景在地球尺度飞行下罕见。

这是"地球尺度 + 飞行仿真"场景下的合理代价。若要做城市街景级近景，应用 Local 坐标系或手动锁 near/far。

## 5. 示例

通道配置（engine JSON）不再内嵌 `entities[]`，只指向独立目录文件：

```json
{
  "injectEllipsoidIfMissing": true,
  "entitiesFilePath": "config/entities_scene_ecef.json",
  "camera": {
    "pose": {
      "ellipsoid": {
        "lla": { "lat": 39.9, "lon": 116.4, "alt": 500 },
        "eulerYprDeg": [0, 0, 0]
      }
    }
  }
}
```

`entities.json`（独立文件；目录契约见 [实体管理设计.md](../引擎基础功能/实体管理设计.md) §4。下例展示 pose 双轨）：

```json
{
  "entities": [
    {
      "id": 1,
      "model": "models/lz.vsgt",
      "pose": {
        "local": {
          "position": [0, 0, 0],
          "eulerYprDeg": [0, 0, 0]
        },
        "ellipsoid": {
          "lla": { "lat": 39.9, "lon": 116.4, "alt": 0 },
          "eulerYprDeg": [0, 0, 0]
        }
      }
    }
  ]
}
```

上例未写 `name`，解析后缺省为 `basename(model)`（`lz.vsgt`）；目录字段权威见 [实体管理设计.md](../引擎基础功能/实体管理设计.md) §4。

## 6. 不做

双轨自动换算、配置 scale、用本配置替代 CIGI 眼点权威；椭球默认用 AABB + 世界 Z-up。
