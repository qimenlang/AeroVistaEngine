## 3. 约束（写死）

1. **不要用抓帧做帧阶段统计。** RenderDoc 适合偶发查 GPU。60Hz 连采用 `Engine::tickOnFrame` 内 `steady_clock` 打点：`preFrame` / `update` / `recordAndSubmit` / `waitForFences` / `present`。
2. **「渲完」不是 `recordAndSubmit` 返回。** 现行 `Engine::render` 是 submit → `present` → `waitForFences`。量 slack 必须先 fence 再 present（帧同步设计 §3.6）。整圈 `_lastFrameSeconds` 分不清哪些在等 VSync。
3. **UDP 收包已在 I/O 线程非阻塞 `recv`。** **IG** 主线程 `IgSync::drainIncoming` → `waitForUdpFrames`：空队列最多再等 **2ms**（两个 1ms I/O 轮询，状态同步设计 §5.1 / `kMaxUdpDrainWaitMs`）。有包立即返回。这 2ms 会直接吃 VBlank 空档，优先于「先改 TCP/UDP 策略」。**Host** `HostSync::drainIncoming` **不等待**（push 模式）。UDP/TCP 发送均在调用方线程（`sendto` / `sendAll`；状态同步 §7.2）。
4. **跨机不能比本地单调钟。** 「各 IG Present 时的 QPC / `steady_clock` 差」没有公共钟就是噪声。能比的是包内 Host `TimeStamp` 和补偿后的 `simTimeUs`（同一套 Host 钟）。实验室两 IG 补偿后差小于一帧见 `CLK-consistent`。
5. **TCP 命令面无业务 ACK。** 「发一次 TCP 到收到」必须自定探针（例如 IG 回调时刻），不是现成回执。不在 Barrier 热路径上。
6. HUD 只放**本机、本帧、改配置当场能用的数**。百分位、通道间差、接缝走日志或眼睛。

## 4. 测量项

| 项 | 回答什么 | 形式 | 做法 |
| --- | --- | --- | --- |
| **4.1 接缝（网格 + 假眼点）** | Async 错帧/相位有多明显 | **一次性目视**（可录像）；眼点脚本可重复 | 场景用通道 JSON `groundGrid` 铺 **ENU 切平面线网格**（钉到指定 LLA 的 ECEF，**不加载** `readymap` 瓦片）。Host 发匀速眼点假数据扫过通道接缝（第 2 步，未做）。Barrier / SofGated 落地后再跑同一条对照。不代替数字 HUD |
| **4.2 一帧各阶段** | 预算花在哪 | **常驻统计** + HUD 上一帧分段 | `tickOnFrame` 打点。日志滚动 p50/p99 才能看掉帧尖峰。扩展现有 F2 HUD（已有 FPS / 整圈 frame ms / IGCtrl 号:`simTime`） |
| **4.3 渲完→VBlank（slack）** | 能不能开软件 Barrier | **先浸泡统计**，再决定是否进 HUD | 见帧同步设计 §3.6。低分位经常小于 2～3ms → 不开 Barrier。窗口模式可用 `DwmGetCompositionTimingInfo` 对照 |
| **4.4 IG `drainIncoming` 等待** | 空转 2ms 是否在偷帧 | **常驻统计 + HUD 一项 drain ms** | 只量 **IgSync**（Host 不等待）。若经常顶满 2ms，先改等待 |
| **4.5 IGCtrl 发出→收到 SOF** | 应用 RTT、SofGated 门控会多重 | **Host 侧统计**；HUD 可显示最近/均值 | 见下方写死规则。`ready`/`release` 延迟的下限参照。不是 §4.8 |
| **4.6 同号 N 的 `simTimeUs`** | 时间特效会差多少 | **事后 CSV** | 列：帧号、包内戳、Present 时 `simTimeUs`、距上次收包年龄。HUD 只显示本机 `N` / `simTime` / age |
| **4.7 TCP 一发一收** | 命令面，非 60Hz 热路径 | **一次性 bench** | 自定探针时刻。命令面要优化再做，不挡 Barrier 决策 |
| **4.8 探测报往返** | 网络路径稳不稳（RTT、丢包） | **Host 侧统计** | 见下方写死规则。不回答 §2，不做 Barrier / SofGated 门槛 |

`release(N)` 之后仍是 `_viewer->present()`，没有第二种换缓冲（帧同步设计 §3.4）。

**§4.1 网格落地**：不加载地球瓦片。通道 JSON 写 `groundGrid`（[位姿配置设计.md](./位姿配置设计.md)）。单机 `vsgEngine.exe -c engine/resources/config/scene_seam_grid.json`；多通道一键 `scripts/run_seam_grid.sh`（或 `scripts\run_seam_grid.bat`），各 IG 用 `scene_seam_grid_ig_main.json` / `left` / `right`。切平面在 20 km 半幅边缘约离椭球面数十米，两 IG 同一网格，接缝仍可比。假眼点巡航是第 2 步。线格是 Vulkan `LINE_LIST` 实线（约 1 像素），由 `vsg::Builder` 的 wireframe 管线画出。

**§4.5 写死（IGCtrl↔SOF 应用 RTT）**：

类 `RttTracker`（时限 `appRttMatchTimeout` = 50ms）。量的是「IGCtrl 发出到应用看见 SOF」。SOF 在 IG 主线程解包之后才发出，Host 的 `t_recv` 又在 `drainIncoming`，所以样本含帧等待。与 §4.8 网络 RTT 共用同一配对器、两张表（按 peer 各持一个 `RttTracker` 实例，时限不同）。

- Host 墙钟配对；`t_recv` 是主线程 `drainIncoming` 见到 SOF 的时刻，不是 I/O `recv`。
- 按 Host Frame Number 配对（本项目 SOF `FrameCntr` 回显最近 IGCtrl）。禁止按到达顺序把「下一条 SOF」算给上一条 IGCtrl。
- 匹配时限 **50ms**（`appRttMatchTimeout`）：`now - tSend >= 50ms` 仍未匹配 → **丢失**，不把时限本身记进 RTT。49ms 到达仍匹配。本机稳态约 20ms，多等一帧仍记 RTT。
- 超时后晚到、同号重复 SOF、未知帧号：不进 RTT。飞行中既不算丢失也不进 RTT。
- 匹配与超时进同一滚动窗（最近 **60** 次完成）：`avgRtt` 只平均窗内匹配样本（窗内匹配满 **10** 才出）；`lossRate` = 窗内超时 / 窗内完成（完成满 **10** 才出）。飞行中不进窗。
- 按 peer 分列。IG 发送 socket 的源地址/端口在 `UDP_SYNC` 时记下，数据面回显帧按该对落到对应 `RttTracker`（TCP 消息头不计 RTT）。观测 `HostSync::rttLast(clientId)`。
- 不断言绝对毫秒黄金值；集成只要求有 \(\Delta > 0\) 的匹配样本。

**§4.8 写死（网络路径 RTT）**：

量的是 Host 本机套接字上、一对探测报的往返：`t_send` 在该报 `sendTo` 之前写入在途表（回显若在 `sendTo` 期间到达仍能按序号配对），`t_recv` 为配对回显 `recvFrom` 返回之后。两下都是 Host 的 `steady_clock`，发送在调用方线程、接收在 `_udpThread`，可以直接相减。禁止用 IG 的 `receivedAtUs` 减 Host 的 `t_send`（两台机器没有公共钟）。

探测不走 SOF，也不用 IGCtrl 的 `FrameCntr`。IG 在 `udpLoop` 里立刻回显，不等 `preFrame`。因此样本不含 §4.5 的帧等待。

- **报文字节**（固定 8 字节，小端）：`magic` 为 `uint32`，值 `0x54525641`（字节 `'A' 'V' 'R' 'T'`，即 `AVRT`）；`sequence` 为 `uint32`。回显原样带回 `sequence`。线格式助手在 `NetProbe.h`。
- **识别**：Host 与 IG 的 `udpLoop` 在业务入队之前看 `magic`。命中则处理并消费，不入业务队列，不进 CCL，不交给 `ProcessIncomingMsg`。
- **发送**：本端 `flushUdp` 把 IGCtrl 扇出之后，对每个 `udpReady` 的 peer 另发一报。序号按 peer 从 1 递增。`t_send` 在这一报 `sendTo` 之前记下，不取 IGCtrl 那一次 `sendTo`。中继转发路径不发探测。采样率跟数据面扇出；RTT 数值不含 UI 定时器。
- **IG 回显**：`udpLoop` 的 `recv` 返回后，若本数据报是探测，立刻 `sendTo` 回已连接的 Host，序号不变，本报不入队。业务数据报仍按现行路径入队。
- **Host 配对**：`udpLoop` 的 `recvFrom` 返回时按源地址/端口找到 peer（与 SOF 同一对 `udpFromIp` / `udpFromPort`），用 `sequence` 配对。禁止按到达顺序把下一条回显算给上一条探测。配对表在 `HostSync`，按 peer 分列（`RttTracker` 实例，时限 `netRttMatchTimeout` = 1ms）。不放进 `UdpSocket`。与 §4.5 共用 `RttTracker`，时限不同、分表。
- **时限 1ms**：`now - tSend >= 1ms` 仍未匹配 → **丢失**，不把时限本身记进 RTT。999µs 到达仍匹配。晚到、同号重复、未知序号不进 RTT。飞行中既不算丢失也不进 RTT。1ms 用来丢掉停住的探测；本机往返约百微秒，不沿用 §4.5 的 `appRttMatchTimeout`。
- **统计**：与 §4.5 同一口径、另一张表。最近 **60** 次完成；`avgRtt` 只平均窗内匹配（满 **10** 才出）；`lossRate` = 窗内超时 / 窗内完成（满 **10** 才出）。飞行中不进窗。
- **收包等待**：`udpLoop` 用 `select` 等套接字。数据报到达立即返回；空闲时 Host/IG 最多等 `SyncInterface::udpIdleWait`（1ms）再淘汰在途探测。业务仍是 I/O 入队、主线程解包。不断言绝对微秒，个位数以下的微秒也不当成网卡标称值。
- 不断言绝对毫秒黄金值。集成只要求有 \(\Delta > 0\) 的匹配样本，且该样本不依赖主线程 `drainIncoming`。

## 6. 推荐顺序

1. **眼看基线**（4.1）：2～3 通道。决定 Barrier 有没有产品价值。
2. **帧预算 + drain + slack**（4.2～4.4）：决定 Barrier **允不允许做**。
3. **IGCtrl↔SOF RTT**（4.5）：SofGated / 栅栏延迟量级。
4. **同号时间 CSV**（4.6，可选）：要较真 shader 时间再做。
5. **TCP RTT**（4.7）：命令面要优化再做。
6. **网络路径 RTT**（4.8）：代码已落地（§9）。要看链路稳不稳时用。不参与 Barrier 门槛，也不替换第 3 步的应用 RTT。

第 2 步已贴满 60fps：同步方案停在同一 Host 帧号扇出（已实现），不要进 `ready`/`release`。SofGated 仍可能做（不挡 Present），但应用 RTT 和 drain 仍要先有数。

| 6 | 已经记过超时，同序号再回显 | 丢失只计一次；晚到的回显不写 `lastRtt` | 注入 |
| 7 | 同序号回显两次 | 第二次不改变 `lastRtt`，也不再增加 `matchCount` | 注入 |
| 8 | 回显的序号从未发出 | 不进 RTT，`lossCount` 仍为 0 | 注入 |
| 9 | 发出后只过了 999µs，尚无回显 | 在途既不是丢失，也不是 RTT；`lossRate` 为空 | 注入 |

| 13 | 更早的超时已被挤出这 60 次 | 窗内 `lossRate` 不再计它；累计 `lossCount` 仍保留 | 注入 |
| 14 | 先记下发出时刻，再发出探测 | 未满时限仍在途、回显键匹配这两条共享用例覆盖在途与算出 RTT。不单测 `sendTo` 之前写入 | 注入 |
| 15 | Host 与 IG 真的互发探测 | 收到回显就有 RTT，而且大于 0。不规定是几毫秒。不用等主线程把业务报文解包。不单列场景，由分项 17 在解 SOF 前断言 | 真链路 |
| 16 | 探测不要混进业务报文 | 探测不占用 SOF、IGCtrl 的计数。正常的 IGCtrl 仍然能被主线程解包看到 | 真链路 |
| 17 | 两套 RTT 各算各的 | 探测的回显只进网络 RTT。SOF 只进应用 RTT。两边的匹配次数互不影响 | 真链路 |
