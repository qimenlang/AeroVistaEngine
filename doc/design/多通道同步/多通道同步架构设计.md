# 多通道同步架构设计

sync 库（`aerovistaSync`）里 **Host / IG 怎么收发**，以及 viewhost **中继怎么把平台和真实 IG 串起来**。本文描述当前实现。

报文布局、节拍字段、验收码、MFC 控件不在这里。库边界见 [sync模块化设计.md](./sync模块化设计.md)，连接与 peer 见 [多通道同步模块设计.md](./多通道同步模块设计.md)，发送 API 见 [状态同步设计.md](./状态同步设计.md) §7，中继契约见 [平台同步设计.md](./平台同步设计.md) §6。

## 1. 三种进程关系

同一套 `HostSync` / `IgSync`。差别是谁持有 Host、IG 的 `igConfig.hostAddr` 指向谁。

| 用法 | Host 进程 | IG 进程 | viewhost |
| --- | --- | --- | --- |
| 本地调试 | viewhost（`HostDriver`） | engine（`IgSync`） | 自己当 Host |
| 正式运行 | platform（直接持 `HostSync`，不用 `HostDriver`） | engine，`target` 指向平台 | 不在环 |
| 真模拟器调试 | platform 仍是节拍权威 | engine，`target` 改指向 viewhost | `HostDriver`：对真实 IG 是 Host，对平台是虚 IG，透传 |

```text
本地调试
  viewhost HostDriver ──UDP/TCP── engine IgSync × N

正式
  platform HostSync ──UDP/TCP── engine IgSync × N

真模拟器
  platform HostSync ──UDP/TCP── viewhost 虚 IgSync
                                    │
                                    └── viewhost HostSync ──UDP/TCP── engine IgSync × N
```

正式少一跳。真模拟器上平台仍发 IGCtrl / 眼点，viewhost 不改 IGCtrl 头，只把切齐后的字节转给真实 IG，并按数据面 UDP 回 SOF。三种用法不运行时热切。

## 2. 库内对象

```text
viewhost ── HostDriver
              ├─ HostSync          对真实 IG：listen / peer / 扇出
              ├─ HostDataManager   权威表（首版实体）；不持 socket
              └─ 虚 IgSync         仅中继：对平台走 IG 的 connect

platform ── HostSync               无 HostDriver、无虚 IG

engine  ── IgSync                  空 igConfig 则不建
         └─ CameraDriver           眼点合成；写相机在 Engine
```

`HostSync` 与 `IgSync` 都继承 `SyncInterface`（`takeIncoming*` / `send*Message` / `flush*` / `shutdown`）。中继用这组接口搬字节，不把平台报文送进虚 IG 的 `drainIncoming` 当唯一消费者，也不把报文拆开再 `<<` 进另一套 CCL session。

每个端点两套 CCL session：UDP 数据面、TCP 命令面。出站 `CigiOutgoingMsg` 只在调用方线程碰（viewhost / platform 的 UI 线程，或测试里的调用线程）。

## 3. 双平面上的收发分工

| 平面 | 传输 | 内容 | 谁发送 | 谁接收 |
| --- | --- | --- | --- | --- |
| 同步面 | UDP | 握手 `UDP_SYNC`、数据面 IGCtrl（可带眼点）、SOF、网络探测 | 调用方 `flushUdp` / `sendUdpMessage`；IG 回 SOF 在 `drainIncoming` | 各自的 UDP 线程 `recv` 后入队 |
| 命令面 | TCP | HELLO、实体 / 文本等一次性报文 | 调用方 `flushTcp` / `sendTcpMessage` | 各自的 TCP 读线程切齐后入队 |

调用方组包：`outMsgWithIgCtrlUdp()` 或 `outMsgWithIgCtrlTcp()` 前置 IGCtrl，业务 `<<` 报文，再 `flush*`。`flushTcp` 是 `PackageMsg` 后对每个 ready peer `sendAll`；`flushUdp` 是 `PackageMsg` 后 `sendto`。数据面 IGCtrl 扇出成功后，Host 再对每个 `udpReady` peer 发一报网络探测。

I/O 线程不碰 CCL 出站，也不把业务报文 `sendAll` 到对端。例外只有握手和探测回显：Host 在 UDP 线程或 client 线程上对 `UDP_SYNC` 回 IGCtrl ACK；IG 的 UDP 线程认出网络探测后立刻 `sendTo` 回显，不入业务队列。

`takeIncomingTcp` / `takeIncomingUdp` 与 `drainIncoming` 互斥，消费同一条队列。中继 take 走字节；`drainIncoming` 才 CCL 解包并触发 `addCallback`。

空闲时 UDP 线程用 `SyncInterface::udpIdleWait`（1ms）做 `select`：有数据立即返回，超时只限制空闲等待。

## 4. Host 收发

`HostSync::initialize` 绑定 UDP、监听 TCP，并启动线程。是否起来只看返回值。打开失败时套接字已收掉。

| 线程 | 做什么 |
| --- | --- |
| `_acceptThread` | `accept`。每来一个连接就起一条 client 线程 |
| client 线程（`_clientThreads`） | 先收 HELLO（`SOF`+`IGMsg`，无 TCP ACK），写入 peer 的 `udpRecvPort` / `channelId`。重复 `channelId` 拒绝。随后 `commandReadLoop`：按 SOF 切齐；仅 `channelId==0`（master）入 `_tcpPayloadQueue`。侧通道仍 `recv`，不入队。HELLO 本身不入队 |
| `_udpThread` | `waitReadable` → 排空 `recvFrom` → 处理。网络探测记入该 peer 的 `netRtt` 并淘汰超时。未 `udpReady` 的 SOF 当作 `UDP_SYNC`，记下源端口并回 ACK。其余 CIGI 数据报入 `_udpPayloadQueue`；若来自 master 且 SOF 后还有业务包，把 SOF 之后的字节另拷进 `_masterUdpRelayQueue`（不拿走原报） |

调用方（viewhost / platform 的 UI 定时器，周期 10ms）做发送和解包：

- 数据面：`outMsgWithIgCtrlUdp()` + `appendEye` + `flushUdp()`。帧号和自计时时间戳在这次调用里填，`TimeStampValid=true`。只扇出 `tcpReady && udpReady` 的 peer。
- 命令面：`outMsgWithIgCtrlTcp()` + 业务报文 + `flushTcp()`。命令面帧号与数据面分开，`TimeStampValid=false`。
- 解包：`drainIncoming()`（viewhost 经 `HostDriver::pollIncoming`）。应用 RTT 在这里用 SOF 帧号配对，时限 `appRttMatchTimeout`（50ms）。网络 RTT 在 UDP 线程上配对，时限 `netRttMatchTimeout`（1ms）。

`fanoutTcp` 先拷出 socket 再逐条 `sendAll`，中间没有覆盖整条消息的锁。一条 TCP 消息不被别的 `send` 插断，是因为 `flushTcp` 和中继 `sendTcpMessage` 都在同一条 UI 线程上，前一次 `sendAll` 返回后才发下一条。

client 线程的 TCP 读循环结束后，`markPeerDisconnected` 关掉该 socket 并从 peer 表删除这条连接。UDP 一直沉默而 TCP 仍开着时，peer 留在表里；超时摘除仍是 [多通道同步模块设计.md](./多通道同步模块设计.md) §9 P0。该文 §2.3 仍写「断线摘除尚未实现」，与 TCP 读循环退出即摘表不一致。

## 5. IG 收发

`IgSync::initialize` 绑定本端 `udpRecvPort`。`connect` 用 `igConfig` 的 `hostAddr` / `hostTcpPort` / `hostUdpRecvPort` 做 TCP HELLO，再发 `UDP_SYNC`。

| 线程 | 做什么 |
| --- | --- |
| `_udpThread` | `waitReadable` → `recv`。网络探测立刻回显。其余数据报入 UDP 队列，带上接收时刻 |
| `_cmdThread` | TCP `recv`，按 IGCtrl 切齐后入 TCP 队列 |

engine 帧循环：

```text
preFrame   IgSync::drainIncoming(true)  → 解包；处理到 IGCtrl 时 sendSofPacket
           IgSync::update()             → 外推冻结，不收包
update     handleEvents 之后 applyLastHostEye 写相机（合成在订阅回调里已经完成）
postFrame  不向 Host 扇出
```

眼点回调在 `drainIncoming` 里同步触发，经 `CameraDriver` 做通道 `offsetDeg`。`IgSync` 不持有相机。

真实 IG 的 SOF 留在自己连着的那台 Host 上，供 IG 列表和 RTT。中继不把这份真实 SOF 原样转给平台。

## 6. 中继转发

只在 viewhost、且 `relay.enable` 时存在。`HostDriver` 同时持有对真实 IG 的 `HostSync` 和对平台的虚 `IgSync`。

虚 IG 不在启动时就连平台。`pollRelay` 看到 `readyIgCount >= relay.expectedIgCount` 且握手未完成，才 `IgSync::connect`（HELLO 的 `channelId` 恒为 0）。平台因此只看到一台 IG。

UI 定时器每一拍的顺序：

```text
HostDriver::update(&_eye)   转发开着则直接返回；关着则自己组数据面 IGCtrl
HostDriver::pollRelay()     取出切齐字节并转发（须在 drain 之前 take TCP）
HostDriver::pollIncoming()  drainIncoming：真实 IG 的 UDP SOF / 应用 RTT
```

`pollRelay` 在转发开着、且虚 IG 已握手时：

**平台 → 真实 IG**（`forwardFromPlatform`）

1. 虚 IG `takeIncomingTcp` → `HostSync::sendTcpMessage`（整条 `sendAll` 给全体 ready IG）。
2. 虚 IG `takeIncomingUdp` → `HostSync::sendUdpMessage`。有 ready IG 时，从该数据报读 ownship 写入眼点缓存。
3. 紧接着 `sendSofForIgCtrl`：读这条 UDP IGCtrl 头的 `FrameCntr`，`packSof` 回平台。没有 ready IG 也回。不改 IGCtrl 头，不另组一套数据面 IGCtrl。

**真实 IG → 平台**（`forwardToPlatform`）

1. `HostSync::takeIncomingTcp`（队列里只有 master、且不含 HELLO）→ 虚 IG `sendTcpMessage`。
2. `takeMasterUdpRelayBodies`（SOF 之后的业务字节，不抽空 `_udpPayloadQueue`）→ 虚 IG `sendUdpAfterSof`：用最近一次 `packSof` 的帧号组 `SOF'`，再接业务包发给平台。

真实 IG 的纯 SOF、侧通道 UDP、真实 HELLO 不进平台。不得对 Host 调用 `takeIncomingUdp`，否则 SOF 统计和 RTT 队列被抽空。

关转发（`setRelayForwarding(false)`）需要缓存里已有 ownship，否则拒绝、开关保持开。关成功后 `pollRelay` 仍把已切齐队列 take 掉，但不 send，因此不 `packSof`、不发 `SOF'`。viewhost 把 `_eye` 写成这份缓存，之后 `update` 用它自己扇出。再开转发时先丢掉当前已切齐队列，再恢复透传，`update` 再次直接返回。

viewhost 自己的命令面（天气、实体、`testtcp`）两种开关下都走 `flushTcp`，与透传各发各的完整消息，都在这条 UI 线程上。

## 7. 三条数据面路径

| | 谁组 IGCtrl | 谁发给真实 IG | 平台看到的 SOF |
| --- | --- | --- | --- |
| 本地调试 | viewhost `update` | `flushUdp` | 无平台 |
| 正式 | platform 定时器里 `outMsgWithIgCtrlUdp` + `appendEye` + `flushUdp` | 同一次 `flushUdp` | 真实 IG 的 SOF 直接回到平台 |
| 真模拟器，转发开 | 平台 | viewhost `sendUdpMessage` 原样转发 | 虚 IG 按该 IGCtrl 的帧号 `packSof`；master 业务 UDP 另发 `SOF'` |
| 真模拟器，转发关 | viewhost `update`（眼点来自关前缓存） | `flushUdp` | 虚 IG 仍连着，但这一拍不 `packSof` |

命令面在本地和正式都是调用方 `flushTcp`。真模拟器上，平台命令经虚 IG 的 TCP 队列原样 `sendTcpMessage`；viewhost 自己的调试包另起一条 `flushTcp`，不接在平台消息后面。
