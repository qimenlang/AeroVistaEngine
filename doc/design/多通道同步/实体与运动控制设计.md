# 实体与运动控制设计

面向本项目 **1 Host + 多 IG** 的实体面设计：**Host 是实体状态权威**，用 CIGI 4.0 标准报文驱动 IG 侧实体的**显示状态（激活/隐藏）**、**位姿摆放**与**动画**。实体几何**在 IG 启动时按独立实体目录文件（`entities.json`，Host/IG 内容一致、人工确保）的 `id → model 路径`映射全部预加载并一次性编译**；运行时 `EntityCtrl` 只控制模型**显隐**（Switch 开关），不再动态加载/编译。路径**不进报文**。

**一句话**：IG 启动即按实体目录把全部模型 `loadScene` 建实例、挂 `vsg::Switch`（初始按 `initialEntityState` 定显隐）并一次性 `compile`，此后零编译；Host 下发 `CigiEntityCtrlV4` 只**切换 Switch 显隐**、`CigiEntityPositionCtrlV4` 控制位姿、`CigiAnimationCtrlV4` 控制动画。链路按语义选择：**一次性 / 配置 / 请求走 TCP，持续实时位姿走 UDP**（沿用 [cigi梳理.md](../../notes/cigi梳理.md) 链路约定）。

## 1. 目标与范围

**做**：

| 项 | 说明 |
| --- | --- |
| Host 权威 | 实体**显示状态**（`Active`/`Standby`，即显/隐）由 Host 用 `CigiEntityCtrlV4` 驱动；实体几何**在 IG 启动时全部预加载建实例并一次性编译**（§7.2），运行时不动态加载/编译 |
| 位姿摆放 | `CigiEntityPositionCtrlV4`（`EntityID≠0`）控制实体位姿（沿用既有命令面摆放路径；坐标系由场景有无 `EllipsoidModel` 决定，见 §4.2） |
| 动画控制 | `CigiAnimationCtrlV4` 控制实体动画播放/暂停/循环 |
| 路径映射 | Host/IG 读同一份**独立实体目录文件**（`entities.json`，内容一致、人工确保）；报文只传 `EntityID`，路径不经网络 |

**不做**（见 §12）：`EntityType` 抽象层（DIS 类型数据库）、业务回执、自定义 group 语义、`EntityID==0` ownship 眼点（已有 [lla位姿传输设计.md](./lla位姿传输设计.md) 覆盖）。

**成功标准**：Host 能通过网络命令让 IG 把指定 id 的模型**显示/隐藏**（`Active`/`Standby`）、摆放到指定位姿、播放动画；IG 侧实体**实例在启动时全部预建**（含 GPU 编译），`EntityCtrl` 只切显隐，无运行时加载/编译。

## 2. 背景与现状

现状（2026-08）实体来源是 **IG 配置预加载**：

```text
Engine::assembleEntitiesScene()
  遍历 config.entities → loadScene(model) → 建 Entity → _entityMap.emplace(id, entity)
```

即 IG 启动时把配置里所有 `entities[]` 一次性加载进 `_entityMap`，Host 对实体清单**无感知**；命令面 `updateEntityPose` 只能摆放**已存在**实体（`if (it == _entityMap.end()) return;`，见 `engine.cpp`），不能创建/销毁。

**问题**：

1. 实体显示不可控——IG 自行全量加载并直接显示，Host 无法按需控制某实体显隐（CIGI 里由 Host `EntityCtrl` 决定 `Active`/`Standby`）。
2. 方向与 CIGI 惯例相反——CIGI 标准里 Host 是实体状态权威（§3），IG 只是执行端。
3. [状态同步设计初版.md](./状态同步设计初版.md) §11 已把「实体预加载（EntityID → 模型映射表）」列为**待设计**，本文补上。

**演进脉络**：2026-09 曾定「把实例建立从 IG 启动改为 Host 命令驱动、运行中才 `loadScene`+挂 scene」；经 VSG 机制查证（向已渲染场景图动态加子树需运行中 `CompileManager` 编译 + 帧边界挂载，代价高、有卡顿/黑模型风险）与显存估算，**最终定案（2026-09 拍板）**：回到「IG 启动全量预建」，但实例**初始隐藏**、一次编译后**运行期零编译**——`EntityCtrl` 只控制显隐（`vsg::Switch` mask），实体实例的**存在与几何**归 IG 启动预建，**显示状态**归 Host 权威。独立实体目录文件保留为**几何来源**（Host 用它渲染可控制清单、IG 用它做 `id → path` 加载映射，§5/§6）。

## 3. 权威模型

**写死：Host 是实体状态权威，IG 是执行端。**

- **Host**：维护实体权威状态表（各 id 当前是 `Active` 还是 `Standby`），决定实体何时显/隐，下发位姿与动画。
- **IG**：实体**实例与几何**在启动时按共享目录全量预建（loadScene → 建 Entity → 挂 Switch → 一次性 compile，§7.2），初始显隐按 `initialEntityState` 设；运行期收到 `EntityCtrl` 只**切换 Switch 显隐**（不建实例、不加载、不编译），收到位姿/动画报文才更新。
- **方向**：全部实体控制报文为 Host → IG（`EntityCtrl` / `EntityPositionCtrl` / `AnimationCtrl`）。

> CIGI 标准依据（SISO-STD-013-2014 §6.1.38 Entity Control）：`EntityState` 控制实体几何的加载/卸载与场景树是否启用——`Inactive/Standby` 时 *"the entity is loaded, but its tree is not enabled in the scene graph"*；`Active` 时 *"the entity's tree is enabled"*。本设计以 `vsg::Switch` 的 mask 精确对应「tree not enabled / enabled」，实体几何在 IG 启动即加载并编译、Standby/Active 只切树开关——与标准「预加载 + 即时激活」范式一致（§7.2）。唯一刻意偏离是首版 `Destroyed` 降级为 `Standby`（§7/§12），及不用 `EntityType` 定位几何（§5）。

### 3.1 实体显示状态全局一致（写死，2026-09 拍板）

**同一实体在所有 IG 上的显示状态（`Active` / `Standby`，即显/隐）恒相同；不存在 per-IG 独立的实体显示状态。实体「是否存在」是 IG 启动预建的既定事实，不属于运行时状态。**

理由：1 Host + N IG 本质是**同一个世界的多视口投影**——各通道的差异只在相机偏移（三通道左/中/右按 `hFOV` 偏 yaw，见 [多通道同步模块设计.md](./多通道同步模块设计.md) §3.2 通道 frustum 拼接），不在世界内容。「实体在 A 通道可见、B 通道不可见」在业务上无法解释。

推论（后续设计与实现均按此前提）：

| # | 推论 |
| --- | --- |
| 1 | Host 只需维护**一份**实体状态表，无 per-IG 状态列；viewhost 实体列表每项显示单一状态即可（[viewhost设计.md](../viewhost设计.md) §4.8） |
| 2 | 向全体 IG **广播**同一 `EntityCtrl` 是正确形态，不是权宜之计；per-peer 定向**发送**因此不是本设计的前置依赖（§7）。**触发时需识别「新增 vs 重连回升」peer**（#20 B：按 TCP peer 端点去重），但识别只用于决定是否广播，不改变广播发送形态 |
| 3 | 向已就绪 IG 广播/重放「当前权威状态」都安全——IG 要么已处于该状态（no-op），要么正需补齐（**后加入**：集合内 ready 晚的 IG 由其 ready 跃变触发收到全量，§7）。**不含掉线重连 IG**——重连补发未设计（决策日志：掉队保持未同步、host 不补发，待定），见 §7「IG 为何也读」 |

> **唯一的 per-IG 概念是「加载失败」，不是「状态」**：目标显隐全局一致，但某台 IG 可能因本地原因（路径缺失、IO 抖动）在启动预建时加载失败 → 该实体在该 IG 缺失（无实例、无法显隐）。首版失败不上报不处理（§7.1），以 IG 侧日志暴露，接受此 per-IG 画面差异。

## 4. 报文

### 4.1 `CigiEntityCtrlV4` —— 实体显隐控制

`PacketID = 0x25`，`PacketSize = 16`。字段（`CigiEntityCtrlV4.h` / `CigiBaseEntityCtrl.h`）：

| 字段 | 类型 | 本设计用途 |
| --- | --- | --- |
| `EntityID` | uint16 | **映射主键**：查实体目录文件 `id → path`；`0` 保留为 ownship（本报文不用于眼点） |
| `EntityState` | enum | 显隐：`Standby=0`（隐藏）/ `Active=1`（显示）/ `Destroyed=2`（首版降级为 `Standby`，见 §7） |
| `EntityType` | uint16 | **不使用**（几何由 `id → path` 决定），默认填 `0` |
| `Alpha` | uint8 | 透明度 0–255；可运行时下发，配置仅作默认值 |
| `InheritAlpha` | enum | 子实体是否继承父透明度（`NoInherit=0` / `Inherit=1`） |
| `CollisionDetectEn` | enum | 该实体碰撞检测开关（`Disable=0` / `Enable=1`） |
| `SmoothingEn` | bool | 运动平滑开关 |
| `ExtendedEntityType` + 七段 DIS 类型 | — | **不使用**（未启用扩展类型；`ExtendedEntityType=Short`） |

### 4.2 `CigiEntityPositionCtrlV4` —— 位姿（同步只 LLA）

沿用既有命令面摆放语义（[状态同步设计初版.md](./状态同步设计初版.md) §4.1），命令实体位姿**恒 LLA**（同步只 LLA，2026-09 收敛；运行时判据见 [lla位姿传输设计.md](./lla位姿传输设计.md) §2）：

| 字段 | 用途 |
| --- | --- |
| `EntityID` | 目标实体；`0` = ownship 眼点（[lla位姿传输设计.md](./lla位姿传输设计.md) 覆盖，本文不涉及） |
| `AttachState` | 恒为 `Detach`（同步只 LLA，2026-09 收敛） |
| `ParentID` | 首版不做父子挂载（§12）：恒 `Detach` + `ParentID=0`（无父） |
| 位置字段 | 恒 `Lat/Lon/Alt`（LLA 绝对位姿） |
| `ClampState` | 钳制模式 |

> **坐标系判据见 [lla位姿传输设计.md](./lla位姿传输设计.md) §2**：同步层只支持 LLA（2026-09 收敛），命令实体位姿恒 `Detach`+LLA。场景有无 `EllipsoidModel` 决定读 pose 哪半与注入；参与同步（有 `igConfig`）的场景引擎自动注入椭球，`injectEllipsoidIfMissing`（bool）仅供单机椭球渲染。
>
> 位姿写入复用 `Engine::updateEntityPose(id, lla, eulerYprDeg)`，恒按 LLA 语义写。
>
> 父子挂载（`AttachState=Attach` + `ParentID≠0` 表达「挂到父实体、跟随运动」）为 §12 扩展位，首版不做；`AttachState` 在首版不表达任何挂载关系。

### 4.3 `CigiAnimationCtrlV4` —— 动画

`CigiBaseAnimationCtrl.h` 字段：

| 字段 | 用途 |
| --- | --- |
| `EntityID` | 目标实体 |
| `AnimationID` | 动画片段 id |
| `AnimationState` | `Stop=0` / `Play=1` |
| `AnimationLoopMode` | `OneShot=0` / `Continuous=1` |
| `AnimationSpeed` | 播放速度 |

> 注意 `CigiBaseEntityCtrl.h` 里的 `AnimationLoopModeGrp` / `AnimationStateGrp` 枚举是 V1/V3 历史遗留（`EntityCtrl` 曾内嵌动画字段）；**V4 中动画已拆到独立报文 `AnimationCtrlV4`**，不要通过 `EntityCtrl` 下发动画。

### 4.4 链路选择（写死）

沿用 [cigi梳理.md](../../notes/cigi梳理.md) 链路约定：

| 报文 | 链路 | 频率 |
| --- | --- | --- |
| `CigiEntityCtrlV4` | **TCP**（一次性） | 事件性（显隐切换：`Standby`/`Active`） |
| `CigiEntityPositionCtrlV4` | UDP（持续实时）/ **TCP**（一次性摆放） | 每帧 / 一次性 |
| `CigiAnimationCtrlV4` | **TCP**（一次性） | 事件性 |

Host 侧经既有 `outMsgWithIgCtrlTcp() << 报文 → flushTcp()` / `outMsgWithIgCtrlUdp() << 报文 → flushUdp()` 发送（IGCtrl 帧头自动前置，见 [状态同步设计初版.md](./状态同步设计初版.md) §7.1）。**无业务回执（fire-and-forget）**：TCP 靠传输层可靠，UDP 靠周期覆盖。

## 5. 路径映射与独立实体目录文件

**写死：模型路径不经报文；Host 与 IG 各自加载同一份**独立实体目录文件**，`EntityID` 作映射键，`EntityType` 填 0 不使用。**

- **实体目录 = 独立配置文件（2026-09 拍板，方案 B）**：`entities[]` 不再内嵌于各 IG 的 engine 配置（`viewhost_ig_*.json` / `scene_ecef_*.json` 等），而是抽成**单独的 `entities.json`**（顶层即实体数组，或顶层 `{ "entities": [...] }`，见 [位姿配置设计.md](./位姿配置设计.md)）。Host 与各 IG 各自加载这份文件。
- **同机 / 跨机一致（写死：人工确保）**：Host 与各 IG 进程读到的 `entities.json` 内容必须一致（同 [lla位姿传输设计.md](./lla位姿传输设计.md) §2.5 的「配置意图应一致（人工/部署约束）」）。同机部署时两进程可直接指向同一份文件（见下条）；跨机则各放一份相同内容。均**人工确保**，**不引入**网络分发 / 启动互校验机制。
- **文件实体暂放 engine 侧（2026-09 拍板）**：物理文件暂放 engine 资源目录 `engine/resources/config/entities.json`，Host（viewhost）与 IG 启动时各自指向该文件（同机共指 / 跨机各放，内容人工保持一致）。**不迁移**到 sync 库或另设共享目录。
- Host 用实体目录渲染「可控制实体」清单（[viewhost设计.md](../viewhost设计.md) §4.8），IG 在**启动预建**时用它做 `id → path` 加载映射；`CigiEntityCtrlV4` 只下发 `EntityID`，IG 按 id 查实体目录得 `model` 路径（§7.2 预建已用，运行时不再查）。
- 集成阶段离线确定映射（类比 Prepar3D 的 `DISEntityTypes.xml`，但以 `id` 为键、`.vsgt` 路径为值，不引入 EntityType 抽象层）。

```jsonc
// entities.json（独立文件；Host 与 IG 读同一份，内容一致、人工确保）
{
  "entities": [
    { "id": 1, "name": "teapot_center", "model": "models/teapot.vsgt" },                          // initialEntityState 缺省 = Active
    { "id": 2, "name": "truck", "model": "models/truck.vsgt", "initialEntityState": "Standby" }
  ]
}
```

**配置格式（写死：JSON，不用 XML / YAML / TOML）**：

- **格式一致**：文件是 JSON，顶层 `{ "entities": [...] }`（数组装键值对对象）。JSON 解析基础设施全项目已就绪（sync 库 `sync_json`），Host / IG 均可直接复用；换格式需新增解析依赖 + 重写全部配置与测试。
- **数组语义正确**：实体清单是有序同构集合，`entities: [ {...}, {...} ]` 是「数组装键值对对象」，正是表达实体表的标准形态。**不用对象当 map**（`{"1": {...}}`）——那会把 `id` 退化成字符串 key，丢失 int 类型、弱化顺序语义、无法硬校验重复。
- **强类型**：JSON 区分 int / string / bool，支撑「`id` 必须 int」、「`model` 非空」等硬校验。
- **id 唯一 fail-fast**：数组遍历 + 查重，重复 `id` 即解析失败，加载失败暴露配置错误，**不静默覆盖、不按文件顺序 / 行号兜底**（id 是协议主键，必须显式可读）。
- **id 合法域（写死：`1..65535`）**：线格式 `EntityID` 为 uint16（`0..65535`），其中 `0` 是 ownship 眼点保留值（[lla位姿传输设计.md](./lla位姿传输设计.md)，IG 侧 `EntityID==0` 分流）；故 `entities.json` 的 `id` 合法域为 **`1..65535`**。配置解析时 `id ≤ 0` 或 `id > 65535` 一律**解析失败**——否则 `70000` 会在打包时静默截断成 `70000 mod 65536 = 4464`，变成"发到另一个实体"的隐性错误。
- **`initialEntityState` 字面值契约（写死）**：允许值**仅** `"Active"` / `"Standby"`（精确匹配 CIGI `EntityStateGrp` 枚举名 `Active=1` / `Standby=0`，**大小写敏感**）；`"Destroyed"` / `"Remove"` 及一切其它值 → **解析失败**（fail-fast，**不回退默认**）。缺省 = `Active`。理由：该字段是 Host 初始下发行为的唯一输入（§6），静默回退会导致「配置写 `Standby` 却全部 `Active` 入场景」的状态漂移。

**对比 `EntityType` 抽象层**：CIGI 原生用 16 位 `Short Entity Type` 或七段 DIS `Extended Entity Type` 作几何代号，IG 内部维护「代号 → 模型」数据库。本项目直接用 `.vsgt` 路径、无类型数据库，引入 EntityType 是额外抽象成本；因此**用 `EntityID` 直接当映射键**（贴合现有 `_entityMap[id]`），`EntityType` 字段填 `0` 不承载语义。若未来需要 DIS 互操作，再迁移到 EntityType 抽象层（§12）。

> **`EntityType=0` 语义偏离（写死）**：CIGI 标准里 `entity type zero` 是「无几何实体」哨兵值（占位 invisible spectator 等）。本设计不启用 EntityType 语义，IG 侧**完全忽略 `EntityType` 字段**、仅按 `id → path` 定位几何，故填 `0` 不会触发标准里的「无几何」行为——这是对标准的刻意偏离，实现时不得因 `EntityType==0` 而拒绝创建几何。

## 6. 配置与报文职责划分

**配置只放「集成期静态确定」的东西，运行时要变的走报文。**

| 信息 | 放哪 | 理由 |
| --- | --- | --- |
| `id` | 配置（必填） | 报文映射键 |
| `model` 路径 | 配置（必填） | 映射核心；报文不下发路径 |
| `name` | 配置（可选） | 显示名，缺省 `basename(model)`（沿用 [位姿配置设计.md](./位姿配置设计.md)） |
| `initialEntityState` | 配置（可选，默认 `Active`） | **初始显隐**：`Active`（启动即显示）或 `Standby`（启动隐藏、待 Host 激活）。只定启动初值，运行态显隐由报文驱动。**Host 与 IG 都读**（见下，2026-09 收敛） |
| 初始位姿 `pose` | 配置（可选默认） | 默认摆放；运行时报文覆盖 |
| 默认 `alpha` | 配置（可选默认） | 静态外观；`EntityCtrl` 可动态覆盖 |
| 运行时 `EntityState` 显隐 | **报文（不配）** | `Standby↔Active` 是运行时显隐（§7），配置仅定启动初值 |
| 位姿 | **报文（不配）** | 持续 / 一次性下发 |
| 动画循环/播放/速度 | **报文（不配）** | 运行时动画控制；除非要"启动即播放某动画"的初始默认才配 |
| 父子挂载 | **报文（不配）** | `AttachState` + `ParentID`（**扩展位**，首版不做，§12） |

> **`initialEntityState` 归属（写死：双侧消费，2026-09 收敛）**：该字段位于**共享**配置，语义为「实体实例的**启动初值**」——IG 启动预建实例后按它设初始 Switch mask（`Active`=显示、`Standby`=隐藏），**Host** 建权威状态表时也按它初始化并广播。**初值收敛、运行期单源**：
>
> - **IG 读初值**：启动即按配置显隐——单机渲染（无 Host）由此获得初始画面；同步 IG 在「收到首个 `EntityCtrl` 前」的短窗内按配置显示。
> - **Host 读初值**：初始化权威状态表并全量广播（§7 下发时机）。**后加入 IG**（集合内 ready 晚）收到广播即被纠正到权威状态——其按配置显示只是**瞬态**，收广播即收敛。**掉线重连 IG 不在此列**（重连补发未设计，见 §7）。
> - **运行状态权威仍唯一归 Host**：`initialEntityState` 不参与运行期决策，仅作启动初值；「双状态源漂移」在新模型下退化为「启动/重启短窗内的瞬态不一致」——**后加入**由 §7 的 ready 跃变全量广播收敛；**掉线重连**的收敛未设计（决策日志「掉队 IG 保持未同步」，见 §7）。

> **`alpha` 默认值（新增字段）**：当前 `EntityConfig` 尚无 `alpha` 字段（`EngineConfig.h`），`viewhost_ig_*.json` 也未配置。`alpha` 作为「配置默认 + 报文覆盖」需**新增配置字段**；首版可只走 `EntityCtrl` 报文、暂不配默认值（此时默认用 CIGI 语义的不透明 255）。

> 现有 [位姿配置设计.md](./位姿配置设计.md) 的 `pose`（`local` / `ellipsoid` 双轨）语义**保留为"初始默认位姿"**：IG **启动预建实例**时以配置 `pose` 初始化 `transform`（**缺省一律补 0，实体恒有初始位置**，#21）；Host 后续 `EntityPositionCtrl` 覆盖。**仅预建时套用一次**——`Standby↔Active` 显隐切换不重套（否则会弹回、覆盖用户已摆位姿）；规则全文见 §9。

## 7. 实体显示状态机

**实体实例在 IG 启动时全部预建（§7.2），`EntityState` 只表达「显隐」两态**：`Active` = Switch ON（显示）、`Standby` = Switch OFF（隐藏）。无「不存在」态（除启动加载失败外），`Destroyed` 首版降级为 `Standby`（见下）：

```text
                    ┌──────────────┐
   ── 启动预建 ────▶│   Standby    │  (实例已建、已编译；Switch OFF —— 隐藏)
                    │  (隐藏)       │
                    └──────┬───────┘
                           │ EntityCtrl(Active)   → Switch ON
              EntityCtrl(Standby) ←────────────────┘ Switch OFF
                    (隐藏/保留实例与资源)
     Active 或 Standby 收到 EntityCtrl(Destroyed) → 首版降级为 Standby（Switch OFF，见下）
```

| 状态 | 含义 | `_entityMap` | Switch mask |
| --- | --- | --- | --- |
| `Standby` | 实例已建、已编译，**隐藏** | 有 | OFF |
| `Active` | 显示 | 有 | ON |

> **`Destroyed` 首版降级为 `Standby`（写死，对标准的刻意偏离）**：协议上 `Destroyed` = 释放几何、从内部数据结构移除、可重建（SISO-STD-013 §6.1.38）；但本设计实体**启动预建、运行期零编译**，真正释放实体需 `Destroyed` 走一次运行中 `loadScene`+`compile` 的重建路径（掉帧、复杂）。首版（2026-09 拍板）**收到 `EntityState=Destroyed` 一律按 `Standby` 处理**（Switch OFF、保留实例与 GPU 资源）——UI 不暴露销毁按钮，协议层也不真正释放。效果 = 「永久隐藏 + 保留显存」，与标准语义不符，作为**已登记偏离**（§12 + §13「完整 `Destroyed` 语义」行）；完整销毁/重建留待后续。
>
> **`Remove` = `Destroyed`（历史别名，写死）**：`EntityStateGrp` 中 `Remove=2` 与 `Destroyed=2` 同值（`CigiBaseEntityCtrl.h`），是 CCL 为兼容老版本命名保留的同义名；实现统一按 `Destroyed` 处理（首版同降级为 `Standby`）。

**转换（写死，首版）**：

| 转换 | 触发 | 首版 |
| --- | --- | --- |
| （启动）→ `Standby` | 启动预建实例，`initialEntityState=Standby` | ✅ |
| （启动）→ `Active` | 启动预建实例，`initialEntityState=Active`/缺省 | ✅ |
| `Standby` → `Active` | `EntityCtrl(Active)`（手动激活，Switch ON） | ✅ |
| `Active` → `Standby` | `EntityCtrl(Standby)`（手动隐藏，Switch OFF） | ✅ |
| `Active`/`Standby` → `Destroyed` | `EntityCtrl(Destroyed)` → **降级为 `Standby`**（保留实例） | ✅（偏离，§12/#19） |

- **`Standby`（隐藏）**：实例在树内、Switch OFF——CIGI 语义「loaded, but its tree is not enabled in the scene graph」（§6.1.38）。不可见、不参与渲染录制；几何与 GPU 资源常驻（§7.2）。
- **`Active`（显示）**：Switch ON，实体可见。**实体恒有初始位置**（transform 在启动预建时以配置 `pose` 填充，缺省字段补 0，见 §7.2 / §6）——激活无需位置检查（#10 已废除），`EntityCtrl(Active)` 直接置显。CIGI 标准「激活须有初始位置」由「恒有默认位置」满足，不拦截。

**初始实体集（写死：IG 启动全量预建，按 `initialEntityState` 设初始显隐；Host 对后加入 IG 广播当前权威状态）**：IG 启动即按共享目录**全部实体**预建实例并设初始 mask（`initialEntityState`）。Host 侧建权威状态表（按同一字段初始化）并在每个 IG ready 跃变时**广播全量当前权威状态**——**后加入 IG**（集合内 ready 晚）收到即收敛到权威态。viewhost 点选列表用于**后续控制**（`Standby↔Active` 切换 / 位姿 / 动画），**不提供销毁按钮**（销毁协议层降级为隐藏，见上）。

**IG 为何也读 `initialEntityState`（写死，2026-09 收敛）**：单机渲染（无 Host）需要启动即有初始画面，故 IG 按配置设初始 mask；这与「Host 运行期权威」不冲突——`initialEntityState` 只定**启动初值**，不参与运行期决策：
1. **初值只生效一次**：预建完成后，显隐完全由 `EntityCtrl` 驱动，配置不再被回读。
2. **后加入收敛、掉线重连不收敛（区分写死）**：**后加入 IG**（集合内 ready 晚，属正常启动流程）启动后按配置显示，收 Host 全量广播即收敛到权威态（§7 下发时机）；**掉线重连 IG** 的收敛**未设计**——Host 已进入同步后掉线的 IG 重连回来时保持未同步、Host 不补发（决策日志「掉队 IG 保持未同步」，待定），属接受行为。

**下发时机（写死：每个 IG 的 ready 跃变各自触发）**：不是全局只触发一次，而是挂在**每个 IG 连接层 ready 的跃变**上——后加入的 IG 由自己的 ready 事件触发下发，不会永久缺模型。标准时序同此：Host 等 IG 报 `IG Mode = Operate` 后才发实体数据（§4.7），对应本项目的连接层 ready。

**下发内容 = 当前权威状态（写死）**：`initialEntityState` 只在 Host **首次建表**时用于**初始化权威状态表**（此前运行时状态不存在）；此后每次下发（**后加入 IG ready / 用户操作**触发）一律携带**权威表的当前值**，不再回读配置。**掉线重连不触发补发**（见下）。

| 时机 | 下发内容 |
| --- | --- |
| Host 首次建表（进程启动、尚无运行时状态） | 由 `initialEntityState` 初始化权威表 → 广播该初始值 |
| 后续任何一次下发（后加入 IG ready / 用户操作） | 权威表**当前值**（用户切过 `Standby` 就发 `Standby`） |

否则「用户把实体 X 切 `Standby` → 另一台 IG 后加入 → X 又按配置显示直到收广播才纠正」，即后加入 IG 的瞬态不一致窗口会拉长（重连 IG 无此收敛，见「IG 为何也读」）。

> **广播重放无害（写死，依据 §3.1）**：`HostSync::flushTcp()` 当前只能向全部 `tcpReady && udpReady` 的 peer 广播（`thirdparty/sync/src/HostSync.cpp:433`）。初始下发**携带当前权威状态**（而非配置初始值）时，IG#2 加入触发的广播重放对 IG#1 无害——IG#1 收到的正是自己已处于的状态，按 §9 幂等语义走 no-op（§3.1 推论 3）。
>
> 因此 **per-peer 定向发送不是本设计的前置依赖**：状态全局一致（§3.1）下广播即正确形态。per-peer 定向**补发**能力（用于掉线重连 IG 的定向同步）**后续按需再议**——首版以「新增 peer 才广播 + 重连不补发」满足（见下触发实现）。
>
> **触发实现（#20 B 方案：需 peer 去重，写死）**：`HostSync` 现无 ready 跃变回调，仅有 `hasReadyIg()` / `readyIgCount()`（`thirdparty/sync/include/aerovista/sync/HostSync.h:65-66`）。仅靠「计数上升即广播」会把**掉线重连回升**误当后加入、向重连 IG 补发全量——与「重连不补发（B 方案）」矛盾。故 Host 侧需**记录已广播过的 IG 连接**（如按 TCP peer 端点去重），仅在**新增** IG ready（此前未广播过）时广播全量当前状态；**重连回升（已广播过的 peer 再次 ready）不广播**——重连 IG 保持未同步（决策日志「掉队 IG」），后续再完善 per-peer 补发。计数下降（IG 掉线）不触发下发。
>
> **启动期重复全量——接受（写死，2026-09 拍板）**：N 台 IG 依次启动接入时，Host 每遇一次「新增 IG ready」即广播全量，故每台 IG 会收到 N 次全量（其余 N−1 次因已处同态而 no-op）。此重复仅在**启动期**、低频、幂等无害（10 台 × 200 实体 ≈ 每台一次性 30 KB 量级），**保持现状**；已否决「等齐 N 台后统一下发」方案（单台故障会全局卡死、需额外超时/强制机制、后加入仍要补发）。若未来需消除重复，per-peer 定向（只向新增 IG 发全量）列为 §12 `[todo] #25`。

### 7.1 就绪语义与加载失败（首版不处理）

**就绪语义（写死）：只有连接层 ready，无业务层 ready。** IG 是否就绪由既有连接层判定——TCP 握手成功，`HostSync::readyIgCount()`（现状机制，不变）。就绪**不含**「模型加载完成」：实体几何加载与编译是 IG **启动预加载**阶段完成的本地行为，且**必须先于 sync 初始化与网络连接**（启动顺序写死，§7.2 / #23）——ready 只在场景就绪后出现，Host 首轮 `EntityCtrl` 必被已建全的 `_entityMap` 接住。这与 CIGI §4.7 一致——IG 发 SOF 即 mission-ready，标准无「模型加载完才就绪」的门槛。

**加载失败（写死：首版不处理、不上报）**：IG 启动预加载/编译某实体失败 → 该实体缺失（不在 `_entityMap`），仅 IG 侧记 `[WARN]` / `[ERROR]` 日志；**不建实例、不上报 Host、Host 不感知**。首版接受「某台 IG 缺某实体」这一静默 per-IG 差异（§3.1 的「全局一致」指成功预建并显示一致的实体；调试阶段路径写对则不触发）。

> 已知后果（写死）：加载失败 = 该实体在该 IG 缺失，画面与其余 IG 不一致（且 Host 后续对该 id 的 `EntityCtrl` 无效——IG 无此实例可切）。首版以日志暴露、不藏错；后续引入「失败实体以占位模型（红立方体）替换」提高可观测性（§12 扩展位 + TODO）。

### 7.2 启动全量预建 + 共享几何 + 一次性编译（写死，2026-09 拍板）

**写死：实体几何（加载 + GPU 编译）是 IG 启动阶段完成、此后常驻；实体显隐（Switch mask）是运行期由 Host `EntityCtrl` 驱动的状态。**

标准依据——CIGI 明确允许 IG 在初始化期预热实体几何，供后续「即时激活」：

> SISO-STD-013-2014 §6.1.38：Models may be preloaded to increase the initial display speed… geometry already exists in memory and is available for instant activation within the graphical scene.
>
> §4.7（Reset 语义）：all entity instances shall be removed from the scene… **Any cached databases or cached entity models may remain in memory.**

本设计比「缓存几何、收到命令再实例化」更进一步：**实例与场景树挂载也在启动完成**，运行期只切 Switch——因为向已在渲染的场景图动态加子树需运行中 `CompileManager` 编译 + 帧边界挂载（代价高、有卡顿/黑模型风险，§2 演进脉络）。

**启动装配 + 初始化顺序（写死，2026-09 拍板 / #23）**：引擎启动必须**先**完成实体场景构建（`assembleEntitiesScene`：loadScene 去重 → 建 Entity/Switch → 一次性 compile），**之后**才初始化 sync 子系统（`IgSync`）并发起网络连接——保证「先有场景、后发/收 `EntityCtrl`」。连接层 ready 只能出现在预建完成后，Host 在 IG ready 跃变即广播全量（§7），届时 `_entityMap` 必然已建全，不会丢首轮 `EntityCtrl`。

```text
assembleEntitiesScene()
  场景根 _scene + 椭球注入（保留）                     // 见 §13
  模型去重：遍历共享实体目录，按 model 路径分组
            → 每个唯一 .vsgt 只 loadScene 一次（共享几何，见下）
  逐实体建 Entity：
    实体.几何  = 该 model 的共享 node（多个实体引用同一编译几何）
    实体.transform = MatrixTransform —— 恒建，初始矩阵 = 配置 pose（缺省字段补 0，#21）
    实体.switch = vsg::Switch（含该 transform）→ 挂 _scene
    初始 mask = (initialEntityState == "Standby") ? OFF : ON
  一次性 _viewer->compile()    // 所有实体（含隐藏的）GPU 资源全部创建；此后不再 compile
  _entityMap[id] = Entity
  ↓ 至此场景就绪，才开始：
  IgSync 初始化 → 网络连接 → SOF/ready
```

- **transform 恒建、恒有初始位置（写死，2026-09 拍板 / #21）**：每个实体预建时**必建** `MatrixTransform` 并用配置 `pose` 填充——**不存在「无 pose 不设位」**。`pose` 可整体缺省或部分字段缺省，缺省一律补 `0`（`local` 位置三轴 / `lla` 三值 / `ypr` 三值）。由此实体**总有初始位置**（缺省则落坐标系原点/赤道海面），`Active` 无需位置检查（#10 已废除），`EntityCtrl(Active)` 直接置显；运行时 `EntityPositionCtrl` 覆盖该矩阵。

- **共享几何（写死，显存关键）**：多个实体引用同一 `model` 路径时，几何/贴图**只 load + compile 一份**，各实体以各自 `MatrixTransform` 引用同一 node——GPU 显存只占一份。引擎按 `model` 路径去重（map[path] → node）。这是「全量预编译」显存可行的前提（目标机场场景：多架同型号飞机共享一个机型几何，§2 显存评估）。
- **一次性编译的代价**：启动需加载 + 编译**全部**实体模型（含隐藏的），启动变慢、隐藏实体常驻显存——换取运行期 `EntityCtrl` 的零编译、零卡顿。目标机场场景（多机型 + 多架同型飞机 + 建筑/小模型/地形）的显存规模主要取决于**去重后的模型/贴图总量**；规模增长靠「共享几何 + LOD + 待命模型卸载」控制（§12 扩展位）。

- **隐藏子树不计入 `computeBound`（写死，2026-09 拍板 / #5）**：`vsg::Switch` mask=OFF 的子树在 bounds 遍历（默认 `overrideMask`）下被跳过，**不贡献场景 AABB**。故启动阶段全部实体隐藏（全 `Standby` 或无初始可见实体）时 `_scene` 的 AABB 近似空——默认相机走 [位姿配置设计.md](./位姿配置设计.md) §4 的既有 fallback（`radius≈0` → 绝对兜底位姿），不依赖隐藏实体参与取景；要初始取景准确需显式配 `camera.pose` 或保证有可见实体。

**边界划分**：

| 层 | 归属 | 生命周期 | 协议可见 |
| --- | --- | --- | --- |
| 实体实例 + 几何 + GPU 资源（`_entityMap` + Switch 子树） | **IG 启动预建**（内容由共享目录定） | IG 进程生命周期；常驻显存 | ❌（存在性不广播；失败不上报） |
| 实体显隐（Switch mask） | **Host 权威** | 由 `EntityCtrl` 驱动 | ✅ |

**`initialEntityState` 的 IG 初值角色（见 §7）**：预建时按配置设初始 mask，供单机渲染与「收首个 `EntityCtrl` 前」短窗使用；此后显隐完全由报文驱动。

> **首版范围（写死）**：IG 启动即对共享目录全部 `.vsgt` 去重后 loadScene + 建实例 + 挂 Switch + 一次性编译（单模型失败见 §7.1，跳过即可、不阻塞整批）。预加载是 IG 本地细节，**不需要改动任何协议**；Host 侧仅按 §7 广播权威状态。

## 8. 时序

**多 IG ready 跃变触发全量广播（§7 下发时机；IG 侧实例已由启动预建完成）**：

```text
Host                                                        IG#1        IG#2
  │ readyIgCount(): 0→1（IG#1 连接层 ready）                    │            │
  │ 广播全量当前权威状态（EntityCtrl 逐实体）                    │            │
  │ ───── TCP [EntityCtrl(1, Active)][EntityCtrl(2, Standby)]… ─▶ 逐个切 Switch │
  │                                                          │（no-op 幂等）│

  │                                                          │  no-op      │
```

## 9. IG 侧处理流程

`onEntityCtrl(const CigiEntityCtrlV4&)` 回调（`IgSync` 命令面 TCP session 订阅 `EntityCtrlV4`，与既有 `onEntityPositionCtrl` 同层）。实体实例在启动已全量预建（§7.2），**回调只切显隐 + 套属性，不建实例、不加载、不编译**：

```text
onEntityCtrl(ctrl):
  // —————— 第一段：显隐（只由 EntityState 驱动）——————
  if _entityMap 无 ctrl.EntityID:
    // 启动预建失败/未映射 id：无实例可切。记 WARN，忽略（§7.1 失败不上报）。
    return
  switch ctrl.EntityState:
    Standby:
      // 隐藏：Switch OFF（幂等——已隐藏则无操作）
      entity.switch->setAllChildren(false)      // 保留实例/几何/GPU 资源
      // 不套配置 pose（非首次装配）——保留当前位姿
    Active:
      // 显示：Switch ON（实体恒有初始位置——transform 启动预建已以配置 pose/默认 0 填充，#21，
      //   #10 位置检查已废除，直接置显）
      entity.switch->setAllChildren(true)          // Switch ON，显示（幂等）
    Destroyed:  // 首版偏离：降级为 Standby（§7/#19）
      // 协议语义为释放几何；本设计运行期零编译，首版不真正释放——
      // 处理等同 Standby：Switch OFF、保留实例与 GPU 资源。完整销毁/重建为后续项（§12/#19）
      entity.switch->setAllChildren(false)

  // —————— 第二段：属性字段无条件套用（无论显隐是否切换）——————
  // #9（写死）：Alpha / InheritAlpha / CollisionDetectEn / SmoothingEn 是「属性」，
  //   不随显隐切换而 no-op——实体在 _entityMap 即逐字段套用
  //   （含「已 Active 只调 alpha」：第一段 no-op、第二段照常生效）
  //   CollisionDetectEn / SmoothingEn 仅记录字段值；碰撞/平滑行为属 §12 扩展位，引擎暂不实现
  if _entityMap 有 ctrl.EntityID:
    entity.alpha            = ctrl.Alpha;            // 0 透明 .. 255 不透明
    entity.inheritAlpha     = ctrl.InheritAlpha;
    entity.collisionDetectEn = ctrl.CollisionDetectEn;   // 存值，无行为（§12）
    entity.smoothingEn       = ctrl.SmoothingEn;         // 存值，无行为（§12）
```

> **配置 `pose` 只在启动预建时套用一次（写死，2026-09 拍板）**：
>
> - **启动预建**：建实例时以配置 `pose` 填充 `transform`（**缺省字段补 0，实体恒有初始位置**，#21）。`initialEntityState=Standby` 的实体同样预建即套好位姿——激活时已有初始位置，无需额外等一个 `EntityPositionCtrl`。
> - **显隐切换**（`Standby↔Active`）：**不套** 配置 `pose`，沿用实体当前 `transform`。否则用户经 `EntityPositionCtrl` 摆好的位姿会在每次隐藏/激活后被配置值弹回，与「配置只定初始默认、运行时报文覆盖」（§6）矛盾。
>
> 一句话：配置 `pose` 绑定「实体实例的诞生（启动预建）」，不绑定「显隐切换」。
>
> **激活位置说明（#10 已废除，2026-09）**：实体 transform 在启动预建即填充（配置 `pose` 或默认 0），故 `Active` 无位置检查、直接置显；位姿报文的角色是「覆盖」，不参与激活门槛。CIGI 标准「激活须有初始位置」由「恒有默认位置」满足。实体在启动预建后**恒在 `_entityMap`**，位姿报文总能命中（更新 transform）；加载失败导致的缺失实体例外（无实例，`updateEntityPose` 忽略，见下）。
>
> **IG 读 `initialEntityState`（写死，2026-09 收敛）**：IG 在启动预建时按配置设初始 Switch mask（§7）；运行期显隐完全由报文驱动，配置不再被回读。

与既有路径的关系：

- **位姿**：`onEntityPositionCtrl`（已实现）分流——`EntityID==0` ownship 眼点、`EntityID≠0` 命令实体。命令实体分支按 §4.2 处理：恒 `Detach`+LLA，直接走 `updateEntityPose`。
- **`updateEntityPose`（实体恒在表内，2026-09 收敛）**：实体在启动预建后**恒在 `_entityMap`**（§7.2），位姿报文总能命中——`Active` 直接改位姿（实时）、`Standby` 更新语义位姿缓存（隐藏；后续 `Active` 置显时以其为准）。实体**不在** `_entityMap` 仅剩加载失败/未映射 id：按 fire-and-forget 静默忽略（或记 WARN）。加载失败导致的缺失实体位姿报文持续无效（§7.1）。
- **动画**：新增 `onAnimationCtrl` 回调，按 `EntityID` 定位实体并触发动画播放。

> **坐标系一致性（2026-09 收敛）**：同步层只支持 LLA，命令实体位姿恒 `Detach`+LLA，无 `Attach`/XYZ 路径，故无需运行时「坐标系一致性拒收」。参与同步（有 `igConfig`）的场景装配时引擎**自动注入**椭球，运行时不存在「场景无椭球却收 LLA」的错配路径（[lla位姿传输设计.md](./lla位姿传输设计.md) §2.3 / §4.5）。原 `entityPoseRejectedByFrameMismatch` 计数器随同步只 LLA 移除。

**开发前前提核对（实现时现场确认，非设计缺口）**：

1. **`EntityCtrlV4`/`AnimationCtrlV4` 订阅机制**：设计写「与既有 `onEntityPositionCtrl` 同层、经 `IgSync` 命令面订阅」（§9）。实现时对照 [状态同步设计初版.md](./状态同步设计初版.md) §8.1/§12 的通用捕获 + `addCallback<T>` 注册总纲确认 `CigiEntityCtrlV4`/`CigiAnimationCtrlV4` 订阅与 `EntityPositionCtrlV4` 双链路捕获机制一致、无遗漏。
2. **共享几何 × 多实例渲染安全（spike）**：设计采用「同 `model` 多实体共享一个编译 `node`、各实体独立 `MatrixTransform`+`Switch` 包裹」（§7.2）。实现 `assembleEntitiesScene` 前先做小验证：两实体同 `model`、各自 `Switch` 独立显隐，编译一次后多实例渲染无冲突、显隐互不影响。此 spike 同时覆盖 §12 `[todo] #24` 的动画挂载点疑点。
3. **engine 启动顺序落点**：文档写死「场景构建（预建+compile）先于 sync 初始化/网络连接」（§7.2 #23）。实现时核对 `engine.cpp` 启动路径中 `assembleEntitiesScene` / `initGraphics` / `initSync` 实际调用顺序；若现状 sync 先于场景装配，需调整为先场景后 sync。

> 此三前提均为「实现前现场确认/验证」，不阻塞设计文档作为开发依据；②建议以 spike 先行（成本低）。
