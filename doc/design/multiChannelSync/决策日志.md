## 框架设计

#### Host侧职责分类

1. HostDataManager:是 Host 侧任务状态门面：维护按报文族划分的各个权威数据表；
2. HostSync:负责报文收发；
3. HostDriver:持有 HostSync + HostDataManager，做具体业务逻辑，mfc UI直接调用；



#### 报文业务回调

1. Sinkable 设计
- CCL 自身带有RegisterCallBack接口，但其只支持C风格裸函数指针，无法携带上下文；不接受std::function（可以捕获this\引用等），因此对于业务侧的使用RegisterCallBack极不方便，放弃使用；
- Sync模块与业务方(engine)是单向依赖的，sync的igsync等拿不到业务方的信息，需要通过业务侧注入回调、通过sinkable进行桥接，将报文信息通过sinkable传给业务方的回调函数；
    - PacketCaptureProc ：对CCL暴露OnPacketReceived，做报文的动态类型转换
    - Sinkable ：持有std::function ，接收转换好的报文，调用callback
- 支持多播：CCL的processor本身支持多播（一个报文（ID），可以增加多个processor进行处理），在sinkable中增加按照报文类型增加多个callback的多播的支持，保持两边行为同步（还不是完全同步，一个是具体报文ID，一个是报文类型）
    - sinkable中使用vector存储同一个报文类型的多个callback,而不是使用map，因addcallback是按照报文类型做dynamic_cast定位，而不是报文ID；
    - sinkable暂时不支持按照报文id的多播，使用vevtor存储多个callback；未来如果有需求，可以考虑udp链路使用原生ccl报文id,tcp链路对ccl报文id进行固定位移作为新id，这样可以解决在一个map中存储两套链路的报文callback，与ccl的EventList保持结构上的一致；



## 业务逻辑

#### Host设计

1. 全部IG的实体状态一致，host只广播、不单播：多通道本质是「同一场景多视角」，实体状态必须全局一致——任何 IG 上的实体状态变更都广播到所有 IG，不维护 per-IG 状态。
2. ig ready = 连接 ready 

   - 连接层ready，发第一个sof
   - ig ready之后，host侧广播entity ctrl，控制模型进场景图；
3. 同步会话=等齐所有ig ready后开始，可以支持手动强行开始；
4. Host作为权威：
   - Host 作为仿真状态的权威：所有改变世界状态的报文都是单向 Host→IG。IG 侧一条能写实体状态或气象状态的报文都没有；
   - IG 作为数据库的权威：IG 独占数据库派生的事实——地形几何、地表材质、它自己那份环境数据，host想知道只能问，但只会问其中一个IG；
   - N 台 IG 依次启动接入时，Host 每遇一次「新增 IG ready」即广播全量，故每台 IG 会收到 N 次全量；
   - Host侧维护当前权威状态快照，ig重连之后，host补发同步当前状态；通过所有实体族、环境族、定义族报文下发状态；暂时不做，暂时重连ig直接忽视（待定）

#### 实体与运动控制

1. 实体列表

     - Host 作为权威管理所有 entity 的显隐状态；
     - host 与 ig 共享独立实体配置文件 `entities.json`（文件放 engine 资源目录，解析器暂留 engine 侧，不抽共享零 vsg 版）；
     - 装配模型：ig 启动即按共享目录全量预加载所有模型 + 挂 `vsg::Switch` + 一次性 compile（运行期零编译）；按 `model` 路径去重共享几何（同模型多实体只占一份显存）；`initialEntityState` 定初始 mask（两侧都读：Host 初始化权威表 + IG 设初始显隐；运行期单源归 Host）；
     - 运行时状态：standby = Switch off（隐藏）；active = Switch on（显示）；destroy 首版降级为 standby（不释放资源，完整销毁留后续）；
     - ig 加载实体模型失败，首版不处理不上报；
3. host 与 具体ig的通信问题

     - 实体的加载结果发送给host之后，host无法知晓是来自于哪个ig，目前回调事件只支持按照报文类型触发，不支持识别具体的ig；[使用计数？]
     - host 给ig发送报文，只支持广播，不支持单播，是否需要支持？[目前阶段不考虑ig断线重连、不支持单播]
     - CigiEntityCtrlV4的发送时机：
       - host 启动之后，ig全部接入，host发送entity ctrl给所有ig，则后续再有ig接入，收不到entity ctrl;[必须ig在初始时全部接入]
3. 坐标系选择：配置文件有`igConfig`，则ig使用ellipsiod;如果无`igConfig`,则是非ig模式，根据injectEllipsoidIfMissing 决定使用ecef还是笛卡尔local坐标系；
