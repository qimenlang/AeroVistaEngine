## 0. 初步同步：范围与目标

**初步同步**要先跑通「多通道跟同一 Host 节拍 + 共用眼点 + 通道视锥相邻」，不追求显示卡 Genlock / 亚毫秒校时。


| 纳入初步                                                      | 暂不纳入                                     |
| ------------------------------------------------------------- | -------------------------------------------- |
| 连接：TCP HELLO 握手 + UDP 同步面握手（`UDP_SYNC`）           | RTT / NTP 式时钟 offset；PTP（见 [时钟同步方案.md](./时钟同步方案.md) §7） |
| FreeRun：Host 按帧自动发 IGCtrl（不等 SOF）                   | Barrier 等齐再发下一帧（可后加 `frameGate`） |
| Host 在 IGCtrl 填入 `simTimeMs`（毫秒）；IG 消费（基准 + 本地流逝补偿） | IG 对 `simTimeMs` 做矫正 / 外推 → 已纳入短窗口外推 + 上限冻结（见 [时钟同步方案.md](./时钟同步方案.md) §4） |
| 每收到 IGCtrl 回一条 SOF（健康 / 掉帧观察）                   | 可靠 UDP、丢包重传                           |
| 每帧 IGCtrl 可内嵌共用眼点；各 IG 本地 `offsetDeg` 算 frustum | 实体级全量状态同步细则                       |
| 1 主窗（Host+IG）+ N 从窗（仅 IG）Engine 集成                 | 边缘融合 / 几何精标定工具链                  |
| TCP 仅握手（HELLO / HELLO_ACK）                               | TCP 加载/切库/复位等命令面 + ACK/NACK（词义见 [socket总结.md](../notes/socket总结.md)） |
| Host 先挂主窗 Engine（channel0）；独立 Host 进程（viewhost 示例已落地，正式拆进程仍后期）       |                                              |
| 本地世界系下 Host 驱动 IG 相机（`setCameraPose` 等）          | —                                            |
| 椭球 / ECEF 下 Host 驱动 IG 相机（LLA + 当地 YPR，§4.8）      | —                                            |

## 1. 职责划分与角色流程


| 类型               | 职责                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| **IgSync**         | UDP bind、`connect(Host)`（TCP HELLO + UDP_SYNC）、收 `IGCtrl`（含可选眼点）、回 `SOF`                        |
| **HostSync**       | UDP bind + TCP `listen`、收各 IG 的 `SOF`、按帧扇出 `IGCtrl`/眼点；维护 IG **peer 表**（接入追加；断线摘除见 §9） |
| **SynchronSystem** | IG 决策器：挂 loop；持有 **IgSync**；收包后 frame 校验、回灌 ⊕ `offsetDeg`、无新包/断线策略。**纯数据流**：场景模式/椭球/channelId 由宿主注入，Host 眼点经 `preFrame()` 收包喂入，产出位姿由宿主取走应用（`takePendingCameraPose`），不持有宿主的相机对象（见 [sync模块化设计.md](./sync模块化设计.md) §3.1）。Host 采样/扇出由宿主直接持 `HostSync` 完成，不经 SynchronSystem |
| **Engine**         | 帧循环 `preFrame / update / render / postFrame`；`mainCamera` / `setCameraPose`；从配置注入偏移与无新包策略。IG 侧每帧从 `SynchronSystem` 取位姿驱动相机；Host 侧持 `HostSync` + `HostPosePublisher` 采样（`captureAuthorityEye`）+ 扇出（`postHostFrame`） |


```text
Engine::tickOnFrame
  preFrame  → SynchronSystem 收包（入队眼点；处理 IGCtrl 时回 SOF；不写相机）
  update    → handleEvents →【主窗覆盖前采样喂入】→ SynchronSystem::update（决策）→ 宿主取 takePendingCameraPose 应用 → viewer update
  render
  postFrame → Host 用本帧采样（或重发上一帧）填入 IgCtrlMsg，扇出 → 全体 ready IG（含 A）
```



### 1.1 HostSync 进程边界

- **最终**：HostSync 独立进程；ABC 均为纯 IG，行为一致。  
- **当前**：HostSync 挂主窗 Engine；眼点权威 = 主窗覆盖前采样 → Host 扇出 → 全体 IG 回灌（含 A，≥1 帧延迟），不为 A 开「跳过回灌」旁路。  
- **独立 Host 进程示例已落地**：`thirdparty/sync/examples/viewhost`（MFC 程序）作为独立 Host，经键盘 / 圆周轨迹产生 Host 本地眼点扇出，见 [viewhost设计.md](./viewhost设计.md)。  
- 拆进程后：Engine 侧仅留 IgSync；权威源改为指定输入 IG 上行或 Host 本地输入（见 §5）。

### 1.2 角色流程（摘要）

```text
A（主窗 Host+IG）: HostSync.initialize + HostSync.run（置 RUNNING，仅一次）
                   + IgSync.initialize/connect
B/C（从窗仅 IG）:  IgSync.initialize/connect → Host readyIgCount 增加
每帧（tickOnFrame）:
  preFrame  → 各 IG 收包/回 SOF（不写相机）
  update    → handleEvents →【主窗覆盖前采样喂入】→ SynchronSystem::update（决策）→ 宿主取位姿应用
  render
  postFrame → HostSync::update(simTimeMs, eye*) 扇出 → 全体 ready IG
```

正式帧路径是 `Engine::tickOnFrame`（含权威采样）。`Engine::tickSync` 为测试捷径（`preFrame → stepSync → postFrame`，`stepSync` = `SynchronSystem::update` + 取位姿应用），**不**调用 `captureAuthorityEye`，Host 权威窗勿用其代替 `tickOnFrame`。

TCP 业务命令面（加载 / 切库 / 复位 + ACK/NACK 等）：**尚未实现**，名词见 [socket总结.md](../notes/socket总结.md)，缺口见 §9。

## 2. 双平面与网络拓扑（TCP / UDP）

本节只讲 **两条网络链路怎么连、谁连谁**，不涉及相机语义。

### 2.1 为什么叫「双平面」

「平面」= **一类用途的通信通道**（不是 3D 几何平面）。本模块故意拆成两条，避免互相拖累：


| 平面 | 协议 | 管什么 | 为什么单独一条 |
| ---- | ---- | ------ | -------------- |
| **同步平面 sync** | **UDP** | 每帧节奏与状态：`UDP_SYNC`、`IG_CTRL`（+可选眼点）、`SOF` | 高频、可丢；丢了用下一帧，不必可靠 |
| **命令平面 command** | **TCP** | 接入握手（当前仅 `HELLO`/`HELLO_ACK`）；日后加载/切库/复位等 | 必须送达、要回执；不适合塞进高频 UDP |


「双平面」= **UDP 同步面 + TCP 命令面** 两套并行链路，不是两套独立产品。

> TCP 业务命令（加载/切库/复位）+ ACK/NACK：**尚未实现**，见 §9；词义见 [socket总结.md](../notes/socket总结.md)。

### 2.2 「拓扑」指什么、谁和谁连

**拓扑** = 节点之间的**连接关系图**（谁 listen、谁 connect、包往哪发）。这里没有人「被拓扑」——是描述 **Host 与各 IG 的连线形状**：

```text
                    ┌──────────── HostSync ────────────┐
                    │  TCP :8100  listen ← 各 IG HELLO │
                    │  UDP :8000  收 SOF / UDP 握手      │
                    │  UDP sendto → 各 IG:udpRecv（IGCtrl）│
                    └──────────┬──────────┬──────────┘
                               │          │
              ┌────────────────┘          └────────────────┐
              ▼                                            ▼
         IgSync A（可与 Host 同进程）              IgSync B / C …
         TCP connect → Host:8100                   同上
         UDP bind 本机 udpRecv                     udpRecv 须不同（同机）
```

默认端口：Host UDP 收 **8000**、发 **8001**；TCP **8100**。同机多 IG：`udpRecv` 必须不同（8001/8003/8005…）；多机可同用 8001。

### 2.3 Peer 表（Host 侧）

**Peer（对等端）** = Host 眼里的「某一个已接入 / 正在接入的 IG」。  
**Peer 表** = HostSync 内存里的 IG 名单（实现：`HostSync::IgPeer` 列表），用来知道「该给谁发 IGCtrl、谁算 ready」。

每条大致含：`{ip, udpRecvPort, tcp 连接, tcpReady, udpReady}`。

- 接入时从 TCP **HELLO** 学习对方 `udpRecvPort`（以及 IP），**追加** peer。
- **两端都 ready**（`tcpReady && udpReady`）才计入扇出目标 / `readyIgCount`。
- **断线摘除尚未实现**：IG/TCP 死后不清除 `tcpReady`/`udpReady`，`readyIgCount` 不降；见 §9 P0。
- 通用释义见 [socket总结.md](../notes/socket总结.md)「Peer」。

## 3. 多窗口用法与通道配置

典型：3 Engine——A 主窗（Host+IG），B/C 从窗（仅 IG）；桌面相邻、frustum 相邻。

位姿表示、Host→IG 写相机、椭球 / ECEF 模式（已落地）见 **§4**；本节只保留窗口 / JSON / frustum 标定配置。

### 3.1 通道启动配置（JSON）

每个 Engine 进程一份 JSON（`engine/resources/config/`）；命令行：`engine.exe -c <path>`（**省略则默认 `default.json`**，不启同步）。


| 文件 | 角色 | 典型键 | `channelId` | 典型 `offsetDeg.yaw` |
| ---- | ---- | ------ | ----------- | -------------------- |
| `default.json` | 独立预览（无同步） | 仅 `model` / `window` | — | — |
| `main.json` | Host+IG | `syncSystem` + `hostConfig` + `igConfig` | `0` | 0 |
| `left.json` | 仅 IG | `syncSystem` + `igConfig` | `1` | ≈ +hFOV（样例 +18.05°） |
| `right.json` | 仅 IG | `syncSystem` + `igConfig` | `2` | ≈ −hFOV（样例 −18.05°） |


#### 解析约定（全体方案 A）

- **有字段 → 解析覆盖；无字段 → 保留 C++ 默认 / 功能 disable。**
- **字段在、类型或取值非法（含 `null`）→ 报错。**
- **任意对象键一旦出现，其 schema 声明的子字段全部必填**（含 `window` / `offsetDeg` / 各类 address；不允许半填合并）。
- 不要求写齐全部顶层键；日常单机只需 `model` / `window`。

#### 未知键策略：直接拒绝

配置 JSON（顶层及任意嵌套对象）中出现 **schema 未声明的键** 时，**直接拒绝加载**（报错返回，不得忽略、不得警告后继续）。

- 目的：拼写错误（如 `hostLocl`）立刻失败，避免静默落到默认值导致角色/端口配错难查。
- 范围：`EngineChannelConfig` 及其子对象（`window`、`offsetDeg`、`hostConfig`、`igConfig` 等）一律适用。
- 与方案 A 的关系：「键可不写」≠「可写错键」；缺省合法，多余键非法。

#### 功能启停：父对象是否存在

**不以 `channelId` 推导角色**；以 JSON **父对象键是否出现**决定 enable。


| 父键 | enable | 子字段（出现时全必填） |
| ---- | ------ | ---------------------------------------------- |
| `hostConfig` | `enableHost` → 启 HostSync | `udpPortSend`, `udpPortRecv`, `tcpPort` |
| `igConfig` | `enableIg` → 启 IgSync | `udpPortSend`, `udpPortRecv`（本地）+ `targetAddr`, `targetTcpPort`, `targetUdpPortRecv`（远端 Host） |
| 二者皆无 | 同步不启动 | — |


合法角色组合：


| 组合 | 含义 | 样例 |
| ---- | ---- | ---- |
| 无 `hostConfig` / `igConfig` | 独立预览 | `default.json` |
| 仅 `hostConfig` | 纯 Host | viewhost / 后期拆进程 |
| 仅 `igConfig` | 纯 IG | `left` / `right` |
| `hostConfig` + `igConfig` | 同进程 Host+IG | `main.json` |


`channelId` 仅作通道标识（联调 / 日志 / 标定），**不**驱动 enable；缺省暂保持 `0`（无同步时勿将其解读为「已启主通道」）。

#### 地址字段（按角色约束；运行时 `HostConfig` / `IgConfig`）

JSON **按角色只允许实际消费的字段**（多余键拒绝，见未知键策略）。

```text
hostConfig  必填：udpPortSend, udpPortRecv, tcpPort        // UDP 接收 bind（INADDR_ANY）+ TCP listen
igConfig    必填：udpPortSend, udpPortRecv                  // 本地 UDP 收发
                     targetAddr, targetTcpPort, targetUdpPortRecv    // 远端 Host（TCP connect + UDP 目标）
```

`igConfig` 自包含「本地收发端口」+「远端 Host 目标」，不再需要独立的 `hostEndpoint` 配对（见 [sync模块化设计.md](./sync模块化设计.md) §4.0）。本地 UDP 接收 / TCP 监听**固定绑定 `0.0.0.0`（INADDR_ANY，所有网卡）**；`bindAddr` 已移除（实现从未消费该字段，见 sync模块化设计.md §4.0）。

#### 跨字段校验

```text
if 有 requireIgConnect 且无 igConfig → 报错（无 IG 时该键无意义）
```

Host **不读** `igConfig`；IG 连接目标由 `igConfig` 的 `target*` 字段**显式**指定。

#### `requireIgConnect`（配置项）

布尔；**有 `igConfig` 时可配**。含义：IG **总会**在启动时尝试 `connect(igConfig.target*)`；本项只决定**连失败是否令 Engine init 失败**。

- **JSON / `EngineChannelConfig` 缺省恒为 `false`**，不做「双开则 true」等推导；需要强制连上时必须显式写 `true`。经配置启动时 `Engine::init` 把该值传入 `initSync`。
- **程序化 API**（`Engine::initSync` / `SynchronSystem::initialize`）形参缺省为 `true`（未显式传入时连失败则 init 失败）；与 JSON 缺省不同，调用方勿混淆。
- 有 `requireIgConnect` 且无 `igConfig` → 报错（见跨字段校验）。


| 模式 | 典型取值 | 行为 |
| ---- | -------- | ---- |
| Host+IG | 显式 `true`（`main.json`） | 连失败 → init 失败（同进程 Host 应已就绪） |
| 仅 IG | 显式 `false` 或不写（`left`/`right`） | 连失败 → 仍可启动（Host 可后到） |
| 仅 Host / 无同步 | 不写 | 无 IG，不参与 |

#### 字段要点


| 字段 | 要点 |
| ---- | ---- |
| `hostConfig` | 出现则启 Host；字段见上（`HostConfig`） |
| `igConfig` | 出现则启 IG；同机多 IG 的 `udpPortRecv` 须不同；含远端 `target*` |
| `syncSystem.channelId` | 通道号，不驱动 enable；缺省暂 `0` |
| `syncSystem.offsetDeg` | 出现则 `yaw`/`pitch`/`roll` 全必填；缺省全 0 |
| `syncSystem.hostEyeStalePolicy` | `ReuseLast` / `Freeze`；缺省 `ReuseLast` |
| `syncSystem.requireIgConnect` | 见上；有 `igConfig` 时可配 |
| `model` / `window` | 模型路径；`window` 出现则 `x`/`y`/`width`/`height` 全必填（显示与否由 `Engine::showWindow`） |


本地世界系应用：`最终位姿 = Host(pos+euler) ⊕ offsetDeg → setCameraPose`。

联调用三窗并排（非产品部署）：left `(0,0)`、main `(640,0)`、right `(1280,0)`，各 `640×1080`；`default.json` 可用整窗（如 `1920×1080`）。读配置写入 `WindowTraits`（当前无边框）。



### 3.2 通道 frustum 拼接（标定）

眼点相同（世界系）；投影参数一致时，水平相邻靠偏航：

- `aspect = 宽/高`；`hFOV = 2·atan(aspect·tan(vFOV/2))`
- 三通道硬拼（本引擎 Y-forward、Z-up，`Rz(+yaw)` 转向 −X / 左侧）：中 `yaw=0`，**左** `+hFOV`**，右** `−hFOV`；融合则幅值用 `hFOV−overlap`、符号同上
- 标定存各 IG 本地 JSON `offsetDeg`；同步包只更新共用眼点（见 §4.5）

## 4. 相机位姿驱动

本节整合 Host 驱动 IG 相机相关约定：Engine 位姿 API、本地世界系下的同步写相机、连接态策略，以及椭球 / ECEF 模式（已落地）。帧内采样与扇出时序细节见 §5；坐标系背景见 [坐标系统总结.md](../notes/坐标系统总结.md)。

### 4.1 目标与范围

### 4.2 本地世界系位姿约定

- **坐标系**：本地笛卡尔世界系；与 Engine / LookAt / Trackball 一致：**Y-forward、Z-up**。
- **对外接口**：仅 `position`（世界 XYZ，米）+ 欧拉角 **YPR（度）**；不用四元数作为对外 / 同步接口。
- **旋转顺序**：`Rz(yaw) * Rx(pitch) * Ry(roll)`，与 `Engine::setCameraPose`、LookAt↔欧拉互逆一致。
  - **对向量的生效顺序（钉死）**：先 roll、再 pitch、最后 yaw（矩阵乘积从右向左作用）。**实现禁止**写成 `Qz*Qx*Qy` 的三四元数连乘：VSG 四元数乘法是 **reverse-Hamilton**（`M(a*b)=M(b)·M(a)`），直接连乘得到的是 `Ry·Rx·Rz`（生效顺序反了）。正确写法是逐个作用 `roll→pitch→yaw`，或显式用矩阵/旋转复合。
  - 该顺序与 **CIGI 字段排列（Yaw/Pitch/Roll）一致**，也是飞行模拟器常用的 yaw→pitch→roll 约定（矩阵从左到右读）；但符号/轴语义是本项目应用层约定（§3.2、lla §3.2），不承诺与第三方 CIGI 视景姿态一一兼容。
- **LookAt 映射**（设相机）：

```text
eye     = position
forward = R(ypr) * (0, 1, 0)
up      = R(ypr) * (0, 0, 1)
center  = eye + forward * d          // 实现取 d = 1
→ LookAt(eye, center, up)
```

- **LookAt → 眼点**（主窗采样出站）：`position = eye`；由 `forward = normalize(center-eye)` 与 `up` 解出 YPR（`SynchronSystem` 内 `lookAtToHostEye`）。



### 4.3 Engine 位姿 API（已实现）


| API                                            | 说明                                                  |
| ---------------------------------------------- | ----------------------------------------------------- |
| `Engine::mainCamera()`                         | 返回主通道 `vsg::Camera`（viewMatrix 为 `LookAt`）    |
| `Engine::setCameraPose(position, eulerYprDeg)` | 按 §4.2 写入 LookAt；无相机或非 LookAt 时返回 `false` |
| `Engine::setCameraPoseLla(lla, eulerYprDeg)`   | 椭球写入口：LLA→ECEF、`up` 取 ENU 局部天向；无场景 `EllipsoidModel` 或非 LookAt 时返回 `false`（详见 [lla位姿传输设计.md](./lla位姿传输设计.md) §3） |

实现位置：`engine/source/engine.cpp`。单元标尺：`HostIGTests` 中 `setCameraPose writes LookAt from position and euler YPR`（`[unit][camera]`）。

有图形时 `SynchronSystem::applyHostEye` 按 `HostEyePose.frame` 选择：`WorldLocal` → `setCameraPose`；`LLA` → `setCameraPoseLla`。无图形路径仍更新 `_lastApplied` 供观测。
### 4.4 Host→IG 写相机链路

```text
主窗 Trackball → update 覆盖前采样喂入 → postFrame 同包扇出（含 A）
各 IG：preFrame 入队 → update 决策 → 宿主取 takePendingCameraPose：Host ⊕ offsetDeg → setCameraPose
```

**连接态与相机驱动（ABC 相同）：**


| 状态                                 | 相机驱动                                                           |
| ------------------------------------ | ------------------------------------------------------------------ |
| 从未连接 / 独立预览                  | 本地 Trackball / 键盘（可直接写相机）                              |
| 已连接且本帧收到新眼点（`hasEye=1`） | 更新缓存，**Host 位姿为准**（+ `offsetDeg`）                       |
| 已连接、有新 IGCtrl 但 `hasEye=0`    | **不入队新眼点**，等同「无新眼点」，走 `hostEyeStalePolicy`         |
| 已连接但本帧无新包                   | 由 `hostEyeStalePolicy` 决定                                       |
| 断开连接                             | **保留最后一帧 Host 位姿**（+ 标定；不自动跳回断线前的 Trackball） |


**无新包策略**（配置 `hostEyeStalePolicy`，默认 `ReuseLast`；经 `SynchronSystem::setHostEyeStalePolicy`，Engine 启动从 JSON 注入）：


| 策略          | 行为                                      |
| ------------- | ----------------------------------------- |
| **ReuseLast** | `update` 仍用缓存 Host 眼点写相机         |
| **Freeze**    | 本帧不改写 LookAt（停在上一帧已写入结果） |


**覆盖前采样要点**（细节与相位见 §5）：`handleEvents` 之后、回灌之前从 `mainCamera` 采样；与 `_lastApplied` 几乎相同则丢弃（防回声）；未采到则 `postFrame` 重发 `_lastSent`。权威窗 A 同样回灌 → 相对 Trackball **≥1 帧延迟**（与 B/C 一致）。

**刻意不做**：相对初始位姿的 XYZ delta；要求三窗初始 LookAt 一致；权威窗跳过回灌；长期独立 intent buffer（仅 `_lastSent` 供重发）。

### 4.5 `offsetDeg` 合成与 frustum

**刚性阵列旋转复合**（rigid-array），不是欧拉分量相加：

```text
R_host = Rz(yaw)*Rx(pitch)*Ry(roll)                  // §4.2 写约定
R_ig   = R_host · Rz(δy) · Rx(δp) · Ry(δr)           // offset 在 Host 自身系内旋转
再把 R_ig 按 §4.2 同一约定反解 YPR → setCameraPose(composed)
```

实现：`SynchronSystem::compose` / `applyHostEye`。yaw 偏移绕 **Host 自身 up 轴**（显示阵列的竖直轴）旋转，因此 Host 有非零 roll 时各通道 up 轴仍平行，frustum 贴边不撕开；左 `+hFOV`、右 `−hFOV` 符号不变（§3.2）。

> **为何不能用分量相加**：`ypr_host ⊕ offset` 等价于 `Rz(y+δ)*Rx(p)*Ry(r) = Rz(δ)·R_host`，yaw 偏移绕**地理 Up（世界 Z）**左乘。当 Host `roll≠0` 时 `up_ig = Rz(δ)·up_host ≠ up_host`，三块屏各自 roll、公共棱线错位——即线上「roll 撕裂」bug。早期实现曾用 `Ry·Rx·Rz` 约定使分量相加偶然等价于 rigid-array；为保证写 / 采遵循同一 `Rz·Rx·Ry` 约定，统一改为显式旋转复合。

Host 只发**同一主 view 眼点**；左右通道偏航来自各 IG 本地 JSON（§3.2）。

### 4.6 报文中的眼点（本地世界系）


| 项     | 约定                                                   |
| ------ | ------------------------------------------------------ |
| 打包   | 内嵌 `IgCtrlMsg`（`hasEye=1` 时 `pos*` / `*Deg` 有效） |
| 位置   | 世界绝对 XYZ（米）；不是经纬高，不是相对初始 delta     |
| 姿态   | YPR（度），顺序同 `setCameraPose`                      |
| 帧身份 | 同包 `frameCntr`；旧包整包丢弃（含眼点）               |




### 4.7 验收要点（对照 `HostIGTests`）

测试分层：应用契约可用 `queueHostEyePose` 注入；E2E 钉真 UDP 报文。主要场景：


| 场景             | 断言要点                                                       |
| ---------------- | -------------------------------------------------------------- |
| 位姿 API         | `setCameraPose` 后 LookAt 的 eye / center / up 与 YPR 约定一致 |

### 4.8 椭球 / ECEF 下的相机驱动（已落地）

**专项设计**：[lla位姿传输设计.md](./lla位姿传输设计.md)（模式判定、LLA+当地 YPR、写/采/报文、验收与不做项）。
背景与 LLA / ECEF / ENU 分层见 [坐标系统总结.md](../notes/坐标系统总结.md)。

**当前状态**：`setCameraPoseLla` / 采样出站产 LLA / 报文 `coordFrame`(WorldLocal | LLA) 均已实现；椭球场景 `LookAt` 落在 ECEF、Trackball 与 `EllipsoidPerspective` 自动启用。剩余项集中在通道偏移的 ENU 叠加（现仅 `yaw`）与近极点 / 俯仰 ±90° 的 LookAt↔YPR 数值策略，见 §9 P1。

#### 模式划分


| 模式             | 判定                                          | 场景 World | 同步权威眼点                         | 通道偏移                          | 写相机                             |
| ---------------- | --------------------------------------------- | ---------- | ------------------------------------ | --------------------------------- | ---------------------------------- |
| **本地**         | 场景无 `EllipsoidModel`                       | 本地笛卡尔 | 世界 XYZ + YPR                       | `offsetDeg` 欧拉相加              | `setCameraPose` 直接写 LookAt      |
| **椭球**         | 场景有 `EllipsoidModel`（自带 / 按 `coordFrame` 注入 WGS-84） | **ECEF**   | **LLA + 当地 YPR**                   | `offsetDeg` 欧拉相加（仅 `yaw` 有语义） | `setCameraPoseLla`：LLA→ECEF、`up` 取 ENU |


「模式随场景是否含 `EllipsoidModel` 切换」；`coordFrame` 是通道意图（`"Local" | "Ellipsoid"`），在无场景椭球时按意图注入 WGS-84 —— 详见 [lla位姿传输设计.md](./lla位姿传输设计.md) §2。

#### 椭球模式位姿语义（要点）

- **对外 / Host→IG**：**LLA（lat°, lon°, alt m）+ 当地 YPR**；`SynchronSystem::applyHostEye` 内部按 `HostEyePose.frame` 分派到 `setCameraPoseLla`（或 `setCameraPose`）。
- **渲染工作坐标**：ECEF 米制笛卡尔；`LookAt.eye/center/up` 落在 ECEF。
- **通道偏移**：目前仍走欧拉分量相加，仅 `yaw` 满足语义；`pitch/roll ≠ 0` 未支持（见 [lla位姿传输设计.md](./lla位姿传输设计.md) §7 与本文 §9 P1）。
- **采样出站**：主窗覆盖前采样在椭球模式下由 `HostPosePublisher::captureAuthorityEye → lookAtToLlaEye` 产出 LLA + 姿态，避免把 ECEF 大数当本地 XYZ 发出。

#### 报文（`IgCtrlMsg` / CIGI 对应包）

- `coordFrame = WorldLocal | LLA`；`hasEye` 时按模式解释字段（本地填 XYZ，椭球填 lat/lon/alt + 当地 YPR）。
- 帧身份仍按 `frameCntr` 整包取新；错模式眼点被首拒收 `[ERROR]`、计入 `eyePoseRejectedByFrameMismatch`（详见 [lla位姿传输设计.md](./lla位姿传输设计.md) §5）。

#### 与本地路径的关系

```text
本地模式:
  Host 眼点 = 世界 XYZ + YPR
  IG: XYZ ⊕ offsetDeg → setCameraPose → LookAt（本地 World）

椭球模式:
  Host 眼点 = LLA + 当地 YPR
  IG: LLA→ECEF；offsetDeg ⊕（现仅 yaw）→ setCameraPoseLla → LookAt（World = ECEF）
```

两条路径同帧循环共存，按场景 `EllipsoidModel` 自动分派。

## 5. 权威眼点、回灌与帧内时序

相机位姿语义与 API 见 **§4**；本节只固定 Host 权威源与单帧相位。

#### Host 权威眼点（ABC 作为 IG 行为一致）

目标：A/B/C 均为 IG，**最终渲染位姿一律来自 Host 回灌**；便于日后 Host 拆进程时 IG 侧逻辑不变。

**权威输入源（现阶段）**：带 Host 的主窗（配置含 `hostConfig`；样例 `main.json`，其 `channelId` 恰为 `0`，**不以** `channelId` 判定权威）。  
**下发方向**：眼点仅 **Host→IG**（内嵌于 `IgCtrlMsg`）。同进程下 Host 用主窗采样结果填充后扇出。

**后期**：Host 独立进程后，「权威 = 带 Host 的主窗」需改为指定输入 IG 上报或 Host 本地输入；上行格式另定。Host 本地输入已有独立 viewhost 示例（[viewhost设计.md](./viewhost设计.md)），「指定输入 IG 上报」仍属后期。

**断线判据（当前）**：IgSync 轮询 TCP 对端关闭后清除 `tcpConnected` / `udpSynced`。UDP 超时、心跳与 Host 侧 peer 摘除仍待细化，见 §9。

#### IG：单帧写入时机（覆盖前采样 + 回灌）

主窗 A（Host + 权威输入）：

```text
preFrame:   收 UDP IgCtrlMsg → 入队眼点；若处理了 IGCtrl 则回 SOF；不写相机
update:
  handleEvents()                 ← Trackball 可能改 LookAt
  【覆盖前采样】                 ← 宿主从 mainCamera 读 LookAt，喂入 HostPosePublisher::captureAuthorityEye（防回声由 HostPosePublisher 处理）
  SynchronSystem::update()       ← 决策；宿主取 takePendingCameraPose 应用（Host ⊕ offsetDeg → setCameraPose，含 A）
  viewer->update()
render
postFrame:
  用【本帧采样】或【_lastSent 重发】填 IgCtrlMsg，扇出 → 全体 ready IG
```

B/C（仅 IG）：无采样、无 Host；只收包并在 `SynchronSystem::update` 决策，宿主取位姿应用。

勿在 `handleEvents` **之前**写 Host 眼点。

#### Loop 相位（`preFrame / update / render / postFrame`）

正式路径：`Engine::tickOnFrame`。

```text
preFrame:   收 UDP（IgCtrlMsg，含可选眼点）→ 入队；处理 IGCtrl 时回 SOF
update:     handleEvents →【主窗覆盖前采样喂入】→ SynchronSystem::update → 宿主取位姿应用 → viewer update
render:     record / present
postFrame:  主窗用本帧采样（或重发上一帧）填 IgCtrlMsg → 扇出全体 ready IG
```

`Engine::tickSync`：测试捷径，跳过 `handleEvents` / 权威采样 / render；见 §1.2。

## 6. 时钟、节拍与报文



### 6.1 模拟时间（现阶段）

- Host 在 `postFrame` / `HostSync::update(simTimeMs)` 把模拟时间写入 `IgCtrlMsg.simTimeMs`。
- **单位：毫秒（ms）**。Engine 侧当前按约 `1000/60` ms 每帧递增（与 FreeRun 帧步进一致）。
- **IG 消费 `simTimeMs`**：以包内值为基准，经相位展开得内部 `simTimeUs`（`uint64` 微秒，保留 Host 绝对基准），消费时补偿本地流逝（`simTimeUs = lastSimTimeUs + (nowUs - lastReceivedAtUs)`）；丢包时同一公式外推并设时间上限冻结。详见 [时钟同步方案.md](./时钟同步方案.md) §2~§4。
- 不做 RTT offset / PTP（见 [时钟同步方案.md](./时钟同步方案.md) §7）。

乱序/迟到：只接受 `frameCntr` **不小于** 当前已处理帧的包（旧包整包丢弃；同帧号重发刷新基准，见 [时钟同步方案.md](./时钟同步方案.md) §4.1）。

### 6.2 节拍策略


| 配置项           | 含义                          | 初步默认 / 现状                                                                 |
| ---------------- | ----------------------------- | ------------------------------------------------------------------------------- |
| `igCtrlSendPace` | 何时发下一帧 IGCtrl           | **FreeRun**（按调用方 fps，不等 SOF）                                           |
| `frameGate`      | 是否等齐 SOF 再允许下一显示帧 | C++ 枚举可写 **BARRIER**；**通道 JSON 不可配**；`HostSync::update` **忽略** `_pace`，始终 FreeRun |


```text
setPaceConfig(SyncPaceConfig{ igCtrlSendPace, frameGate, targetFps, barrierTimeoutMs })
  // 可调用；当前 HostSync::update 不读 _pace（SynchronSystem::initialize 固定传默认 SyncPaceConfig{}）
HostSync::run() → RUNNING（initialize 时调用一次，非每帧）
HostSync::update(simTimeMs, eye*) → 本帧扇出 IGCtrl（FreeRun；不得阻塞等 SOF）
```

- **一次** `update` **= 一轮扇出**（对每个 ready IG 各发一份相同逻辑帧；`igCtrlSentCount` 计轮次，不是 UDP 包总数）。  
- 无独立周期 beacon；保活依赖 TCP 连接存活检测与 UDP 业务包。



### 6.3 报文字段（现状：`sync_proto`）

下列为**当前实现**的自建 POD。数据面演进为 CIGI 后的对应关系见 **§8**。


| 报文        | 方向                           | 字段                            | 用途                                                     |
| ----------- | ------------------------------ | ------------------------------- | -------------------------------------------------------- |
| `IgCtrlMsg` | Host→IG                        | `simTimeMs`（**ms**）           | Host 下发的模拟时间；IG 消费为基准 + 本地流逝补偿（见 [时钟同步方案.md](./时钟同步方案.md) §4） |
| `IgCtrlMsg` | Host→IG                        | `frameCntr`                     | 帧身份；乱序裁决                                         |
| `IgCtrlMsg` | Host→**全体 ready IG（含 A）** | `hasEye` + 世界 XYZ + YPR（度） | 共用主眼点；与帧计数同包（本地系，见 §4.6；椭球见 §4.8） |
| `SofMsg`    | IG→Host                        | `frameCntr` 回显                | 健康、掉帧；**不门控** FreeRun 发帧                      |


握手另有 `HELLO` / `HELLO_ACK`（TCP）、`UDP_SYNC` / `UDP_SYNC_ACK`（UDP）。

同进程权威位姿来源：主窗 **覆盖前采样**（非独立上行报文）。Host 拆进程后的上行格式另定。

SOF：每成功处理一条 IGCtrl 在 **preFrame /** `IgSync::update` 回一条；丢 SOF 不阻塞下一 IGCtrl。

## 8. 数据面切换为 CIGI CCL（演进）

目标：底层**业务数据报**改为 CIGI V4（`thirdparty/cigi` / CCL），同时**保留**现有 TCP｜UDP 双平面、动态端口与 HELLO / UDP_SYNC 握手。  
CIGI 与传输层解耦：CCL Session 只做 pack/unpack，**不**负责 socket、listen/connect、端口发现。

### 8.1 分层决策


| 层 | 策略 | 说明 |
| -- | ---- | ---- |
| TCP / UDP / 端口 / peer 表 | **保持** | 同机多 IG、动态学 `udpRecvPort`、命令面走 TCP 的工程选型不变 |
| 握手 `HELLO` / `UDP_SYNC` | **保持自建** `sync_proto::WireMsg` | 标准 CIGI **无**对等发现报文；Session 不能替代 |
| 数据面 IGCtrl / 眼点 / SOF | **改为 CIGI V4** | 见 §8.3 |
| 日后加载 / 切库 / 复位 | **继续倾向 TCP** | 可靠 + ACK 比 UDP+自建重传更省事；载荷可为 CIGI 控制包或自建命令（见 §8.5） |


传统 CIGI 产线多为**预配置 IP/端口 + 纯 UDP**（DummyIG/MiniHost 亦然），不做 TCP 握手与动态端口——那是固定机房部署习惯，不是「用了 CIGI 就禁止自建链路」。本项目可自建链路、只换载荷。

### 8.2 CIGI 能力边界（相对现状）

**能覆盖（节拍层）**

- 帧号：`CigiIGCtrlV4::FrameCntr`
- SOF 回帧：`CigiSOFV4`
- FreeRun：Session 异步（`SetSynchronous(false)`），不等齐 SOF 再发
- 同一 UDP 数据报内多 packet：`OutgoingMsg` 一次 `PackageMsg`

**不由标准 CIGI / CCL Session 提供**

- TCP HELLO + 运行时学习各 IG `udpRecvPort` / peer 表
- 「TCP 命令面」作为 ICD 规定通道（CIGI 控制字段通常仍走 UDP 会话）
- IGCtrl **内嵌**眼点字段（标准 IGCtrl 无位姿）

**与现状拧着、但可改映射而不改业务方向**

| 现状 `sync_proto` | CIGI 映射 | 说明 |
| ----------------- | --------- | ---- |
| `IgCtrlMsg` 同 struct 含 `hasEye`+XYZ+YPR | 同 datagram：`IGCtrl` +（有眼点时）`EntityPositionCtrl` | **多一个逻辑包**，常仍是**一次** `sendto`；跟拍语义不变 |
| 本地世界系绝对 XYZ | `EntityPositionCtrl` **Attach** + `X/Y/Z off`（相对合成 parent） | 本地模式路径；勿默认塞 Detach 的 Lat/Lon（有 ±90/±180 校验）。**为何 Attach 而非 Detach+XYZ、EntityID/ParentID 含义（非场景图）**见 [lla位姿传输设计.md](./lla位姿传输设计.md) §5 |
| LLA + 当地 YPR（椭球模式，已落地 §4.8） | `EntityPositionCtrl` **Detach** + Lat/Lon/Alt + 姿态 | Host `HostEyePose.frame == LLA` 时选 Detach；线上不带私有 frame 字段，收端按包结构判断 |
| `simTimeMs`（double ms） | IGCtrl `TimeStamp`（`uint32`，约 10µs 步进） | 需换算约定 |
| 极简 `SofMsg` | SOF 字段更多 | 填 FrameCntr 即可；其余按 CCL 默认/忽略 |


结论：换 CIGI **不只是图省事**，但也**没有**挡住「保留现拓扑」——挡住「整包换成标准 CIGI 而不改映射」的是眼点内嵌与本地 XYZ；用 IGCtrl+EntityPosition + Attach 过渡即可继续跟拍。

### 8.3 目标数据面报文


| 方向 | CIGI 包 | 用途 |
| ---- | ------- | ---- |
| Host→全体 ready IG | `CigiIGCtrlV4` | `FrameCntr`、时间戳；FreeRun 节拍 |
| Host→全体 ready IG（有眼点时） | `CigiEntityPositionCtrlV4` | 共用主眼点；与 IGCtrl **同一 UDP buffer** |
| IG→Host | `CigiSOFV4` | 回显帧号；**不门控**下一 IGCtrl |


`offsetDeg` 仍在各 IG 本地 JSON，不上线（与现设计一致；亦可远期改 Host 发 `ViewCtrl`）。

UDP 收包分流（同一 socket）：

```text
if magic == AVSY → 握手 / UDP_SYNC（自建）
else            → CIGI unpack（IGCtrl / EntityPosition / SOF）
```

### 8.4 传输与分帧注意

- **UDP 数据面**：一次 `recvfrom` 边界清楚；CIGI 多 packet 在同一数据报内解析即可。
- **TCP 命令面**（若载荷变长）：TCP 是字节流，存在粘包/拆包，需**长度分帧**或按 CIGI 包头 size 拼出完整消息；定长 `WireMsg` 握手不受影响。
- 握手仍是：双方先 **bind UDP** → TCP connect → `HELLO`（上报 `udpRecvPort`）→ `UDP_SYNC` 探测；**不是**「TCP 通了再建立 UDP 连接」（UDP 无连接）。

### 8.5 命令面与 TCP

- 标准 CIGI **不定义**专用 TCP 命令面；`DatabaseID` / `IGMode` 等通常在 UDP 控制包里。
- 本项目仍可采用 **TCP 传命令**（加载/切库/复位 + ACK）：比 UDP+自建 ACK 更直接；与是否用 CIGI 数据面无关。
- 「保留现拓扑就必须自建 TCP」应收窄为：若要坚持**运行时发现端口 + 命令走 TCP**，标准 CIGI Session 盖不住，需自建（或改预配置端口并放弃 TCP 命令面）。

**命令面载荷选型（写死）：用 CIGI `IGMsg`（V4），不用 IGCtrl。**

| 维度 | IGCtrl | **IGMsg（选定）** |
| --- | --- | --- |
| 用途 | 帧级控制（数据面已用它发帧节拍 / 时间戳 / 眼点） | **通用消息 / 指令通道** |
| 字段 | `DatabaseID` / `IGMode` / `FrameCntr` / `TimeStamp` | `MsgID`（uint16）+ `Msg`（变长字节） |
| 与数据面冲突 | 数据面已用 IGCtrl，命令面再塞会语义混淆 | **不冲突**：独立指令通道 |
| 承载自定义指令 | 只能映射到 `DatabaseID`（加载/切库）与 `IGMode`（复位）两个语义 | `MsgID` 自定义指令码 + 任意载荷，可扩展 |
| 变长载荷 | 固定字段 | `Msg` 变长，加字段不改报文格式 |

- **标准 CIGI 语义**：`IGCtrl.DatabaseID`（0=无动作，1~127=加载指定库）、`IGCtrl.IGMode`（Reset/Standby/Operate/debug）是「加载/切库/复位」的原生承载，但走 **UDP 控制包**；本项目命令面走 TCP，故用 `IGMsg` 封装自定义指令码更干净。
- **指令码约定**（示例，最终以实现定）：`MsgID = 1`（加载 / 切库，`Msg` 携带库名 / 路径）、`MsgID = 2`（复位）、`MsgID = 3`（……）；ACK/NACK 由 IG 沿同一条 TCP 回执，携带原 `MsgID` + 结果码。
- **长度分帧**：TCP 是字节流，命令面载荷（`IGMsgV4` 变长）需**按 CIGI 包头 `PacketID + PacketSize` 拼出完整消息**（§8.4 已要求）；定长 `WireMsg` 握手不受影响。

### 8.6 实现与验收落点

- 改动集中在 `HostSync::update` 组包、`IgSync` 收 IGCtrl/回 SOF、UDP demux；`SynchronSystem` 采样/回灌/`offsetDeg`/stale **尽量不动**。
- 线格式契约与节拍/E2E 用例标签：`HostIGTests` 中 `[cigi]` / `[unit][cigi][wire-contract]`（行为方向不变：帧交换、SOF、FreeRun、真报文眼点、防回声）。
- 握手与连接面用例（§1 类）继续覆盖自建 `WireMsg`，不改为 CIGI。

1. 复用常驻 `CigiHostSession` / `CigiIGSession`（现每帧堆上创建，可优化）。
2. TCP 命令面载荷若走变长 CIGI，补长度分帧。

### P1 — UDP 握手偶发失败优化

**问题**：Windows 下偶现 IG 首次握手失败（`readyIgCount` 少 1），根因是握手确认链路本身走 UDP——`UDP_SYNC_ACK` 同样可能丢包，且 `TcpSocket::connect` 200ms 超时在负载/调试器下偏紧。`IgSync::connect` 虽有多层重试（TCP×16、握手×8、UDP_SYNC 内重发），但**全部耗尽后永久掉线、运行期不自愈**。

**待优化方向**（择一或组合）：

1. **自愈重连（兜底）**：IG 运行期周期性检查 `udpSynced`，失败则重新 `connect`（当前仅启动时连一次）。
2. **ACK 走 TCP 可靠通道**：`UDP_SYNC_ACK` 改经已建立 TCP 下发（TCP 可靠），消除确认丢包放大。
3. 调参：放宽 `tcpConnectTimeoutMs`、UDP_SYNC 重发间隔指数退避。

### P2 — 明确不在初步范围（防范围蔓延）

1. 显示同步（VSync 对齐、Genlock、swap 屏障）
2. 精时钟同步（RTT offset / PTP）——见 [时钟同步方案.md](./时钟同步方案.md) §7（PTP 留扩展位，当前不做）
3. 边缘融合、非对称分辨率通道的完整光学标定
4. Host 发现/配置中心（独立 Host 进程已有 viewhost 示例，见 [viewhost设计.md](./viewhost设计.md)）
5. 为迁就 CIGI 而拆除 TCP/动态端口、改为纯预配置 UDP（**非必须**；见 §8.1）
