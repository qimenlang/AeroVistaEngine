# 平台同步设计

Platform 用本仓库 **`HostSync` 做 CIGI Host**。viewhost 是视景侧 **调试器 / 编辑器**（另一团队的平台进程不能日常拿来调 IG）。正式运行 **不经过** viewhost。

> 本文档描述设计决策；实现状态见 §12。不记录变更历史。

## 1. 目标与边界

### 1.1 目标

1. **正式**：平台进程 `HostSync` 当唯一 Host；各 IG `igConfig.target` 指向平台。节拍用现成的 `outMsgWithIgCtrlUdp/Tcp()`（数据面帧号 + 自计时 TimeStamp / 命令面独立帧号）。少一跳 RTT。
2. **本地调试**：与现状相同——无平台，viewhost `HostSync` 当 Host，键盘眼点 / 实体 / 命令行。见 [viewhost设计.md](./viewhost设计.md)。
3. **真模拟器上调试**：平台仍当 Host 并产生 IGCtrl/眼点；IG 改连 viewhost；viewhost **透传** 平台↔IG 的 CIGI 消息（**不改 IGCtrl 头**），数据面 UDP IGCtrl 入队后 `packSof` 回平台，并可按链路 **附加** 调试包（如天气）。
4. 不把 viewhost 合并进平台进程（视景团队否则无法脱离仿真环境调 IG）。

### 1.2 非目标

- 正式运行夹 viewhost、改 IGCtrl/SOF 头、viewhost 当节拍权威。
- shuttle `IgSync` 解包再 `<<` 进另一 Session。
- 裸 socket 自建 50 路 `PacketID` 工厂；改 `thirdparty/cigi` 去掉方向表。
- 本仓库实现平台仿真业务（可用最小 `HostSync` 替身测中继）。
- 运行时热切三种用法（改配置 / 改 `igConfig.target` 并重启相关进程）。

### 1.3 一句话

**正式 IG 直连平台 HostSync。** viewhost 只为 debug：要么自己当 Host，要么在真模拟器上 **消息透传并按 TCP/UDP 矩阵附加调试包**；数据面帧号与时间戳始终来自 **当前那台 Host**（正式/真模拟器 = 平台，本地 = viewhost）。

## 2. 三种用法

三种 **互斥**，同一组 IG 同一时刻只连一个 Host。

| 用法 | 谁跑 `HostSync` | IG `target` | viewhost | 节拍 / IGCtrl / SOF |
| --- | --- | --- | --- | --- |
| **正式** | 平台 | 平台 | **不在环** | 平台 `outMsgWithIgCtrl*`；IG 回 SOF 给平台 |
| **本地调试** | viewhost | viewhost | 调试器 Host（现状） | viewhost；无平台 |
| **真模拟器调试** | 平台 | viewhost（中继） | 透传 + 附加；**禁止** 自己再发数据面 IGCtrl | 平台的头原样到 IG；虚 IG 在数据面 IGCtrl **入队后** `packSof`（§6.1）；master 的 TCP 上报转平台，真实 IG 的 UDP SOF 不转（§6.3） |

```text
正式
  平台 HostSync  ←CIGI+HELLO→  各 IgSync

本地调试
  viewhost HostSync  ←CIGI+HELLO→  各 IgSync

真模拟器调试
  平台 HostSync  ←HELLO+UDP_SYNC（虚 IG）+ CIGI 原样→  viewhost  ←HELLO+UDP_SYNC+扇出→  各 IgSync
```

## 3. 选型与否决

| 路径 | 结论 |
| --- | --- |
| 正式直连 + 本地 Host + 真模拟器透传附加（本文） | **采用** |
| 两段 Session 解包再组包 / shuttle `IgSync` 回自己的 SOF | **否决**：改帧号、双节拍；正式也不该多一跳 |
| 中继改 IGCtrl/SOF 头、viewhost 当节拍权威 | **否决**：正式节拍已在平台 `HostSync`；调试中继跟平台钟 |
| 完全透传且中继模式仍跑 `HostDriver::update` 扇出眼点 | **否决**：两路数据面 IGCtrl |
| 调试天气塞进平台 UDP 眼点 / 接到平台 TCP 末尾 | **否决**：天气一次性、走独立 TCP 消息；透传不改平台消息 |
| 中继 TCP 半截就转 / 自组插进半条平台消息 | **否决**：切齐一条 CIGI 消息再入队整条 `sendAll`（§6.2） |
| 命令面改可靠 UDP（ACK 重发）替换 TCP | **否决**：为中继插包自造传输层，不动现网 TCP/UDP 分工 |
| Host↔Host 互发 / 改 CCL 方向 / 合并进程 | **否决** |

## 4. 正式：IG 直连平台

平台与现网 Host 相同：`loadHostConfig` + `HostSync::initialize` / `run`，UDP 收 SOF、TCP listen 收 HELLO。IG 配置与连 viewhost 时相同，只换 `igConfig` 的 `targetAddr` / `targetTcpPort` / `targetUdpPortRecv`。

多通道仍由各 IG `channelId` + `offsetDeg` 本地加偏，平台不感知通道数（[viewhost设计.md](./viewhost设计.md) §2 同一原则）。

---

## 5. 本地调试：viewhost 当 Host

现网不变。`HostDriver::update`：`outMsgWithIgCtrlUdp` + 眼点 + `flushUdp`。实体 / 命令行走 TCP。无平台、无中继。

## 6. 真模拟器调试：透传 + 附加

### 6.1 传输角色（不是第二套 CIGI Session）

对 **IG**：viewhost 仍是 HELLO 的 Host（现有 `HostSync` listen / peer 表 / 学 UDP 口），否则不知道往哪 `sendto`。

对 **平台**：viewhost 是一台 **虚 IG**——按现网 IG 的 `IgSync::connect` 走完 **TCP HELLO + UDP_SYNC**（`relay.target*` 当 `HostTarget`，HELLO 上报 `relay.udpPortRecv`，`channelId=0`）。**推迟到真实 IG 起齐之后才 `connect`**（§6.4），平台 `HostSync` 的 ready 判定不用改：握手完成前 `readyIgCount == 0`（不往中继 `flush*`）；`tcpReady && udpReady` 后 `readyIgCount == 1`，随后 `flushUdp`/`flushTcp` 自然打到中继。

连上之后 CIGI **仍透传**（不改 IGCtrl 头）。禁止把平台报文喂进虚 IG 的 `drainIncoming` / `outMsgWithIgCtrl*` 当唯一消费者（那是已否决的 shuttle：队列被解包吃掉，真实 IG 收不到）。握手可复用 `connect`；平台下行字节从虚 IG 的 I/O 队列取**原始数据报/切齐消息**入 Host FIFO。

**虚 IG 回 SOF（写死，#13）**：每条以 `IGCtrl` 开头的**数据面 UDP** 透传消息，**原样入 Host UDP FIFO 成功之后**，按该包头 `FrameCntr` `packSof` 回平台（读 IGCtrl 24 字节头即可，不必 CCL 解包整条）。TCP 透传 / 调试包入队后**不**回 SOF。无 ready peer（入队会丢）则**不**回 SOF。禁止 `drainIncoming(sendSof=true)` 作为这条回 SOF 路径。

**数据面禁止** 再用 `CigiIGSession`/`outMsgWithIgCtrl*` 把消息拆开重组成另一条。TCP 用消息级分帧（[状态同步设计.md](./多通道同步/状态同步设计.md) §4.2）切出 **完整消息字节**（不 CCL 解包）再转发。消息起点随方向：下行 `IGCtrl`（`0x0000`），回程 TCP `SOF`（`0xffff`）。切齐后的字节入 **Host 对应发送 FIFO**（与 `flush*` 同一套，§6.2 / 状态同步 §7.2）；调试包经 `flushTcp` 入下行 TCP FIFO（§7）。

中继 **没有** 数据面帧循环：不跑 `HostDriver::update` 扇出眼点。转发不经 UI 定时器。

**报文自检（写死）**：只对 **真实 IG**（[viewhost设计.md](./viewhost设计.md) §4.7）。`testtcp` / `testudp` 组包经 `flush*` 入 Host FIFO 发给 IG；「接收」看真实 IG 经 `HostSync` 的上行。与平台那一跳无关：不解析、不显示平台下行，也不把自检包发给平台。中继时仍禁止另发一套数据面 IGCtrl（即禁止 `HostDriver::update`）。

### 6.2 下行

`Req` / `Def` / `Ctrl` 是 **Host→IG**（[cigi梳理.md](../notes/cigi梳理.md)）；`Resp` 不会出现在这一段。

原子单位是 **一条 CIGI 消息**（Host→IG 以 `IGCtrl` 开头；一次 `flushTcp` 里可以有多个业务包，整条不拆）。切齐边界 = 下一个 `IGCtrl`。写死：

```text
平台 TCP recv → 按 IGCtrl 切齐 → Host TCP 发送 FIFO → sendAll 全体 ready IG
viewhost flushTcp（天气/实体/testtcp）组包     → 同一 FIFO     → 挨个 sendAll
平台 UDP 数据报（一报一条）                   → Host UDP 发送 FIFO → sendto 全体 ready IG
                                         入队成功 → packSof(同 FrameCntr) 回平台
viewhost flushUdp 组包                         → 同一 FIFO     → 挨个 sendto（不 packSof）
```

禁止：半截 TCP 就转；`flush*` 直接写 socket；自组插进正在发送的那一条中间。发送者一次只取队头一条。本地调试（无平台）同样：`flush*` 只入队。

谁回 `Resp` 是 **IG 业务**：各 IG 看自己的 `channelId`，**只有 0 回复**；非 master 收到请求也不回。正式直连同样（`HostSync::flushTcp` 本就扇出全体）。中继不按包分流。

IG 看到的数据面 `FrameCntr` / `TimeStamp` **等于平台发出的**。平台收到的 SOF 是虚 IG **入队后**的 `packSof`（同号）；测的是中继已受理，不是真实 IG Present。真实 IG 的 SOF 留在 viewhost，供 IG 列表 RTT。平台若开 SofGated，等的也是这条虚 IG SOF。

「读不到下一包头则乐观结束」、后续包 body 未齐则等待：两向沿用现网（状态同步 §4.2）。中继不另做可靠 UDP。`CigiFrameAssembler(startPacketId)` 已按方向给消息起点（下行 `0x0000` / 回程 `0xffff`）；中继回程须用 SOF 起点接入 FIFO（仍待实现）。

### 6.3 回程

`Resp` / 通知是 **IG→Host TCP**，不会发给 IG。数据面 UDP SOF：真实 IG → viewhost（IG 列表 RTT）；平台收到的 SOF 来自虚 IG 入队后 `packSof`（§6.1）。

平台只有一条逻辑 IG 连接，**不能** 把 N 台真实 IG 的 SOF 都灌进去（多份帧号回显会打乱配对）。

写死：

- **master** = 真实 IG 的 `syncSystem.channelId == 0`（与常见 `viewhost_ig_main` / SofGated 主通道同一约定）。不配置、不改号。
- 平台只见 **一个** peer（中继这一台）。**数据面 UDP SOF 不转发**：真实 IG 的 SOF 只进 viewhost `HostSync`（IG 列表 RTT）；平台 UDP SOF 仅来自虚 IG 入队后 `packSof`（§6.1）。同一 `FrameCntr` 不得两份给平台。
- master 的 **TCP** 上报（`Resp` / 通知等，消息以 SOF 为分帧起点）转给平台：按 `0xffff` 切齐 → **回程 TCP 队列**（与下行队列分开）→ 整条 `sendAll`。按来源 IG 过滤，**不**按 PacketID 过滤。非 master 的上报 **丢弃**（IG 侧本不应回 Resp，这是兜底）。现网 IG→Host UDP 仅 SOF，故 master UDP 上报不转平台。
- 回程 TCP 切齐与下行相同三步（切齐 → 入队 → 整条 `sendAll`），消息起点是 SOF 不是 IGCtrl。同一 `recv` 里两条 SOF 消息必须分成两条，不得粘成一条再转。
- 把 peer 对上 `channelId==0`：**HELLO 是 CIGI 消息**（IG→Host TCP：`SOF` + `CigiIGMsgV4`），**不**回 TCP ACK。`IGMsg.MsgID = 1`（握手）；`Msg` 为两个十进制整数 `udpRecvPort channelId`（空格分隔）。`channelId` = 该 IG 的 `syncSystem.channelId`。Host 从 HELLO 学 `udpRecvPort` 与 `channelId` 写入 peer 表；`igSnapshot` **另含** `channelId`（`id` 仍是 Host `clientId`）。UDP_SYNC 仍按 HELLO 里的 `udpRecvPort` 对 peer、不读 `channelId`。禁止用「第一条连接」顶替。同一 listen 上后到的重复 `channelId` **拒绝**（关 TCP、不覆盖、不回 UDP_SYNC_ACK）。虚 IG 对平台的 HELLO 填 `0`（平台只见这一台，SofGated 认 0 即中继）。

### 6.4 启动顺序与谁 listen

写死顺序（Host 先 listen；**虚 IG 对平台 ready 必须晚于真实 IG 起齐**）：

1. **平台** `HostSync` 启动（`hostConfig` listen，与正式相同）。此时尚无 peer，`readyIgCount == 0`，不往中继发 CIGI。
2. **viewhost** 启动：本进程 `HostSync` listen 真实 IG（`hostConfig`）。**先不**对平台做虚 IG `connect`。
3. **普通 IG** 启动，`igConfig.target` 指向 viewhost，直到 viewhost `readyIgCount == relay.expectedIgCount`（起齐）。
4. 起齐之后 viewhost 才虚 IG `HELLO + UDP_SYNC` 连平台 → 平台 `readyIgCount == 1`，随后平台 `flush*` 才打到中继；此时 FIFO 扇出已有真实 ready peer。

起齐：`relay.expectedIgCount`（`relay.enabled` 时必填，整数 ≥1）。首版等齐，无超时、无强行开始。未齐则虚 IG 一直不 `connect`，平台一直 `readyIgCount == 0`。

两套端口不得混用：虚 IG 用 `relay.udpPortRecv` / 连平台 `tcpPort`；真实 IG 用 viewhost `hostConfig`。IG 现网 `connect` 本就会重试；步骤 1–3 的先后是意图。起齐之后才允许步骤 4，这条是硬门闩。

### 6.5 运行期：仅 master 掉线则平台 un-ready

启动门闩是 **全部起齐**（§6.4）。运行期平台 ready 跟 **master**，不跟侧通道：

- **master**（`channelId==0`）从 viewhost peer 表摘除：虚 IG **断开**对平台的连接，平台 `readyIgCount` 回到 0，停止 `flush*`。不再入队、不再 `packSof`；TCP 回程也停。
- **非 master** 掉线：虚 IG **保持**对平台 ready；下行 FIFO 继续扇出剩余 ready IG；该通道上报本来就会丢。数据面 IGCtrl 仍入队并 `packSof`。
- **不**做断线重连：master 回来后是否再 `connect`、要不要重新起齐，本文不写。
- 落地前提：可探测断线已摘除 peer（`readyIgCount` 下降）；HELLO 带 `channelId`（§6.3）才能认出 master。

## 7. 调试附加与 TCP IGCtrl 帧号

附加遵守链路矩阵：一次性 / 配置 / 请求走 **TCP**（天气等）；禁止塞进平台 UDP 眼点。

**不**把调试包接到平台消息末尾。viewhost 调现网 `outMsgWithIgCtrlTcp()` 组一条完整 TCP 消息，**`flushTcp` 入 Host TCP 发送 FIFO**（与切齐后的平台消息同一条），发送者挨个 `sendAll`。CCL 仍要求首包是 IGCtrl，命令面 `FrameCntr` **无业务含义**（现网 TCP 不回 SOF）；填 `1` 即可，`TimeStampValid = false`。禁止因此再发数据面 UDP IGCtrl，也禁止 `flush*` 绕过 FIFO 写 socket。

调试命令是事件触发（点一次入队一次），不跟帧循环走。

平台稍后下发同名天气：last-write-wins；中继 **不** 把附加写进 `HostDataManager`、也不回写平台。

**待完善**：同一瞬间（或短间隔）多条同类型 TCP（例如两份天气）暂时都生效，**谁后到谁覆盖**。这会造成平台权威表与 IG 实况分叉，首版不修。

## 8. 对 sync 库的切口

正式 / 本地调试 / 真模拟器调试：**同一套发送路径**（[状态同步设计.md](./多通道同步/状态同步设计.md) §7.2）。`flushTcp`/`flushUdp` 只 `PackageMsg` 入对应 FIFO，**不写 socket**。分帧器增加按方向的消息起点（IG 入站仍 `IGCtrl`；Host 入站 TCP 改为 `SOF` 边界）。

真模拟器调试额外需要：

1. **已打包 CIGI 消息入同一 FIFO**（中继切齐后的字节，不能走 `outMsgWithIgCtrl*` 重填头）。
2. 中继 TCP 两向都切齐入队：下行按 `IGCtrl` 入 Host TCP FIFO；回程按 `SOF` 入 **回程 FIFO**（发往平台，与下行分开）。无数据面帧循环；`HostDriver::update` 不得扇出眼点（会经 `flushUdp` 往 UDP FIFO 塞第二套数据面 IGCtrl）。
3. 回程只转发 `channelId==0` 的 **TCP** 上报（不按 PacketID 筛）。真实 IG 的 UDP SOF **不**转平台。
4. HELLO 为 CIGI `SOF`+`IGMsg`（本 IG `syncSystem.channelId` + `udpRecvPort`；虚 IG 对平台填 channelId `0`；**无 TCP ACK**）。Host peer 表存该号。实体去重同一键；首版重连回升**不广播**（[实体与运动控制设计.md](./多通道同步/实体与运动控制设计.md) §7）。
5. 虚 IG 对平台：复用现网 `HELLO + UDP_SYNC`（与 `IgSync::connect` 同款），**推迟到真实 IG 起齐之后**；**不必**改平台 `HostSync` 的 ready 门闩。运行期仅 master 摘除时虚 IG 断开（§6.5）。数据面：从虚 IG I/O 队列取原始字节入 Host FIFO；**禁止** `drainIncoming` 当唯一消费者。每条数据面 UDP IGCtrl **入队成功后** `packSof` 同号回平台（§6.1）。
6. 调试 TCP 走 `flushTcp` 入 Host TCP FIFO（独立完整消息），不接到平台报文上、不直接写 socket。

不改名 `IgSync`。不为中继再养一套用来 **解包重组出站** 的 CIGI IG Session（握手 ≠ shuttle）。虚 IG 回 SOF 用 `packSof` 读 IGCtrl 头，不经 `drainIncoming`。

## 9. 配置

**IG（engine）**：`igConfig.target*` 指向当前 Host——正式 = 平台，本地/真模拟器调试 = viewhost。未知键拒绝。

**平台 Host**：现有 `hostConfig`（`udpPortRecv` / `tcpPort`）。正式与真模拟器调试同一 listen，不因有无中继改端口。

**viewhost**：

| 键 | 含义 | 规则 |
| --- | --- | --- |
| （现有）`hostConfig` | 对真实 IG listen | 本地调试与中继相同 |
| `relay.enabled` | 真模拟器调试 | 缺省 false ≡ 本地调试（自己组数据面） |
| `relay.targetAddr` / `targetTcpPort` / `targetUdpPortRecv` | 平台 Host | `relay.enabled` 时必填（`HostTarget`） |
| `relay.udpPortRecv` | 虚 IG 本端 UDP（HELLO 上报；UDP_SYNC；收平台 IGCtrl；`packSof` 回平台） | 与 `hostConfig.udpPortRecv` 不同 |
| `relay.expectedIgCount` | 真实 IG 起齐台数 | `relay.enabled` 时必填，整数 ≥1；`readyIgCount` 达到该值才允许虚 IG `connect` |

master 不配：恒为 `channelId==0`。`relay.enabled=true` 时不得跑数据面 `HostDriver::update`。发送一律走 FIFO（正式 / 本地 / 中继相同），不经 UI 定时器直接 `sendAll`。
