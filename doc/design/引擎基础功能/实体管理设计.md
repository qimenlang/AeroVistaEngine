# 实体管理设计

面向引擎（IG / 单机渲染）的实体面：**实例与几何归引擎启动预建**，运行期只切显隐与写位姿。模型路径不进报文；Host 用 CIGI 驱动运行态的权威、组包与广播见 [实体与运动控制设计.md](../多通道同步/实体与运动控制设计.md)。

**一句话**：引擎启动按独立实体目录（`entities.json`）把全部模型 `loadScene` 建 `Entity`、挂 `vsg::Switch`（初始按 `initialEntityState` 定显隐）并一次性 `compile`，此后零编译；运行期 `Engine::onEntityCtrl` 只切 Switch + 套属性，`Engine::onEntityPose` 只写 transform。

## 1. 目标与范围

**做**：

| 项 | 说明 |
| --- | --- |
| 实体目录 | 独立 `entities.json`：`id → model` 映射；通道 JSON 只留 `entitiesFilePath` |
| 启动预建 | `initSceneFromEntities`：去重 `loadScene` → 建 `Entity` → 挂 Switch → 一次 compile（§8） |
| 运行时表 | `_entityMap[id]`；`Engine::findEntity` / `entitySize()` |
| 显隐 / 属性 | `onEntityCtrl` → `Entity::applyCtrl`：只切 Switch + 套属性，不加载、不编译 |
| 位姿写入 | `onEntityPose` → `Entity::setPoseLla`（`EntityID≠0`；线格式恒 Detach+LLA） |

**不做**（见 §11）：动画控制、`EntityType` 抽象层、父子挂载、完整 `Destroyed` 释放、加载失败上报 / 占位模型。`EntityID==0` ownship 眼点由 [lla位姿传输设计.md](../多通道同步/lla位姿传输设计.md) 覆盖。Host 权威表 / 广播 / 链路选择由 [实体与运动控制设计.md](../多通道同步/实体与运动控制设计.md) 覆盖。

**成功标准**：单机或 IG 启动后，目录内模型均成实例（失败 id 跳过）；`initialEntityState` 决定初始可见性；收到 `EntityCtrl` / `EntityPositionCtrl` 后显隐与位姿可观测变化，全程无运行时 `loadScene` / compile。

## 2. 背景与现状

2026-08 实体来源是 IG 配置预加载：遍历配置 `entities[]` → `loadScene` → 建 `Entity` → `_entityMap`，Host 对清单无感知，命令面只能摆放已存在实体。

**演进（2026-09 拍板）**：曾考虑 Host `EntityCtrl` 运行中动态 `loadScene`+挂 scene；经 VSG 机制查证（向已渲染场景图动态加子树需运行中 `CompileManager` + 帧边界挂载，代价高、有卡顿/黑模型风险）与显存估算，**最终定案**：IG 启动全量预建、实例初始按配置显隐、一次编译后**运行期零编译**。`EntityCtrl` 只控制 `vsg::Switch` mask。独立 `entities.json` 作为几何来源（方案 B）。

实现入口：`Engine::init` → `loadEntitiesFile` → `initSceneFromEntities` → `initSync` → `finishGraphicsAfterScene`（含 compile）。`Entity::assemble` 负责 transform + Switch 挂树。

## 3. 模块边界

**写死：实体「是否存在 / 几何 / GPU 资源」是引擎启动预建的既定事实；「运行期显隐与位姿」可由 Host 报文驱动，落地仍在引擎。**

| 层 | 归属 | 生命周期 | 协议可见 |
| --- | --- | --- | --- |
| 实体实例 + 几何 + GPU 资源（`_entityMap` + Switch 子树） | **引擎启动预建**（内容由共享目录定） | 进程生命周期；常驻显存 | ❌（存在性不广播；失败不上报） |
| 实体显隐（Switch mask）与位姿（transform） | **引擎执行**；有 Host 时运行态权威在 Host | 由 `EntityCtrl` / `EntityPositionCtrl` 驱动 | ✅ |

CIGI 标准依据（SISO-STD-013-2014 §6.1.38）：`Inactive/Standby` 时 *"the entity is loaded, but its tree is not enabled in the scene graph"*；`Active` 时 *"the entity's tree is enabled"*。本设计以 `vsg::Switch` mask 对应「tree not enabled / enabled」——与标准「预加载 + 即时激活」范式一致。刻意偏离：首版 `Destroyed` 降级为 `Standby`（§7 / §11）；不用 `EntityType` 定位几何（§4）。

有 Host 时同一实体在所有 IG 上的显示状态恒相同（多视口同一世界），推论与广播形态见 [实体与运动控制设计.md](../多通道同步/实体与运动控制设计.md) §3。无 Host 的单机渲染：启动后保持 `initialEntityState` 与配置 `pose`，不接收报文。

## 4. 实体目录

**写死：模型路径不经报文；Host 与 IG 各自加载同一份独立实体目录文件，`EntityID` 作映射键，`EntityType` 填 0 不使用。**

- **独立文件（2026-09 拍板，方案 B）**：`entities[]` 不再内嵌于各 IG 的 engine 通道 JSON，抽成单独的 `entities.json`（顶层 `{ "entities": [...] }`）。通道配置只留 `entitiesFilePath`。
- **同机 / 跨机一致（写死：人工确保）**：Host 与各 IG 读到的内容必须一致。同机可共指同一文件；跨机各放一份相同内容。**不引入**网络分发 / 启动互校验。
- **文件实体暂放 engine 侧（2026-09 拍板）**：物理文件暂放 `engine/resources/config/entities.json`（及场景专用 `entities_scene_*.json`）。**不迁移**到 sync 库或另设共享目录。
- IG 用完整 schema（含 `pose` 双轨）做 `id → path` 加载与初始位姿；Host 用**子集**建权威表（见 [实体与运动控制设计.md](../多通道同步/实体与运动控制设计.md) §3.2 / [位姿配置设计.md](../多通道同步/位姿配置设计.md)）。
- 解析入口：`loadEntitiesFile`（`EngineConfig.cpp`）。契约辅助可走 `AeroVistaConfig`；不抽「一份解析器服务 Host+IG 全字段」。

```jsonc
// entities.json（独立文件；Host 与 IG 读同一份，内容一致、人工确保）
{
  "entities": [
    { "id": 1, "name": "teapot_center", "model": "models/teapot.vsgt" },                          // initialEntityState 缺省 = Active
    { "id": 2, "name": "truck", "model": "models/truck.vsgt", "initialEntityState": "Standby" }
  ]
}
```

`pose` 双轨（`local` / `ellipsoid`）字段结构以 [位姿配置设计.md](../多通道同步/位姿配置设计.md) 为准；本文只定目录级契约与引擎消费规则。

**配置格式（写死：JSON）**：

- 顶层 `{ "entities": [...] }`（数组装键值对对象）。**不用对象当 map**（`{"1": {...}}`）。
- **id 唯一 fail-fast**：重复 `id` 即解析失败，**不静默覆盖**。
- **id 合法域（写死：`1..65535`）**：线格式 `EntityID` 为 uint16，`0` 保留 ownship（[lla位姿传输设计.md](../多通道同步/lla位姿传输设计.md)）。`id ≤ 0` 或 `id > 65535` 一律解析失败。
- **`model` 必填、非空**；`name` 可选，缺省 `basename(model)`（含扩展名）。`name` **不**作查找键，允许重复。
- **`initialEntityState` 字面值契约（写死）**：允许值**仅** `"Active"` / `"Standby"`（精确匹配 CIGI 枚举名，**大小写敏感**）；`"Destroyed"` / `"Remove"` 及一切其它值 → **解析失败**（不回退默认）。缺省 = `Active`。
- 未知键拒绝。空数组拒绝（`loadEntitiesFile` fail-fast）。
- 通道 JSON：`entitiesFilePath` 非空则必须成功解析该文件，失败则 `Engine::init` 失败；路径空则走单模型 `initSceneMode`（`config.model`）。

> **`EntityType=0` 语义偏离（写死）**：CIGI 标准里 type zero 是「无几何」哨兵。本设计 IG **完全忽略 `EntityType` 字段**、仅按 `id → path` 定位几何——实现时不得因 `EntityType==0` 而拒绝创建几何。若未来需要 DIS 互操作，再迁 EntityType 抽象层（§11）。

## 5. 运行时 Entity

与目录一项对应。C++ 为独立 `class Entity`（`engine/source/function/entity/Entity.h`），字段私有。引擎以 `id` 为主键维护 `unordered_map<int, Entity> _entityMap`；**禁止**用 `name` / `path` 作 Map 键。`Engine` 只提供 `findEntity(id)`（不在表为空）与 `entitySize()`。

```text
Entity {
  id: int                                 // ≡ JSON id；Map 主键
  name: string                            // ≡ JSON name；缺省已填 basename(model)
  path: string                            // ≡ JSON model
  ellipsoidModel: EllipsoidModel?         // 装配时从场景传入；非空 = LLA+当地 ENU YPR，空 = 本地笛卡尔
  positionOrLla: dvec3                    // 本地 xyz 或 LLA，由 ellipsoidModel 有无解释
  eulerYprDeg: dvec3
  node: vsg::Node                         // 模型子图（loadScene 结果；同 model 多实体共享一份，§8）
  transform: vsg::MatrixTransform         // 恒建；配置 pose（缺省字段补 0）填初始矩阵
  switch: vsg::Switch                     // transform 的父；显隐开关（Active=ON / Standby=OFF）
  alpha: uint8                            // 0 透明..255 不透明；缺省 255
  inheritAlpha / collisionDetectEn / smoothingEn: bool  // 报文属性存值；碰撞/平滑行为属 §11
}
```

| 成员 | 来源 / 职责 |
| --- | --- |
| `id` / `name` / `path` | 配置 |
| `ellipsoidModel` / `positionOrLla` / `eulerYprDeg` | 运行时只留**当前场景消费的一半**：有椭球则 LLA，否则本地笛卡尔（缺省补 0）。JSON `pose` 双轨在配置层，装配时按场景选半（[位姿配置设计.md](../多通道同步/位姿配置设计.md)） |
| `node` | 共享几何根 |
| `transform` | **恒建**；不存在「无 pose 不设位」 |
| `switch` | 每个实体一个，挂 `_scene`；compile 对其子树全部编译（含隐藏） |
| `alpha` 等 | 缺省 255 / false；`EntityCtrl` 无条件套用（§9） |

公开查询：`visible()` / `alpha()` / `node()` / `transform()` / `samplePose()` / `name()`。写入：`assemble`（启动）、`applyCtrl`（显隐+属性）、`setPoseLla`（摆放）。

## 6. 配置与运行态职责

**配置只放集成期静态确定的东西；运行时要变的走报文（有 Host）或保持启动初值（单机）。**

| 信息 | 放哪 | 理由 |
| --- | --- | --- |
| `id` / `model` | 配置（必填） | 映射主键与几何路径 |
| `name` | 配置（可选） | 显示名 |
| `initialEntityState` | 配置（可选，默认 `Active`） | **启动初值**；运行态显隐由报文驱动 |
| 初始位姿 `pose` | 配置（可选默认） | 启动预建套一次；运行期 `EntityPositionCtrl` 覆盖，不回写文件 |
| 默认 `alpha` | 配置（可选；首版未配则 255） | 静态外观；`EntityCtrl` 可动态覆盖 |
| 运行时显隐 / 位姿 / 属性 | **报文（不配）** | `Standby↔Active`、摆放、Alpha 等 |

> **`initialEntityState`（写死：双侧消费）**：共享配置上的启动初值。IG 预建后按它设 Switch mask（单机即最终画面；同步 IG 在收到首个 `EntityCtrl` 前的短窗内按配置显示）。Host 建权威表也读它（[实体与运动控制设计.md](../多通道同步/实体与运动控制设计.md) §6/§7）。运行期不再回读配置。
>
> **配置 `pose` 只在启动预建时套用一次（写死）**：缺省字段补 0，实体恒有初始位置。`Standby↔Active` **不重套** pose，否则会把已摆位姿弹回配置值。
>
> **`alpha` 配置字段**：当前 `EntityConfig` 尚无 `alpha`；首版只走 `EntityCtrl` 报文，缺省 CIGI 不透明 255。

## 7. 显示状态机

**实例在启动时全部预建（§8），`EntityState` 只表达显隐两态**：`Active` = Switch ON，`Standby` = Switch OFF。无「不存在」态（除启动加载失败外）。`Destroyed` 首版降级为 `Standby`：

```text
                    ┌──────────────┐
   ── 启动预建 ────▶│   Standby    │  (实例已建、已编译；Switch OFF)
                    │  (隐藏)       │
                    └──────┬───────┘
                           │ EntityCtrl(Active)   → Switch ON
              EntityCtrl(Standby) ←────────────────┘ Switch OFF
     Active 或 Standby 收到 EntityCtrl(Destroyed) → 首版降级为 Standby
```

| 状态 | 含义 | `_entityMap` | Switch mask |
| --- | --- | --- | --- |
| `Standby` | 实例已建、已编译，**隐藏** | 有 | OFF |
| `Active` | 显示 | 有 | ON |

> **`Destroyed` 首版降级为 `Standby`（写死）**：协议上 Destroyed = 释放几何并可重建；本设计运行期零编译，真正释放需运行中 `loadScene`+`compile`。首版收到 `EntityState=Destroyed` **一律按 Standby**（Switch OFF、保留实例与 GPU 资源）。UI 不暴露销毁按钮。完整销毁/重建见 §11。
>
> **`Remove` = `Destroyed`（历史别名，写死）**：`EntityStateGrp` 中 `Remove=2` 与 `Destroyed=2` 同值；实现统一按 Destroyed 处理（代码：非 `Active` 即 Switch OFF）。

**转换（写死，首版）**：

| 转换 | 触发 | 首版 |
| --- | --- | --- |
| （启动）→ `Standby` | 预建且 `initialEntityState=Standby` | ✅ |
| （启动）→ `Active` | 预建且 `initialEntityState=Active`/缺省 | ✅ |
| `Standby` → `Active` | `EntityCtrl(Active)` | ✅ |
| `Active` → `Standby` | `EntityCtrl(Standby)` | ✅ |
| `Active`/`Standby` → `Destroyed` | `EntityCtrl(Destroyed)` → **降级为 Standby** | ✅（偏离，§11） |

- **`Standby`**：CIGI「loaded, but tree not enabled」。不可见、不参与渲染录制；几何常驻。隐藏子树不计入 `computeBound`（默认 `overrideMask` 跳过 Switch OFF）——全隐藏且无 `camera.pose` 时默认相机走 [位姿配置设计.md](../多通道同步/位姿配置设计.md) §4 fallback。
- **`Active`**：可见。transform 启动即填充（配置 pose / 默认 0），**无激活位置检查**；`EntityCtrl(Active)` 直接置显。

### 7.1 加载失败（首版不处理、不上报）

某实体 `loadScene` / 编译失败 → 不入 `_entityMap`，仅 IG 侧 `[WARN]` / `[ERROR]`；**不建实例、不上报 Host**。后续对该 id 的 `EntityCtrl` / `EntityPositionCtrl` 无效（查表空则忽略）。接受此 per-IG 画面差异。后续占位模型见 §11。

就绪语义（连接层 ready、与模型加载无关）见 [实体与运动控制设计.md](../多通道同步/实体与运动控制设计.md) §7.1。引擎约束：场景图预建必须先于 `initSync`，compile 在 `finishGraphicsAfterScene`（§8），保证首轮 `EntityCtrl` 能命中已建全的 `_entityMap`。

## 8. 启动全量预建

**写死：实体几何（加载 + GPU 编译）在启动阶段完成、此后常驻；运行期只切 Switch。**

标准允许初始化期预热几何（SISO-STD-013 §6.1.38 / §4.7 cached models may remain）。本设计比「缓存几何、命令再实例化」更进一步：**实例与场景树挂载也在启动完成**。

**启动顺序（写死）**：

```text
Engine::init()
  applyConfig → resetGraphics
  entitiesFilePath 非空 → loadEntitiesFile（失败则 init 失败）
  列表非空 → initSceneFromEntities()     // 装配场景图
    _scene + 椭球注入
    按 model 路径去重 loadScene（共享几何）
    逐实体 Entity::assemble：
      几何 = 共享 node
      transform 恒建，初始矩阵 = 配置 pose（缺省补 0）
      Switch（含 transform）→ 挂 _scene
      初始 mask = (initialEntityState == Standby) ? OFF : ON
      _entityMap[id] = Entity
    单模型失败：跳过该 id，不阻塞整批
  列表空或未配目录 → initSceneMode(config.model)   // 单模型路径
  ↓
  initSync()                // _entityMap 已建全
  ↓
  finishGraphicsAfterScene  // 一次性 _viewer->compile()；含隐藏实体
  ↓ 进入帧循环
```

- **transform 恒建、恒有初始位置（写死）**：`pose` 可整体或缺字段缺省，一律补 0。实体总有初始位置（原点 / 赤道海面，视坐标系）。
- **共享几何（写死）**：同 `model` 只 `loadScene` + compile 一份；各实体独立 `MatrixTransform`+`Switch`。`Entity::node()` 指针相同。这是全量预编译显存可行的前提。
- **隐藏子树不进 AABB（写死）**：Switch OFF 不贡献 `computeBound`；全 `Standby` 且无 `camera.pose` → 默认相机 fallback（[位姿配置设计.md](../多通道同步/位姿配置设计.md) §4）。
- **预加载是 IG 本地细节，不改协议**；Host 只按权威表发报文。

位姿矩阵写法（Local `T*R` / Ellipsoid `LocalToWorld*R_enu`）见 [位姿配置设计.md](../多通道同步/位姿配置设计.md) §3。椭球注入判据见 [lla位姿传输设计.md](../多通道同步/lla位姿传输设计.md) §2。

## 9. 运行期处理

`IgSync` 命令面订阅 `CigiEntityCtrlV4` / `CigiEntityPositionCtrlV4`，转发 `Engine::onEntityCtrl` / `onEntityPose`（与测试注入同层）。**回调不建实例、不加载、不编译**。

```text
onEntityCtrl(ctrl):
  entity = findEntity(ctrl.EntityID)
  if 无:
    记 WARN，return          // 启动失败 / 未映射 id（§7.1）
  entity.applyCtrl(ctrl)

Entity::applyCtrl:
  Switch ON  当且仅当 EntityState == Active
  否则 Switch OFF            // Standby / Destroyed / Remove 同降级
  无条件套用 Alpha / InheritAlpha / CollisionDetectEn / SmoothingEn
  不重套配置 pose
```

> **属性无条件套用（写死）**：已 Active 只调 alpha 时，第一段显隐 no-op、第二段仍生效。`CollisionDetectEn` / `SmoothingEn` 仅存值，行为属 §11。
>
> **`setPoseLla`**：实体恒在表内则更新 transform（Active 实时可见，Standby 更新语义位姿，再 Active 以其为准）。不在表（加载失败 / 未映射）静默忽略。
>
> **坐标系**：同步只 LLA，命令实体恒 `Detach`+LLA（[lla位姿传输设计.md](../多通道同步/lla位姿传输设计.md) §2；报文字段见 [实体与运动控制设计.md](../多通道同步/实体与运动控制设计.md) §4.2）。`onEntityPose` 对 `EntityID==0` 直接 return（眼点走 `CameraDriver`）。
>
> 动画：`onAnimationCtrl` 为首版之外（§11）；现仅报文自检订阅。

## 10. 验收要点

> 对齐 [测试用例书写规范.md](../../测试用例书写规范.md)。**阶段 ②** 启动装配（不连 Host、不发 `EntityCtrl`）；**阶段 ③** 报文显隐与属性（测试可直接调 `onEntityCtrl` / `onEntityPose`，与真包 E2E 分场景）。Host 权威表 / 广播码 `ENT-04-*`、`ENT-link` 见 [实体与运动控制设计.md](../多通道同步/实体与运动控制设计.md) §11。
>
> **验收码（试点）**：一经分配不改号、不复用、不重排。Catch2 挂同名 tag。未写用例的码表示尚未落地，不是缺号。
