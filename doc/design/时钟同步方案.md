# 时钟同步方案

面向本项目 **1 Host + 多 IG（约 10 通道）** 的时钟同步初步方案。通用时钟同步知识见 [时钟同步总结.md](../notes/时钟同步总结.md)；同步模块整体设计见 [多通道同步模块设计.md](./多通道同步模块设计.md)。

**初步方案一句话**：IG 把 Host 下发的 `simTimeMs` 当「基准时间戳」，内部统一以 **`uint64` 微秒（`simTimeUs`）** 单调累计（相位展开 + 消费时本地流逝补偿：`simTimeUs = lastSimTimeUs + (nowUs - lastReceivedAtUs)`），补偿后 IG 间差异只剩网络延迟差；收不到时用同一机制外推并设**时间上限**冻结，恢复后**直接跳变**到新基准；**不引入 PTP/NTP**，PTP 留作未来延迟标定的扩展项。

## 1. 范围与目标


| 纳入初步                            | 暂不纳入                     |
| ------------------------------- | ------------------------ |
| IG 逐帧消费 Host `simTimeMs`（帧内权威值） | PTP / NTP 时钟对齐           |
| **本地单调时钟补偿流逝时长**（收到包时也补偿）       | 延迟标定 / 补偿                |
| **内部统一 `uint64` 微秒计时（`simTimeUs`）** | Genlock / Framelock 硬件同步 |
| 外推 + **时间上限**冻结，恢复后直接跳变            | host 独立进程后的上行时间基准        |


**目标**：各 IG 渲染同一帧时，计算得到的仿真时间**一致到可接受阈值**（阈值待标定，通常 ≤ 半帧）。不追求各 IG 本地时钟对齐。

**关键认知**：仿真时间一致性**不是**靠「收到包直接取包内值」保证——那会留下「最新时间戳新鲜度差」（最多一个发送周期 + 丢包差异）。正确做法是把时间戳当**基准**，用本地单调时钟补偿「距收到它的流逝时长」。补偿后一致性只受「网络延迟差」影响。

## 2. 方案总览

```text
Host: 高频发送 IGCtrl，内嵌 simTimeMs（+ frameCntr）→ 扇出全体 ready IG
IG 每帧（逻辑 / 渲染计算时）:
  仿真时间(us) = lastSimTimeUs + (nowUs - lastReceivedAtUs)   // 核心公式，均用 vsg::clock（steady）

  lastSimTimeUs     = 最近一次收到 Host 包，经相位展开得到的 64 位单调累计（us）
  lastReceivedAtUs  = 收到该包时的本机单调时钟（us）
  nowUs             = 当前本机单调时钟（us）

  收到 Host 包 → 相位展开更新 lastSimTimeUs / lastReceivedAtUs（按 frameCntr 取新）
  超过冻结条件 → 冻结（见 §4.3）
```

- **核心机制：基准时间戳 + 本地流逝补偿**。不管本帧收到几个包、收到多新，都在「最近基准」上叠加「自收到起流逝的时长」。内部统一用 **us（`uint64`）** 单调累计，消费时才换算成 ms / 秒（见 §4.0）。
- **为什么不能直接用「包内最新值」**：180Hz 发送时，两个 IG 在同一渲染帧内可用的"最新基准"可能相差一个发送周期（如 IG1 只收到 0ms、IG2 收到 11.11ms），直接取值差 ~11ms；补偿后都收敛到「收到时刻 + 流逝」，差异只剩网络延迟差。
- **外推是同一机制的自然延伸**：没收到新包时 `nowUs - lastReceivedAtUs` 越来越大，公式自动外推；只是多了上限与冻结。
- **冻结**：外推达到时间上限后不再递增，等恢复；恢复后**直接跳变**到 Host 最新值（见 §4.4）。**注意：上式是通用公式，冻结期间不成立**——冻结时消费返回 `lastSimTimeUs`（不加流逝项），见 §4.3。

## 3. 数据面：时间戳的传输

现状链路（CIGI V4 数据面，见 [多通道同步模块设计.md](./多通道同步模块设计.md) §8）：


| 报文                        | 字段                                                         | 当前处理                 |
| ------------------------- | ---------------------------------------------------------- | -------------------- |
| Host→IG `IgCtrlMsg`（CIGI） | `simTimeMs`（double ms）→ `IGCtrl.TimeStamp`（uint32，10µs 步进） | Host 填值；**IG 消费待实现（§4）** |
| Host→IG `IgCtrlMsg`（CIGI） | `frameCntr`                                                | IG 裁决旧包丢弃            |


```text
// engine/source/engine.cpp — Engine::postFrame 尾部（方案 B，已实现）
// 模拟时间基于 steady_clock 连续推进：simTimeMs = _simStartMs + (steady_clock::now() - _simStartTime)
if (_synchronSystem)
    _synchronSystem->postFrame(*this, _simStartMs + elapsedMs);
```

> 换算（已实现，`CigiWire.h`）：Host 侧 `simTimeMsToTimeStamp`，ms → 10µs ticks。**IG 侧不走直接反解**（`timeStamp/100` 会撞回绕），而是用 §3 相位展开把 `timeStamp` 累计成 64 位 `simTimeUs`。

**TimeStamp 回绕（uint32，≈11.9h）——接收端相位展开**：

CIGI `IGCtrl.TimeStamp` 为 `uint32`、单位 10µs，最大 `0xffffffff` ≈ **11.9 小时**。超限后若自然溢出会**回绕归零**（模拟时间瞬间回退 ~11.9h，补偿公式与乱序裁决都会错乱）；当前 `simTimeMsToTimeStamp` 是**饱和**（停在 `0xffffffff`，IG 反解停住，也是问题）——**第一版将改为自然回绕（见下）**。

> **Host 侧决策（写死）**：**第一版直接实现跨 12h 自然回绕**——`simTimeMsToTimeStamp` 改为在超限处**取模回绕**（`static_cast<uint32_t>(ticks)` 自然溢出，而非饱和到 `0xffffffff`）。理由：
>
> | Host 侧行为 | 超 11.9h 后 IG 表现 |
> | --- | --- |
> | 保留**饱和** | Host 恒发 `0xffffffff` → IG 相位展开 `delta=0` → `extendedTime` 停住 → 模拟时间停住（相位展开形同虚设，§6 回绕用例在真实链路不触发） |
> | 改为**自然回绕** | Host 归零重发 → IG 相位展开平滑跨过 → 模拟时间连续（本方案的前提） |
>
> **第一版即按自然回绕实现，不做「先饱和、后改回绕」的两阶段过渡**。该改动只影响 `simTimeMsToTimeStamp`（`CigiWire.h`）：去掉饱和分支、依赖 `uint32` 自然溢出即可；IG 侧相位展开（§3）即为其配套。

**选定方案：接收端相位展开（phase unwrap）**——线上仍是 CIGI 标准 `uint32`，**不新增高 32 位字段、不破坏 CIGI 兼容**；IG 本地维护 64 位单调时间（`uint64` 微秒），用模减法平滑跨过回绕点：

```text
// IG 本地维护：extendedTime（uint64，单位 10µs tick）、lastRaw（uint32）
首次收到包（会话开始 / 重连）：
  lastRaw = raw
  extendedTime = raw            // 保留 Host 绝对 tick 基准，不从 0 起
每次收到后续包：
  delta = (uint32)(raw - lastRaw)   // 模 2^32 无符号减法，回绕处仍给出正向增量
  extendedTime += delta             // 单位：10µs tick
  lastRaw = raw

lastSimTimeUs = extendedTime * 10   // tick → 微秒（us）；uint64 下约 5.8e15 年才回绕，等于永无此问题
```

- 正常递增：`delta` = 实际增量，`extendedTime` 单调前进；
- **回绕瞬间**：`raw` 从大跳小，模减法仍算出正确正向增量 → `extendedTime` 平滑跨过，**无跳变**；
- **乱序兜底**：UDP 乱序时 `raw < lastRaw` 但非回绕，模减法会算出巨大 delta——靠既有 `frameCntr` 裁决（旧包整包丢弃）先挡掉乱序包，到不了展开逻辑；时间戳只做「单调时长累计」，帧的新鲜度/乱序仍由 `frameCntr` 裁决，两者分工不混。
- **单位衔接**：相位展开在**收到包时**完成，产出 `lastSimTimeUs`（us）；补偿公式与消费统一用 **us**，仅在消费边界换算成 ms / 秒（见 §4.0）。
- **为什么首包不归零（关键）**：Host `simTimeMs` 是绝对模拟时间，`TimeStamp = simTimeMs×100`。若 `extendedTime` 从 0 起，`lastSimTimeUs` 变成「相对接入时刻的增量」，各 IG 接入时刻不同 → 系统性时间偏移，破坏一致性。首包 `extendedTime = raw` 保留 Host 绝对基准，`lastSimTimeUs` 从一开始就等于 Host 发送时刻的 us。

**边界**：

- **重置时机以「连接会话」为界**：TCP 断开并重连 = 新会话 → `lastRaw` 与 `extendedTime` 均以重连后首个包的 `raw` 初始化（保留 Host 绝对基准，不从 0 起）；同一会话（TCP 持续存活）内才做连续相位展开。
- **Host 重启的兜底**：Host 崩溃重启后 `simTimeMs` 归零、`raw` 从小值重新开始，但若 UDP 数据面在 TCP 重连完成前先到，`lastRaw` 仍是旧会话大值 → 模减法会误判为「回绕」、让 `extendedTime` 猛增约 11.9h。**处理：以会话生命周期（TCP 断开/重连）作为相位展开状态的唯一重置信号**；若实现检测到 `raw` 大幅回退但连接未断，应先判定连接异常（走断线/重连流程）再重置，勿当正常回绕累加。

## 4. IG 侧消费逻辑

### 4.0 核心公式：基准时间戳 + 本地流逝补偿（统一 us）

**单位分工（写死）**：

```text
Host 侧（生产）：  double ms      —— Engine::_simStartMs + steady_clock 流逝、HostSync::update、CigiWire::packHostFrame 入参
                        │  ×100
线上 CIGI：        uint32 10µs    —— IGCtrl.TimeStamp（唯一在线单位）
                        │  ÷100
IG 侧（消费）：    uint64 us      —— simTimeUs（相位展开 + 补偿 + 外推，IG 内部专用）
                        │  ÷1000
Engine 消费：      double ms      —— IG 把 simTimeUs 转成 ms 交给 Engine
```

- **Engine 内部统一 ms**（现状即 ms，不改）；**IG 时间戳逻辑内部统一 us**（相位展开/补偿/外推需整数微秒精度与 uint64 单调性）；
- IG 向 Engine 提供时间戳时**换算成 ms（double）**：`simTimeMs = static_cast<double>(simTimeUs) / 1000.0`（保留小数，防 60fps 下整数除法丢 0.67ms/帧累积漂移）；给 shader / 物理用秒：`simTimeSec = static_cast<double>(simTimeUs) / 1e6`；
- **us 不下沉到 Engine**——Engine 消费侧始终是 ms。

```text
simTimeUs(now) = lastSimTimeUs + (nowUs - lastReceivedAtUs)   // 均用 vsg::clock（steady），单位 us
```

| 量                 | 含义                                   | 更新时机                   |
| ----------------- | ------------------------------------ | ---------------------- |
| `lastSimTimeUs`   | 最近一次收到 Host 包，经相位展开后的 64 位单调累计（us） | 收到新包：相位展开后更新（按 `frameCntr` 取新） |
| `lastReceivedAtUs`| 收到该包时的本机单调时钟（us）                  | 与 `lastSimTimeUs` 同包更新 |
| `nowUs`           | 当前本机单调时钟（us）                       | 每次计算时取                 |

**两条链（写死顺序）**：

```text
收到 Host 包：
  frameCntr 裁决取新（§4.1）→ 相位展开得 lastSimTimeUs（§3）→ 记录 lastReceivedAtUs
消费（逻辑 / 渲染计算）：
  simTimeUs = lastSimTimeUs + (nowUs - lastReceivedAtUs)   // 补偿流逝
  需要时换算：simTimeMs = (double)simTimeUs / 1000.0；simTimeSec = (double)simTimeUs / 1e6（给 shader / 物理）
```

- **内部统一 us（`uint64`）**，只在**消费边界**换算成 ms / 秒；禁止在内部到处转单位。
- shader / 物理模拟惯例用**秒**：传 `simTimeSec`（`us / 1e6`）；逻辑 / 日志用 ms。

**动机**（场景：Host 180Hz 发、IG 60fps、有丢包）：IG1 帧内只收到 0ms、IG2 收到 0/5.56/11.11ms。直接取"最新值"→ IG1=0、IG2=11.11，差 ~11ms；补偿后 IG1=0+16.67、IG2=11.11+5.56，都 ≈16.67，一致。

**单位换算（实现注意）**：`nowUs` / `lastReceivedAtUs` 由 `vsg::clock::now()` 转 us：`duration_cast<std::chrono::microseconds>(nowTime - lastReceivedTime).count()`（单调时钟时刻，命名可自定，单位统一 us）。

### 4.1 收到 Host 包

- 按 `frameCntr` 裁决取新：**`frameCntr >= 已处理帧号` 即接受**（现状 `IgSync::update` 是「严格小于丢弃」，同帧号继续处理）。**旧帧整包丢弃（含时间戳）**。
- **已知限制：`FrameCntr` 同为 `uint32` 也会回绕**。60fps 下 `2^32` 帧 ≈ **2.3 年**；回绕瞬间裸比较 `>=` 会把新帧误判为旧包丢弃。周期远超单次任务，**第一版不处理**（记录为已知限制；如需支撑跨 2 年连续运行，后续对裁决也做相位展开式处理）。
- 更新 `_lastFrameCntr`、`_lastSimTimeUs`（相位展开，§3）、`_lastReceivedAtUs = vsg::clock::now()` 转 us。
- **同 frameCntr 的重复包同样刷新基准**：方案 C 高频重发不递增 frameCntr，同一渲染帧内多次重发必须让 `lastSimTimeUs` / `lastReceivedAtUs` 取最后一次收到的值（即「取最新基准」），否则基准停在首包、补偿失效。实现时用 `>=` 接受，勿写成「大于才更新」。
- **基准在收到即更新**，不只在 preFrame 取一次——帧内任何时刻消费都基于最新基准补偿流逝。

### 4.2 未收到 Host 包（同一公式自动外推）

```text
本帧仿真时间(us) = lastSimTimeUs + (nowUs - lastReceivedAtUs)   // 与收到时是同一个公式
```

- 仅当「已收到过至少一帧」才有意义；从未收到 → 无仿真时间可用（由上层策略决定，如保持初始值）。
- **必须用单调时钟**（`steady_clock`）测流逝时长，禁止 `system_clock`（NTP 校正回跳会让外推倒退）。

### 4.3 外推上限与冻结

| 参数                  | 含义          | 初步建议          |
| ------------------- | ----------- | ------------- |
| `extrapolateTimeoutMs` | 外推时间上限（超时冻结） | 待标定（如 100~200ms） |

**只保留时间上限一个参数**（不设帧数上限——帧数依赖 IG 帧率、语义不直接）；超过上限：**冻结**。

**冻结判据（写死）**：从最后收到包的时刻起算，`nowUs - lastReceivedAtUs > extrapolateTimeoutMs * 1000` 触发冻结（`extrapolateTimeoutMs` 单位 ms，判据左边是 us，须换算成 us 再比）。

**冻结的实现语义（写死）**：置冻结标志；冻结期间消费公式**改为 `simTimeUs = lastSimTimeUs`**（不再加 `(nowUs - lastReceivedAtUs)` 流逝项，否则 `nowUs` 增长会让结果继续递增，与「冻结」矛盾）。**冻结期间收到任何合法新包（按 `frameCntr` 取新）都清除冻结标志并正常更新基准**（`lastSimTimeUs` / `lastReceivedAtUs`），与是否冻结无关——恢复后的补偿用新基准。

**实现注意（消费函数形态，防漏判冻结分支）**：同一消费函数会同时被正常路径与冻结路径调用，必须显式判断冻结标志，勿只写通用公式：

```cpp
uint64_t simTimeUs() const {
    if (frozen)
        return lastSimTimeUs;                          // 冻结：不加流逝项，返回值恒定
    return lastSimTimeUs + (nowUs - lastReceivedAtUs); // 正常 / 外推：补偿流逝
}
```

**为什么必须有上限**：长时间没包意味着网络故障或 Host 挂了；此时眼点同样过期（画面停在旧位姿），光把时间推准无意义。

### 4.4 恢复策略

- 重新收到包：`simTimeUs` **直接跳变**到新基准值（相位展开后的 `lastSimTimeUs`），简单可预期。
- **不做限幅 / 平滑收敛**——冻结期间本来就没有可靠时间信息，平滑反而引入不确定的中间态；跳变幅度 = 冻结时长，由 `extrapolateTimeoutMs` 控制在可接受范围（冻结上限已限，跳变幅度有界）。

### 4.5 残余误差与后续增强

补偿后，两个 IG 的仿真时间差收敛到：

```text
IG 间模拟时间差 ≈ d₁ - d₂   （两 IG 到 Host 的链路延迟差，单位 ms / us 均成立）
```

- LAN 内延迟差通常在亚毫秒 ~1ms 级，相对 16.67ms 帧周期可接受。
- 若需进一步压：**延迟标定**（每个 IG 测自己的 `d_i`，在补偿公式中加上以对齐 Host 当前时刻，见 §5.3）与**多时间戳回归**（拟合 skew），见 §5.3 / §5.4。

## 5. 发送侧：时间戳实时化（可选）

现状：`Engine::postFrame` 已实现**方案 B**——模拟时间基于 `steady_clock` 连续推进（`simTimeMs = _simStartMs + (steady_clock::now() - _simStartTime)`），渲染卡顿时时间戳跟上真实流逝（不再固定步进）。

| 方案              | 做法                                                           | 收益                | 代价                               |
| --------------- | ------------------------------------------------------------ | ----------------- | -------------------------------- |
| **A. 固定步长（已废弃）** | `+= 1000/60`                                                 | 实现最简单            | 渲染卡顿时时间戳滞后；IG 外推误差被 host 帧节奏波动放大 |
| **B. 单调时钟实时推进（已实现）** | `simTimeMs = simStartMs + (now - startTime)`（`steady_clock`） | 时间戳=当前时刻，新鲜度最好 | 已实现于 `Engine::postFrame` |
| **C. 独立发送线程**   | 按固定间隔（如 100~200Hz）快照当前时间+最近眼点发帧                              | 渲染卡顿不影响数据新鲜度；天然冗余 | 线程安全；frameCntr/眼点绑定需钉死（见下）       |

**建议**：B 已实现（零架构风险）；若丢包仍明显再上 C。

### 5.1 若做独立发送线程（方案 C），必须先钉死 4 点

1. **眼点与帧号绑定**：眼点是渲染线程每帧采样的；发送线程只能发"实时时间戳 + 最近一次采样眼点"。高频包内眼点是旧值，接受该语义或加锁采样（不推荐）。
2. **frameCntr 语义**：推荐高频重发**不递增** frameCntr（同一渲染帧内多次重发，只更新时间戳），否则 IG 的"严格小于丢弃"会把重发误判为新帧，眼点与帧号绑定断裂。
3. **SOF 回显节流**：IG 每处理一条 IGCtrl 回一条 SOF，高频发送会让计数/统计失真；应在"新 frameCntr"或周期性才回。
4. **线程安全**：`HostSync::update` 当前在渲染线程无锁调用，独立线程需加锁或改队列。

### 5.2 IG 一帧收到多包

现状 `IgSync::update` 已 drain 处理所有积压 datagram、后包覆盖先包（UDP 单 socket FIFO）——**"一帧取最新"天然成立**，无需改动。

### 5.3 延迟标定（概念）

**要解决的问题**：补偿公式把「收到时刻」当「Host 发出时刻」，实际两者差一个**链路延迟 d**。无标定时各 IG 补偿结果差 `d₁-d₂`（§4.5）；标定后统一对齐 **Host 当前时刻**，消除该差异。

**推导**：Host 在 `t_send` 发包（包内时间 `S(t_send)`），IG 在 `t_recv = t_send + d` 收到。IG 无标定的补偿值：

```text
S(t_send) + (now - t_recv) = S(t_send) + now - t_send - d = S(now) - d
```

即无标定时 IG 算出的结果比 Host 当前模拟时间少一个 d。要对齐 Host 当前时刻 `S(now)`，应 **加上** 各自的 `d_i`：

```text
simTimeUs(now) = lastSimTimeUs + (nowUs - lastReceivedAtUs) + d_i_us   // 对齐 Host 当前时刻，单位 us
```

> **语义注意**：标定后 IG 的模拟时间对齐 Host 当前时刻，而数据（眼点 / 状态）仍是 d 前发出的——时间超前于数据 d（LAN 内 <1ms，可接受）。若目标改为「对齐数据发送时刻」，则直接用包内 `lastSimTimeUs`（不补偿），所有 IG 对同一包完全一致，但帧内模拟时间不再连续推进（对象动画 / 粒子每帧跳变）。两种目标自洽，**默认选对齐 Host 当前时刻（`+d_i`）**，需在实现前固定。

**测量方式**（握手面已有 TCP/UDP 双平面）：

1. **往返探测（RTT/2）**：IG 向 Host 发一条带时间戳的探测，Host 立即回；IG 记录 `t0`（发）、`t3`（收），估算 `d ≈ (t3 - t0)/2`。前提是上下行对称。
2. **单向标定**：若 host 本地时钟可由 PTP/NTP 对齐，则 `d = t_receive - t_send` 直接算出（需时间同步，本项目未做，属扩展）。

**注意**：d 在 LAN 内通常 <1ms，对 16.67ms 帧周期影响小；是否值得做取决于目标精度。这与 PTP 的「延迟测量」是同一类，但 PTP 测的是时钟同步报文延迟，这里标定的是业务报文延迟。

### 5.4 多时间戳回归（概念）

**要解决的问题**：补偿公式假设「IG 本地流逝 = Host 时间流逝」，但 IG 晶振有 skew（±100ppm）。短窗口可忽略，长外推会累积（1 秒 ≈ 100µs、10 秒 ≈ 1ms）。

**做法**：高频发送时 IG 每帧能收到多个时间戳，把它们拟合一条直线：

```text
simTime ≈ a × τ + b        // τ = 本机单调时刻
```

- **b（截距）**：Host 时间与 IG 时钟的基准相位 → 提供比"最新单点"更稳的基准。
- **a（斜率 ≈ 1）**：等效的时钟频率比 → 补偿 IG 晶振 skew，长外推不漂。

**本质**：这是**轻量软件时钟同步**（软件版 PTP 雏形）——不依赖硬件时间戳，只用「Host 时间戳 × IG 单调时刻」数据点做最小二乘拟合。实现成本低（滑动窗口存最近 N 个点），是「当前方案」与「PTP」之间的折中档。

**与本方案关系**：初步用 §4.0 的补偿公式即可；若外推窗口拉长或 IG 帧率与 Host 差异大，再升级为回归（或延迟标定）。
