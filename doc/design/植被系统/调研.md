# 植被系统调研

外部公开资料整理，不是设计契约，也不定本项目方案。日期：2026-10-27。

问题：飞行模拟和训练视景里，植被谁做得好，好在哪一层。UE5 的飞行视景用法见 §7.1，与功能目标的对照见 §13。

## 1. 结论

按公开材料能核对到的程度，分三档。

| 档 | 谁 | 好在哪 | 公开材料能核对到什么 |
| --- | --- | --- | --- |
| 全球飞行视景 | Microsoft Flight Simulator 2020 / 2024（Asobo） | 整颗地球、任意高度；树的位置来自遥感，颜色贴航拍，远处用八面体 impostor 撑住百万级实例 | GDC 2022 演讲幻灯片 + 2024 SDK。近景「每一棵树」是产品访谈，不是工程规格 |
| 军事训练视景 | VBS4（Bohemia Interactive Simulations） | 程序化铺全球，按生物群系和土地覆盖出树和贴地草；草要参与隐蔽，不能只是贴图 | 厂商对比片、版本说明、地理数据合作新闻。绘制实现未公开到 MSFS 那个粒度 |
| 树木资产与森林运行时 | SpeedTree（现属 Unity） | 树木建模、风、LOD、公告牌，以及面向自有引擎的 Runtime SDK。游戏里看起来最好的树，多数是这套资产做出来的 | Runtime SDK 10 手册、Unity 收购说明。它不是飞行视景，也不负责「地球上哪里有林」 |

其余飞行模拟有完整植被管线，但公开效果和做法都停在更早一档：X-Plane 12 是近处三维网格、远处公告牌；Prepar3D 是地类标注里的植被多边形；FlightGear 是十字交叉面片。它们说明行业基线，不是当前上限。

近距离、高密度的几何上限在游戏引擎，不在飞行产品：Unreal Engine 5 的 Nanite Foliage（官方标成实验特性），以及《对马岛之魂》公开过的程序化草。它们解决的是「走进树林」，不是「全球铺树」。

摄影测量网格（MSFS 的 TIN、Google Photorealistic 3D Tiles）里那些树冠不是植被系统。树被烘进三角网，不能换物种、不能跟风、也不能按土地类型重铺。MSFS 的做法是承认这层不够，再在上面画 impostor。

## 2. 飞行视景里什么叫好

从上面几家实际在优化的东西归纳，不从某一款的宣传句归纳。

1. **高度带分开。** 巡航高度，树要融进航拍颜色，叶面几何几乎看不见。低空和贴地（直升机、跑道头、下车行走），公告牌会穿帮，需要树冠体积和立着的草。一套模型打全部高度，公开产品里没有这样做的。
2. **摆放来自地表语义，不来自手工种树。** 土地覆盖、生物群系、林斑掩码、排除区（机场、路、水、建筑）。全球范围手摆不成立。
3. **位置稳定。** 密度可调，但已经种下的树不因密度、视点或再次进入而换地方。MSFS 用 Halton 采样就是为这个。
4. **绘制成本和实例数脱钩。** 百万棵树时，按「物种 × 地形瓦片」合并绘制，单棵树的顶点数据压到极少。
5. **和地表影像是同一套颜色。** 否则森林边缘会从航拍的绿跳到模型的另一种绿。

## 3. Microsoft Flight Simulator

公开技术材料最完整的飞行视景植被。分两截：2020 的地形演讲说清楚了怎么铺、怎么画；2024 的 SDK 说清楚了物种和生物群系怎么配。产品负责人访谈里的「地球上每一棵树」单独记，不当成已核实的绘制规格。编辑器能改什么、SDK 能不能拿来用，见 [外部库sdk调研.md](./外部库sdk调研.md) §1。

### 3.1 2020：铺在哪、怎么画

来源：Asobo 技术总监 Lionel Fuentes，GDC 2022《Designing the Terrain System of Flight Simulator: Representing the Earth》。幻灯片：<https://www.asobostudio.com/files/inline-images/Designing_Terrain_System_Fuentes_Lionel.pdf>。参考文献 [2] 是 Ryan Brucks 的 Octahedral Impostors：<https://shaderbits.com/blog/octahedral-impostors>。

放置：

- 每块地形瓦片有植被标记和树木掩码，标记用在 Bing Maps 瓦片的 LoD 13 和 LoD 15。
- 掩码在 Azure 上预先算，用的是机器学习，不是客户端现扫航拍。
- 点位用 Halton 采样。幻灯片写明：无论密度取多少，分布保持均匀；密度在绘制时再收。这是为了调密度时不把树重新随机一遍。
- 物种由生物群系规则决定。
- CPU 采样 DEM 得到树高，采样航拍得到树的颜色，使树在远处自然淡入地表影像。

绘制：

- 百万级实例走三维 impostor。
- 每个物种、每块瓦片一次绘制。
- 顶点缓冲里一棵树一个顶点。
- 幻灯片给过一帧量级：生成约 2300 万棵，视锥内约 630 万棵。这是该页的画面例子，不是对外的性能规格。

摄影测量（TIN）里已经烘进树冠，幻灯片写明「不够好」。运行时把这些树冠压平会在换 LoD 时跳变，所以他们把 impostor 画在 TIN 几何上面，而不是先挖掉 TIN 里的树。这能解释社区里常见的现象：摄影测量区域的树偏大、偏密，用来盖住底下那层难看的树冠。

### 3.2 2024：物种、生物群系、仍然是 impostor

SDK（物种）：<https://docs.flightsimulator.com/msfs2024/html/5_Content_Configuration/Environment/Vegetation/Species_XML_Properties.htm>

SDK（生物群系）：<https://docs.flightsimulator.com/msfs2024/html/5_Content_Configuration/Environment/Vegetation/Biomes_And_Vegetation.htm>

SDK 写明植被用八面体 impostor：公告牌、纹理图集和着色器合在一起，画大量相似的树和灌木。物种 XML 里能配的是变体比例、高度范围、抗风 `stiffness`、图集帧数、纹理索引，以及航拍着色的遮罩（避免树干被染成叶色）。生物群系 XML 再规定这些物种出现在哪一类天然植被里，例如寒带落叶林、热带稀树草原。附加内容可以自带 `vegetation` 目录替换或增补，不必改全球数据。

官方文档没有把 2024 改成「近处全是高模树」。近处库里的单个树模型（地编里摆的杏仁树一类）和自动植被不是同一条管线；2022 年社区对 SDK 的核对也是这个区分。

### 3.3 访谈里的目标，尚未在工程文档里核对

Jörg Neumann（Microsoft Flight Simulator 负责人）接受 PC Gamer 访谈时说：2024 要用机器学习辨认树种，并在运行时种下「数以万亿计」的树；检测会错，例如把冰岛标成有林，再人工改。转述见 <https://www.pcgamer.com/games/sim/flight-simulator-2024s-huge-ambition-means-you-can-now-exit-the-plane-walk-around-you-can-land-on-every-ship-and-it-looks-like-a-first-person-shooter-environment/> 与 <https://flightsim.to/news/403/jorg-neumann-reveals-details-on-microsoft-flight-simulator>。

这是产品目标表述。能核对的工程事实仍是：全球掩码 + 生物群系 + 八面体 impostor + 航拍着色。

不要把 Blackshark.ai 算进这套树木管线。它公开承担的是 MSFS 的建筑自动生成。Fuentes 的地形演讲讲树木时没有把它列为树木数据来源。

## 4. VBS4

军事训练视景里，公开把「全球程序化植被 + 贴地草要参与战术」说清楚的是 VBS4。

厂商对比片（VBS3 对 VBS4）里的表述，不是独立测量：

- VBS3 的植被是做小块地形时手摆的；VBS4 按生物群系和气候程序化生成，并按坡度、高度、道路等自动拿掉不该有的植被。
- 视距内可以同时看见百万级的树。
- 运行时从 DirectX 9 时代的限制换到 Vulkan。

片源：<https://www.youtube.com/watch?v=FY-3nQ5Fpeo>。

贴地草有单独的版本说明。Defense Advancement 对 VBS4 / VBS Blue IG 22.2 的报道：全球、按地区区分的三维草和地被；人卧在草里时，极远处的其他实体也看不见他（他们称为 fair fight）；人走过草会倒伏。<https://www.defenseadvancement.com/news/latest-software-releases-of-bisims-flagship-military-simulation-training-products/>

地理数据不是引擎自己变出来的。2023-11-28 Bohemia 与 LuxCarta 的合作新闻写明：正射影像、土地覆盖、数字地形，以及从亚米影像提取的植被、建筑、路，进入 VBS4 一类运行时。<https://www.luxcarta.com/blog/press-release/bohemia-interactive-simulations-and-luxcarta-announce-geospatial-terrain-partnership>

学术侧同一用法：ISPRS 2025 论文把 OpenStreetMap 渲成土地覆盖栅格，点名 X-Plane 和 VBS4 都用这类栅格在运行时生成「看起来属于那一块地方」的植被。<https://isprs-annals.copernicus.org/articles/X-G-2025/269/2025/isprs-annals-X-G-2025-269-2025.pdf>

VBS4 没有公开到「一棵树几次绘制、用不用 impostor」。能借鉴的是数据层和训练约束：土地覆盖决定种什么，排除区决定不种什么，草是战术遮挡而不是远景装饰。

## 5. 其他飞行模拟

### 5.1 X-Plane 12

官方格式说明（2022-11-10 起覆盖 X-Plane 12）：<https://developer.x-plane.com/article/forest-for-file-format-specification/>

三维树制作说明：<https://developer.x-plane.com/article/building-custom-3-d-trees/>

- `.for` 描述一片林用什么树。X-Plane 12 起可以是真正的三维网格，不再只有纹理矩形。
- 每棵树两套外观：近处一到多个三维网格，风会吹这套网格；远处一张始终朝向相机的侧视公告牌。由引擎按距离切换。
- 林可以分层（下层灌木、上层乔木），也可以分组，让同一物种聚成一团。
- 自动场景和 DSF 多边形都引用 `.for`。WorldEditor 的森林工具画区域、林带或单点，并设密度。<https://developer.x-plane.com/manuals/wed/>

这是一条清楚、可实施的 LOD 链，全球自动植被也在用。它没有 MSFS 那种「采样航拍给树染色」的公开说明，低空地面仍常常是平的草纹理。第三方插件 3Dgrass 的产品页把这件事说得很直：用相机周围一圈立着的、能随风动的地被，替换平的绿纹理；宣称 130 多种草、花、灌丛。<https://3d-grass.com/> 它是插件，不是 Laminar 的植被系统，但说明 X-Plane 12 的短板在贴地，不在远处的林冠。

### 5.2 Prepar3D

Autogen 说明：<http://www.prepar3d.com/SDK/Environment%20Kit/Autogen%20SDK/autogen.html>

世界分成大约 1.2 km 见方的格子。土地分类纹理可以带标注：建筑脚印和植被区域。植被长什么样由 `AutogenDescriptions.XML` 决定，里面是分组和地区，用相对权重抽模型（例如某一组里成熟、老龄、幼龄各占多少）。标注工具画的是一块植被多边形，运行时在这块里面生成树，不保留照片里每一棵树的位置。

这是 FSX 一代的做法，Prepar3D 沿用。它能铺大范围、能按地区换树种，但没有全球机器学习掩码，也没有 impostor 合并绘制的公开说明。

### 5.3 FlightGear

<https://wiki.flightgear.org/Random_Vegetation>

两处来源：`materials.xml` 里按材质随机铺；或者地块 STG 里的 `TREE_LIST` 明确给点，后者经常由 osm2city 从 OpenStreetMap 生成。树本身是十字交叉的矩形（2024.1 之后是三片），纹理图集横向上是不同树形，纵向上是夏、夏雪、冬、冬雪。密度由渲染设置缩放。

开源、数据路径清楚，视觉上就是公告牌林。适合当「最小可用植被」的参照，不是效果标杆。

### 5.4 专业图像生成器

Presagis Vega Prime 的产品页把自然植被列为大范围实时视景的一项：<https://www.presagis.com/en/product/vega-prime/>。Fidelity 的 FidViewEX 写了单棵树、森林、地被、动画和风：<https://fidelitytech.com/sims-trainings/fidviewex/>。页面是能力清单和多边形吞吐宣传，没有放置规则和绘制结构。本次不把它们和 MSFS、VBS4 排在同一证据档。

CAE Medallion、AMST VISIM、MVRsimulation VRSG 能核对到的公开说法见 [外部库sdk调研.md](./外部库sdk调研.md) §3。同样不进 §13 的评分表。

DCS World 的树木实现没有官方技术说明。社区论坛里「老版本 SpeedTree 授权」一类说法，本次不采信。

## 6. SpeedTree

树木资产和森林运行时的工业默认件。Unity 于 2021-07-14 完成对 Interactive Data Visualization（SpeedTree）的收购，2021-07-22 公布。收购说明写明产品覆盖建筑、游戏、影视和实时仿真，并且继续引擎无关。<https://unity.com/news/unity-acquires-interactive-data-visualization-inc-idv-creators-speedtreer>

收购说明点名的游戏（《地平线：零之曙光》《使命召唤：战区》《巫师 3》《刺客信条：英灵殿》《杀手 3》《对马岛之魂》）用的是植被资产生成。这不等于这些游戏都嵌入了 SpeedTree 的森林管理运行时。

Runtime SDK 10 手册（原 Games SDK）：<https://docs.unity3d.com/speedtree-runtime-sdk/manual/index.html>

集成可以停在某一层：

| 用法 | 得到什么 | 失去什么 |
| --- | --- | --- |
| Modeler 只导出网格 | 最快接进任意渲染器 | 运行时 LOD、可缩放的风、公告牌、森林裁剪都没了 |
| 只用 Core 读 `.stsdk` | 顶点、LOD、风、骨骼、环境光遮蔽等 Modeler 数据 | 仍要自己做森林管理和绘制 |
| 再用 Forest | 裁剪和 LOD，手册写可管理一千万棵以上的树，三维 LOD 一直收到一张公告牌，同类型公告牌合批；另有草 | 绘制调用仍由接入方接到自己的图形 API |

对手头是自有渲染器、又要近景树木质量的项目，SpeedTree 解决的是「树长什么样、风怎么吹、LOD 怎么收」。它不解决「这个经纬度是不是林地」。许可、标价和源码是否公开，见 [外部库sdk调研.md](./外部库sdk调研.md) §2。

## 7. 近景密度：游戏引擎里的参照

这些不是飞行模拟产品。飞行模拟要补「贴地和走进树林」时，公开做法在这里，不在 Prepar3D 的 Autogen 里。

### 7.1 Unreal Engine 5

UE5 没有一套全球飞行植被产品。Epic 的自制飞行模拟教程用 Cesium 或 ESRI 铺地球和机场，用 Cartographic Polygon 把机场从地形网格里裁开，教程本身不包含植被。<https://dev.epicgames.com/community/learning/tutorials/mmL/unreal-engine-a-diy-flight-simulator-tutorial>

飞行视景若用 UE5，公开路径是：Cesium for Unreal 一类插件提供全球地形和影像，植被再用引擎自己的工具铺到这块地形上。Cesium 官方教程允许用 Foliage 工具把植物刷到 Cesium World Terrain 上，并要求实例放进与地理参考绑定的子关卡，否则改原点后树会错位。教程明确不要对全球地形使用 Fill，范围太大，编辑器会卡死。<https://cesium.com/learn/unreal/unreal-foliage> Cartographic Polygon 裁的是地形网格，不自动把已经种下的树从跑道上删掉；官方也写明这种裁切不影响物理。<https://cesium.com/learn/unreal/unreal-clipping/>

引擎里和植被有关的是几套工具，不是一个森林系统：

- **Foliage 工具**：在网格上刷静态网格实例，硬件实例化。可设密度、缩放、坡度、剔除距离、阴影和碰撞。
- **Landscape Grass**：按地形材质层在近处铺草，有出现和消失距离。只接 Landscape，不直接接 Cesium 瓦片。
- **PCG**：按空间数据做规则生成，可以做排除和分层生物群系。Epic 写明它能做森林，但不是森林专用工具。5.6 起可用 GPU PCG 按 grass map 铺草；5.7 起可用 Instanced Skinned Mesh Spawner 生成蒙皮实例。Biome Core 是官方示例，把多套 PCG 拼成一个世界。<https://dev.epicgames.com/community/learning/knowledge-base/KP2D/unreal-engine-a-tech-artists-guide-to-pcg>
- **Nanite Foliage**：5.7 起为实验特性，5.8 文档仍要求发布时谨慎。<https://dev.epicgames.com/documentation/unreal-engine/nanite-foliage> 用虚拟几何画密林：实例化、蒙皮、体素化。Epic 举的例子是《巫师 4》技术演示里的森林飞越，场景是做好的局部林地，不是土地覆盖驱动的全球铺树。风走 Dynamic Wind 插件，按骨骼算，比逐顶点的 World Position Offset 便宜。树冠这类碎几何要开 Preserve Area，否则远处变稀；一张卡片插很多叶子的掩码材质，开 Nanite 不一定更快，不透明叶子几何往往更合适。<https://dev.epicgames.com/documentation/unreal-engine/working-with-naniteenabled-content>

远景仍要另做 impostor 或 HLOD。社区讨论里，大量实例和 HLOD 对换时会卡。UE 侧有没有把 Brucks 的八面体 impostor 收成官方插件，本次没有用 Epic 文档核对，不写死。

和本项目目标直接相关的缺口：没有全球林斑，没有把树染成所在航拍的颜色，没有「巡航高度树消失进地表、贴地再长出树冠和草」这条高度带。草的剔除距离能让草只出现在近处，但是按距离裁掉，不是沿视线融进地表颜色。

### 7.2 《对马岛之魂》的草

GDC 2021，Eric Woley，Sucker Punch，《Procedural Grass in Ghost of Tsushima》。演讲记录：<https://www.youtube.com/watch?v=Ibe1JBF5i5Y>。幻灯片归档：<https://archive.thedatadungeon.com/ghost_of_tsushima_2020/documents/gdc_2021/gdc_2021_procedural_grass_in_got.pdf>。

他们放弃整张草卡片，因为风绑在整张卡片上，而且密度一高 overdraw 过大。做法是地形切块，计算着色器在块内撒叶片、做距离和视锥剔除，再实例化绘制。演讲给出的一帧：场景里考虑约 100 万片草叶，实际画约 8.3 万片，端到端约 2.5 ms。草的种类、高度来自地形纹理，不是每片草一个场景节点。

这是贴地草的公开上限之一。飞行视景若只做巡航，用不上；要做直升机贴地或步行，预算应照这种「计算着色器撒点 + 只画视锥内的叶片」来估，而不是照场景图里一棵节点一棵树来估。

## 8. 开源地球场景：osgEarth

和飞行视景最接近的开源实现是 osgEarth 的程序化植被，作者同为 Pelican Mapping。

结构（源码模块，不是产品规格）：`LandCover` 提供地类，`LifeMapLayer` 把地类和噪声变成适宜度，`BiomeLayer` 决定这一带用哪些模型，`VegetationLayer` 负责铺树、灌木和地被，绘制走 `Chonk`（GPU 裁剪、间接绘制、绑定纹理）。风和阴影在这条管线上都有着色器支持。源码索引：<https://deepwiki.com/gwaldron/osgearth/4.4-procedural-vegetation>。`Chonk` 的多视口绘制有单独说明：<https://docs.osgearth.org/en/latest/chonk-multiview.html>。

更早一档是 `GroundCoverLayer`：在地表贴片上用 GPU 画公告牌（树、草、石头），输入同样是土地覆盖、遮罩和颜色层。<https://github.com/gwaldron/osgearth/blob/master/src/osgEarthSplat/GroundCoverLayer>

osgEarth 的价值是管线拆分已经落在开源库里，可以直接读。它不是效果上超过 MSFS 的产品。默认密度、实例上限这次没有逐行核对源码，不写进结论。

同一家的 Rocky 是基于 Vulkan Scene Graph 的地球渲染库。公开 README 有影像、地形和地理注记，没有植被层。<https://github.com/pelicanmapping/rocky>

## 9. 看起来像树，但不是植被系统

Google Photorealistic 3D Tiles 是摄影测量网格。Google 自己的问答写明：行人尺度不准，停着的车、雨篷会熔进网格，树冠有时是浮空的一块；数据不是测量级，目的是沉浸式看，不是空间分析。<https://mapsplatform.google.com/resources/blog/commonly-asked-questions-about-our-recently-launched-photorealistic-3d-tiles/>

Cesium 社区里，Google 这套数据没有土地类型属性，不能查询哪一块是路、草或树。<https://community.cesium.com/t/terrain-metadata-on-google-photorealistic-tileset/38128>

所以它不能换树种、不能跟风、不能按季节换叶，也不能在跑道头可靠地「没有树」。MSFS 在 TIN 上再铺 impostor，开源地编工具（如 GEDOT）则用 OpenStreetMap 的林地多边形把摄影测量里的植被三角挖掉，再交给模拟器自己的自动植被。两条路都是：网格负责建筑和地形大形，植被另铺。

## 10. 各家实际分成的层

把上面的做法叠在一起，飞行视景的植被是四层，不是一种模型。

| 层 | 观众在哪 | 公开产品里用什么 | 谁做得完整 |
| --- | --- | --- | --- |
| 地表颜色 | 中高空 | 航拍或土地覆盖着色，让林冠远看和地面是同一块绿 | MSFS（采样航拍给树染色）；摄影测量网格在这一层已经「像树」 |
| 林冠体积 | 中低空，能看出一棵棵树 | 八面体 impostor 或侧视公告牌；按物种和瓦片合并绘制 | MSFS；X-Plane 的远处公告牌是更简单的一档 |
| 单棵树几何 | 贴树飞行、步行 | 三维网格，近处替换 impostor；风吹网格 | X-Plane 12 的 `.for`；SpeedTree 资产；UE5 Nanite（实验，且不是全球数据） |
| 贴地草 | 直升机、跑道头、下车 | 计算着色器或 GPU 在相机附近撒叶片；远处仍是地面纹理 | VBS4 把草做成全球、分地区、并参与隐蔽；游戏侧参照是《对马岛之魂》；X-Plane 默认较弱，靠 3Dgrass 一类插件补 |

放置数据是另一条轴，和上面四层正交：

- 全球、预先算好的林斑：MSFS 的 Azure 掩码。
- 全球、运行时按土地覆盖和生物群系生成：VBS4、osgEarth。
- 地块里的植被多边形或点列：X-Plane、Prepar3D、FlightGear（含 OSM）。
- 只有模型、没有「哪里是林」：SpeedTree、Nanite Foliage。

### 13.6 格子不够看的地方

摆放：

- MSFS 的树高会为盖住摄影测量树冠而偏大，和「不能为了好看放大」对着干，所以树高是部分，不是支持。Halton 和绘制时再收密度，位置稳定是支持。
- VBS4 按坡度、高度、道路拿掉植被，排除只覆盖到路和坡，没有公开进近净空，所以排除是部分。
- X-Plane 的自动林和 `.for` 有地类，也有排除多边形；一部分 `.for` 每次运行会重新随机树种，所以位置是部分。
- SpeedTree 不生成位置。位置稳不稳完全看交进去的实例，列成不支持。
- UE5 能按地形图层和 PCG 规则铺，也能按坡度筛。没有全球林斑。刷在 Cesium 上的实例存在子关卡里，地理参考原点变了会错位。

近远：

- MSFS 高空染进航拍是支持这一半；自动植被公开的仍是八面体 impostor，没有贴地网格和立着的草，所以高度带是部分。物种 XML 里的草是地面纹理，不是立着的草。
- VBS4 的三维草要在极远处仍挡住卧倒的人，和「高空不画草」相反，所以这一行是不支持。
- X-Plane 默认没有立着的草。3Dgrass 插件补的是相机周围一圈，不是官方系统，也不融进航拍颜色。
- SpeedTree 有网格淡成 360° 公告牌和顶视公告牌；草没有 LOD，格子进视锥就出现。
- UE5 的 Landscape Grass 和 PCG 草能按距离只留近处，淡出是裁剪，不是融进地表颜色，所以草这一行是部分。

绘制：

- 和航拍同色，公开写清楚的只有 MSFS（采样航拍，树干可用遮罩排除）。osgEarth 的地被层可以乘一张颜色图，不是按棵采样航拍。
- MSFS 的风是物种上的一个 `stiffness`，整棵 impostor 一起动，没有从树干 0 到树叶 1。变体可以各自有 stiffness，所以大小树刚性是部分。
- SpeedTree 的顶点上分别有枝条权重和叶片权重。刚性按基树调，大树和小树要做成不同基树，不是按实例高度自动变。树有级联阴影；草会不会投射影子，手册没有单独写。
- 成本和实例数脱钩：MSFS 是每物种每瓦片一次绘制、一棵树一个顶点。SpeedTree 是按基树实例化、同种公告牌合批。UE5 的 Foliage 和 Nanite 也是实例化，但没有「全球、一棵树一个顶点」这种画法。
- 贴地前视：MSFS 用 impostor 避开透明树冠叠层。SpeedTree 的叶子就是透明卡片，不解决这个预算。UE5 写明掩码卡片贵，Nanite 更偏向不透明几何，这是部分。

加载：

- MSFS 的四叉树按屏幕大小和带宽要瓦片，相机周围留在内存里，这条按机制算支持。下降时会不会空几秒，没有定量公开。
- UE5 的 Cesium 地形能流，植被不能跟着全球下降现种。官方教程禁止对全球地形 Fill。所以这一行是不支持。

第 5 节：

- FlightGear 的树图集有夏、夏雪、冬、冬雪四行，落叶着色器会换色。VBS4 公开的是雪可以积到植被上，不是落叶换季。SpeedTree 的季节在 Pipeline SDK，前提是模型做过季节，Runtime 森林不负责换叶。
- 夜视和红外：SpeedTree、UE5 的植被文档都没有这项。其余没写到，保持不明。
- 命中体：VBS4 的草参与远处遮蔽，不是树的离地高度查询。SpeedTree 的 Core 导出碰撞体，没有 HAT 查询。UE5 的 Foliage 类型可以开碰撞从而挡住射线；Cesium 裁地形不影响物理，密草上开碰撞也不是训练用的离地查询。
