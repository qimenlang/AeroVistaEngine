# 植被系统功能目标梳理

使用场景：同一套植被要同时覆盖高空飞行，和直升机低空贴地。需求按摆放、近远切换、绘制、加载分开。最后一节是这个场景推不出来的，先不当必须。效果标准来自 [调研.md](./调研.md) §2。刚体实例的格子和数组来源见 [植被系统设计.md](./植被系统设计.md)，挂接见 [实例渲染设计.md](../引擎基础功能/实例渲染设计.md)。

贴地时视线沿着地面向前，不是从正上方往下看。直升机会在一次飞行里把高空和贴地都飞穿。

## 1. 摆放

种在哪、种多高、换不换地方。

1. **来自地表语义，不来自手工种树。** 土地覆盖、生物群系、林斑掩码决定种什么。全球范围手摆不成立。
2. **位置稳定。** 密度可调，但已经种下的树不因密度、视点或再次进入而换地方。MSFS 用 Halton 采样就是为这个。
3. **树高是高度和距离参照，不能为了好看放大。** 树底落在地形高程上，树高落在该物种的高度范围内。直升机用树冠顶判断离地高度和到林缘的距离。树被放大去盖住底下不好看的网格时，这个参照是错的。陡坡、水面、近垂直的面不种，或按坡度把密度降下去。
4. **排除区按能降落、能进近来划。** 跑道、滑行道、直升机起降坪、进近方向上的净空、路、水、建筑都没有树，也没有立着的草。只把铺装面抠掉不够：跑道头向外延伸的一段、林中空地，贴地时同样是可落地的地方。

## 2. 近远切换

同一片林从巡航看到贴地，外观怎么变。

1. **高度带分开。** 巡航高度，树要融进航拍颜色，叶面几何几乎看不见。低空和贴地（直升机、跑道头、下车行走），公告牌会穿帮，需要树冠体积和立着的草。一套模型打全部高度，公开产品里没有这样做的。
2. **换带不能跳。** 从巡航降到贴地，林冠从「融进航拍」收到「能看出树冠体积」，再收到近处网格，应当是连续的淡入淡出。某一距离上整片林从公告牌换成网格、或草在某个半径上整圈出现，在贴地前视里都站在画面中央。MSFS 把摄影测量树冠压平再换 LoD 时会跳，这条就是要避开那种跳。耗时也同样：近处比高空重是允许的，但不能在某一个高度整档切换，使这一帧从轻载掉进过载。
3. **贴地草只出现在近处，淡出要沿视线融进地面颜色。** 高空不画草。贴地时草要立着，但不能在飞机周围留一圈明显的圆边。直升机向前看时，这圈边会横在画面里。远处仍是地表颜色。
4. **近景能分出树冠轮廓，远景合成少数几种。** 贴地能看出针叶和阔叶这一类差别；高空只需要颜色和疏密。不是近处也铺几百个物种。

## 3. 绘制

近处看起来什么样，以及大量实例怎么画。

1. **和地表影像是同一套颜色。** 否则森林边缘会从航拍的绿跳到模型的另一种绿。
2. **近景随风动。** 近处的树冠和草要随风摆动。高空融进航拍的那一层可以不动。树种之间抗风可以不同。风的方向和相位来自同一套时间，不跟各自通道的本地帧计时走。
   - 树叶、树干 随风运动的权重不同，从树干到树叶权重从0增加到1；
   - 大树小树，刚性权重也不同；

3. **近景有阴影。** 近处的树和草要投下可见的影子。高空不要求每棵树单独一根影子。
4. **绘制成本和实例数脱钩。** 百万棵树时，按「物种 × 地形瓦片」合并绘制，单棵树的顶点数据压到极少。
5. **贴地前视要单独留填充率预算。** 贴地向前看会穿过大量透明树冠，一个像素上叠着很多层叶子，比高空俯视重得多。预算按这个视角来留，不能只按高空俯视来估。

## 4. 加载

植被数据怎么跟上飞机。

1. **同时应付两种运动。** 高空快、看的范围大、细节粗；贴地慢、范围小、要网格和草。从高空一头扎进一片林时，近处细节要跟得上下降，不能先空几秒再长出树。

## 5. 这个场景推不出来，先不列为必须

下面这些在别的产品里有，但「高空飞行 + 直升机贴地」本身不要求它们。要做需要另定目标。

| 项 | 为什么先不列 |
| --- | --- |
| 季节、积雪换叶 | 高空和贴地都不依赖季节。FlightGear 做了，MSFS 物种配置里没有把它写成绘制前提 |
| 夜航灯、夜视、红外里的植被响应 | 贴地常常发生在夜里，但是否做传感器视景还没作为本系统的使用场景提出 |
| 画面里的树同时成为 HAT / HOT / LOS 的命中体 | 协议里有这些查询，引擎还没有植被。若训练要把树当障碍物或遮挡，查询必须用摆放里同一套树底、树高，不能只在画面上有树。是否纳入，要单独定 |
