# 坐标系统模块设计

面向本项目:在不引入瓦片场景(`readymap.vsgt` 等)的前提下,让当前普通 `.vsgt` 模型也能跑在 **ECEF 世界系**下,并让相机在椭球场景中以正确的"当地天向"初始化、正常手动飞。作为后续 Host→IG 椭球模式同步(见 [多通道同步模块设计.md](./多通道同步模块设计.md) §4.8)的场景侧前置能力。

坐标系背景见 [坐标系统总结.md](../notes/坐标系统总结.md)。

## 1. 目标与范围

**做**:场景加载普通 `.vsgt` 模型时,可选切到椭球世界(ECEF)。模型摆到指定 LLA;相机以模型附近上空为初始视点,手动飞(椭球 Trackball)。

**暂不做**:

- 加载 `readymap.vsgt` / `openstreetmap*.vsgt` 等瓦片场景
- 修改 `Engine::setCameraPose` 语义或新增 `setCameraPoseLla`
- Host→IG 报文 / 同步链路的椭球化(仍走本地世界系)

范围只覆盖**场景装配 + 相机初始化**,同步与位姿 API 不动,回滚成本低。

## 2. ECEF 坐标系统

### 2.1 装配结构

```text
Scene
├─ setObject("EllipsoidModel", EllipsoidModel::create())   // 挂椭球参数(WGS-84)
└─ MatrixTransform(LocalToWorld(lla_model))                // 父节点:把模型钉到 ECEF
   └─ 现有 .vsgt 模型(顶点仍是本地笛卡尔)

Camera
   viewMatrix = LookAt(ecef_eye, ecef_center, local_up)    // 一次性初始化
   → Engine 检测到 EllipsoidModel → 自动切 EllipsoidPerspective + 椭球 Trackball
```

`EllipsoidModel` 只挂参数,不搬几何;真正让"World = ECEF"的是模型父节点 `MatrixTransform`,矩阵由 `computeLocalToWorldTransform(lla)` 生成。椭球投影与 Trackball 由 `engine.cpp` 现有 `getRefObject<EllipsoidModel>` 检测自动启用。

### 2.2 最小闭环步骤

```text
1. scene->setObject("EllipsoidModel", vsg::EllipsoidModel::create())   // 默认 WGS-84

2. 选测试 LLA(如北京地面: lat=39.9, lon=116.4, alt=0)
   auto mt = MatrixTransform::create(ellipsoid->computeLocalToWorldTransform(lla_model))
   mt->addChild(model);  scene->addChild(mt)

3. 相机初始 LLA 选模型上空(alt=500m 之类,能看到模型)
   eye    = ellipsoid->convertLatLongAltitudeToECEF(lla_cam)
   center = ellipsoid->convertLatLongAltitudeToECEF(lla_model)
   up     = normalize(eye)                    // 当地天向
   mainCamera->viewMatrix = LookAt::create(eye, center, up)

4. 运行,手动飞:地平线水平、椭球 Trackball 拖动正常、靠近/远离模型符合预期
```

启用开关由 JSON 中的 `coordFrame` 字段控制,详见 §3。

### 2.3 关键点与坑位

- **模型没有"LLA 坐标"**:`.vsgt` 顶点是本地笛卡尔,只能靠父 `MatrixTransform` 钉到 ECEF。`ComputeBounds` 会穿过该矩阵,bounds 中心自然是 ECEF 大数(~6.3e6 m)。
- **`up` 必须用当地天向**:世界 Z `(0,0,1)` 只在赤道 0° 经度恰好是天向,其他位置会导致地平线歪、Trackball 旋转轴错、近极点奇异。正确取 `normalize(ecef_eye)`(地表附近足够近似椭球法向),或取 `computeLocalToWorldTransform(lla_cam)` 第三列。
- **绕开 `setCameraPose`**:该 API 内部 `up = R(ypr) * (0,0,1)` 是世界 Z,椭球场景不成立。初始化直接写 `mainCamera->viewMatrix = LookAt(...)`;改造 `setCameraPose` 或加 `setCameraPoseLla` 属后续步骤。

## 3. 配置结构:坐标系与初始位姿

### 3.1 顶层字段

新增 / 调整字段:

| 字段 | 类型 / 取值 | 缺省 | 说明 |
| --- | --- | --- | --- |
| `coordFrame` | `"Local"` \| `"Ellipsoid"` | `"Local"` | 决定 `entity.pose` / `camera.pose` 使用哪一半;非法值(含 `null`)报错 |
| `entity` | 对象(见 §3.2) | 无 | 收编原顶层 `model`;单个实体,后续如需多实体再重构 |
| `camera` | 对象(见 §3.3) | 无 | 相机初始位姿;可缺,缺则走引擎默认(Trackball 按 bounds 计算) |

顶层 `model` 字段**取消**,统一放入 `entity.model`。所有现有 `default.json` / `main.json` / `left.json` / `right.json` 需一次性迁移。

`window` / `channelId` / `offsetDeg` / `hostLocal` / `igLocal` / `hostEndpoint` / `requireIgConnect` / `hostEyeStalePolicy` 不变,规则沿用 [多通道同步模块设计.md](./多通道同步模块设计.md) §3.1(方案 A + 未知键拒绝)。

### 3.2 `entity`

```text
entity {
  model : string                     // 模型路径(必填)
  pose? : {                          // 可缺,缺则模型不套 MatrixTransform,走引擎默认放置
    local?     : LocalPose
    ellipsoid? : EllipsoidPose
  }
}

LocalPose      { position: [x,y,z],  eulerYprDeg: [yaw,pitch,roll] }   // 世界米 / 度
EllipsoidPose  { lla: {lat, lon, alt}, eulerYprDeg: [yaw,pitch,roll] } // 度 / 度 / 米
```

### 3.3 `camera`

```text
camera {
  pose? : {                          // 可缺,缺则走引擎默认相机(Trackball 按 bounds)
    local?     : LocalPose
    ellipsoid? : { lla: LLA, lookAtLla: LLA }
  }
}
```

椭球相机第一版只支持 **lla + lookAtLla**(自动产生"当地天向"作 `up`,无奇异问题)。后续如需 YPR 姿态形式再扩展 —— 见 §4。

### 3.4 解析与校验规则

- `coordFrame` 缺省 `"Local"`;取值只允许 `"Local"` / `"Ellipsoid"`,其他报错。
- `entity.pose` / `camera.pose` **可缺**;缺则该实体 / 相机走引擎默认放置,不启用椭球分支。
- 两半 `local` / `ellipsoid` **不强制同时填齐**:允许只写正在使用那半。
- **`coordFrame` 选中的那一半必须完整**:例如 `coordFrame == "Ellipsoid"` 且 `entity.pose` 存在时,`entity.pose.ellipsoid` 必填且子字段齐全;`entity.pose.local` 可以整个不写。切换到未填的那一半 → 报错(不静默回退到默认)。`camera.pose` 同理。
- 沿用方案 A:任一对象一旦出现,其声明子字段全必填;未知键拒绝。
- **不做**跨模式语义等价校验(如 `local.position` ↔ `ellipsoid.lla` 的一致性)。两半 pose 视为**平行意图**,人工负责对齐;写着不同、切模式看到不同位置属正常行为。

### 3.5 示例

**本地模式(缺省,现有场景迁移):**

```json
{
  "entity": {
    "model": "models/lz.vsgt",
    "pose": {
      "local": { "position": [0, 0, 0], "eulerYprDeg": [0, 0, 0] }
    }
  },
  "camera": {
    "pose": {
      "local": { "position": [0, -50, 10], "eulerYprDeg": [0, 0, 0] }
    }
  },
  "window": { "x": 0, "y": 0, "width": 1920, "height": 1080 }
}
```

**椭球模式:**

```json
{
  "coordFrame": "Ellipsoid",
  "entity": {
    "model": "models/lz.vsgt",
    "pose": {
      "ellipsoid": {
        "lla": { "lat": 39.9, "lon": 116.4, "alt": 0 },
        "eulerYprDeg": [0, 0, 0]
      }
    }
  },
  "camera": {
    "pose": {
      "ellipsoid": {
        "lla":       { "lat": 39.9, "lon": 116.4, "alt": 500 },
        "lookAtLla": { "lat": 39.9, "lon": 116.4, "alt": 0 }
      }
    }
  },
  "window": { "x": 0, "y": 0, "width": 1920, "height": 1080 }
}
```

### 3.6 Engine 消费

```text
1. 解析 JSON → EngineChannelConfig(带 coordFrame + entity + camera)
2. if coordFrame == "Ellipsoid":
     scene->setObject("EllipsoidModel", EllipsoidModel::create())
     使用 entity.pose.ellipsoid 生成 MatrixTransform(LocalToWorld(lla))
     使用 camera.pose.ellipsoid 直接写 mainCamera->viewMatrix = LookAt(...)
   else (Local):
     使用 entity.pose.local(如有)套 MatrixTransform 或直接放
     使用 camera.pose.local(如有)调用现有 setCameraPose
3. entity.pose / camera.pose 缺 → 各自走引擎默认(Trackball 按 bounds)
```

## 4. 不做 / 后续

**本次不做**:

- 修改 `setCameraPose` 语义 / 新增 `setCameraPoseLla` 等椭球写入口
- Host→IG 报文扩展 `coordFrame` / LLA 字段
- 主窗覆盖前采样(`captureAuthorityEye`)在椭球模式下的语义调整
- 加载真正的瓦片场景

**后续推进(按 [多通道同步模块设计.md](./多通道同步模块设计.md) §4.8 / §9 P1)**:

1. `setCameraPoseLla(lla, ypr)`:内部 LLA→ECEF,`up` 取局部天向,统一椭球写入口。
2. Host→IG 报文加 `coordFrame`(`WorldLocal | LLA`),`hasEye` 时按模式解释字段。
3. 主窗覆盖前采样在椭球模式下产出 LLA + 姿态,避免把 ECEF 大数当本地 XYZ 发出。
4. 通道 `offsetDeg` 在 ENU / 局部叠加后再变 ECEF,而非直接在欧拉分量相加。
5. LookAt↔欧拉 在椭球奇异附近(近极点、俯仰 ±90°)的数值策略。
