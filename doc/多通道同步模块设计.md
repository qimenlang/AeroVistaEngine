# 多通道同步模块设计

面向本项目 **1 Host + 多 IG（IP 可不同，目标约 10 通道）**。  
TCP/UDP、端口与连通性等通用知识见 [socket总结.md](./socket总结.md)。

验收规格：`engine/Tests/HostIGTests.cpp`（Catch2 BDD）。

---

## 1. 职责划分：SynchronSystem / HostSync / IgSync

角色不对称（帧节奏、TCP 命令方向不同），拆成两个网络端点类，并由引擎侧门面编排：

| 类型 | 职责 |
|------|------|
| **IgSync** | IG 端：本地 UDP bind、`Connect(Host)`、收 `IGCtrl`/状态、回 `SOF`；TCP 收命令并回 ACK/NACK |
| **HostSync** | Host 端：UDP bind + TCP `listen`、收各 IG 的 `SOF`、发 `IGCtrl`/每帧状态；TCP 下发命令并等 ACK；维护 IG 表 |
| **SynchronSystem** | **引擎同步门面**：挂在 Engine loop（如 preFrame / update）；持有 **IgSync**；把收到的同步状态应用到场景（相机/物体）；可选持有 **HostSync** 以便从引擎取数再扇出到各 IG |

```text
Engine loop
  └─ SynchronSystem          ← 参与 preFrame / update
        ├─ IgSync            ← 必有：收 Host 数据 → SynchronSystem 写场景
        └─ HostSync          ← 可选（临时）：从引擎取眼点等 → 发往各 IG
```

### 1.1 HostSync 与进程边界

- **最终**：HostSync（及 Host 业务）应落到 **独立进程**，与 Engine 剥离。  
- **当前**：临时作为 `SynchronSystem` 成员，只为方便 **从本机 Engine 取待发送数据**（如主窗相机眼点），再经 socket 发给各 IG。  
- 拆进程后：Engine 侧 `SynchronSystem` 仅保留 IgSync；Host 进程持有 HostSync + 数据源。

### 1.2 多窗口视觉同步（目标用法）

典型：3 个 Engine 窗口——1 个主窗（SynchronSystem = HostSync + IgSync），2 个从窗（仅 IgSync）；桌面相邻、通道 frustum 相邻。

```text
主窗：本地输入更新眼点 → HostSync 扇出眼点（+ 帧号）
     本地通道建议直接应用眼点，勿依赖 UDP 自环
从窗：IgSync 收包 → SynchronSystem 按 channelId + 标定算本通道视锥并设相机
```

注意：Host 发的是 **共用眼点/主 view**；各 IG 用通道标定形成相邻 frustum，而不是三份完全相同的 camera。

#### 通道 frustum 拼接（标定）

眼点相同；投影参数（vFOV、aspect、near/far）各通道一致时，水平相邻靠 **朝向偏航** 对齐：

- `aspect = 窗口宽/高`；VSG 用 vFOV，水平张角  
  `hFOV = 2·atan(aspect·tan(vFOV/2))`
- 三通道、硬拼无重叠：中 `yaw=0`，左/右 `yaw=±hFOV`
- 需要边缘融合时改为 `yaw=±(hFOV−overlap)`

各 IG 本地存通道标定（相对主视向的 yaw 等）；同步包只更新共用眼点，投影与朝向用本通道标定。

### 1.3 Loop 相位（约定）

```text
preFrame:  IgSync 收包 → SynchronSystem 应用到 camera/entity → 再 update/render
晚于本机相机输入（主窗）: 读最终 eye → HostSync 发给各 IG
```

主窗若以本地输入为准，可关闭本机 IgSync 对相机的位姿覆盖，避免与 Host 出站互相打架。

共享能力（组合，勿两套拷贝）：`UdpTransport` / `TcpTransport`、CIGI 编解码与回调注册。

## 2. 双平面

| 平面 | 通道 | 本模块流量 | 是否必达 |
|------|------|------------|----------|
| sync | UDP | `IGCtrl`、`SOF`、心跳、时间戳、每帧状态（含眼点） | 否；丢了用下一帧补 |
| command | TCP | 加载场景、切库、复位、模式切换、业务指令 + 回执 | 是 |

```text
HostSync
 ├─ UDP  sync plane      IGCtrl / SOF / 心跳 / 每帧状态
 └─ TCP  command plane   命令 + ACK/NACK
         ↓
    IgSync × N
```

## 3. 默认端口

便于同机同时起 Host+IG，并用端口区分上下行。记忆：**Host 收 8000、发 8001**（IG 对调）。

```text
UDP  sync（交叉双端口）
  HostSync: send → 8001,  recv ← 8000
  IgSync:   send → 8000,  recv ← 8001

TCP  command
  HostSync listen :8100
  每个 IgSync connect → Host_IP:8100
```

| 通道 | 端口 | 说明 |
|------|------|------|
| UDP IG→Host | **8000** | HostSync `bind`；IgSync `sendto` Host |
| UDP Host→IG | **8001** | IgSync `bind`；HostSync `sendto` 各 IG |
| TCP 命令 | **8100** | HostSync 一个 `listen`；每 IG 一条连接 |

约束：Host 的 `udpPortSend` == IG 的 `udpPortRecv`（默认 8001），反之亦然（8000）。

同机多 IG：各 IG `udpPortRecv` 须不同（如 8001 / 8003）；Host 在接入时学习。多机部署时各 IG 可都 bind `8001`。

> 注：与 CIGI MiniHost/DummyIG 默认端口号对调，联调第三方示例时注意改配置。

## 4. 拓扑（1 Host + N IG）

```text
                         ┌── sendto IG1_IP:udpRecv
HostSync UDP bind :8000  ┼── sendto IG2_IP:udpRecv
   ↑ recvfrom            └── ...
IgSync_i bind 各自 udpRecv，sendto Host_IP:8000

HostSync TCP listen :8100 ── accept ── IgSync × N
```

HostSync：1 个 UDP 收口 + N 个发送目标；TCP 1 listen + N 连接；维护 `{id, ip, udpRecvPort, tcp}`。

## 5. 配置与 API 语义

```text
AddressConfig  { addr, udpPortSend, udpPortRecv, tcpPort }
```

| API | 类型 | 含义 |
|-----|------|------|
| `Initialize(AddressConfig local)` | HostSync / IgSync | 建本地传输；**不**表示已连上对端 |
| `Connect(AddressConfig hostEndpoint)` | **仅 IgSync** | TCP + UDP 同步确认 |
| — | HostSync | **不**提供 `Connect`；初始化后等待 IG |

UDP 同步成功（实现内）：双方各收发至少一次预期 sync 报文后置位；BDD 只断言状态位，不读取 payload。

### 状态（分项）

| 查询 | 类型 | 含义 |
|------|------|------|
| `tcpConnected()` / `udpSynced()` | IgSync | 命令面 / 同步面是否已通 |
| `hasReadyIg()` / `readyIgCount()` | HostSync | 已就绪 IG（TCP+UDP）数量 |

`IgSync::Connect` 成功 ⇔ `tcpConnected && udpSynced`；HostSync 对应 `readyIgCount` 增加。  
Initialize 之后连接类状态均为 false。

## 6. 角色流程

```text
HostSync.Initialize(local)       — UDP bind:8000，TCP listen:8100，等待 IG
IgSync.Initialize(local)         — UDP bind:udpRecv（默认 8001）
IgSync.Connect(hostEndpoint)     — TCP → Host:8100，并完成 UDP 同步
HostSync                         — accept + 记录 IG，readyIgCount 增加
Engine / SynchronSystem          — loop 中应用 IgSync 数据；主窗经 HostSync 扇出眼点
```

命令面：HostSync 下发带 `seq` 的命令 → IgSync `ACK`/`NACK` → 超时重试、幂等。高频每帧状态走 UDP。
