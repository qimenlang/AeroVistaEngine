## 0. 初步同步：范围与目标

**初步同步**要先跑通「多通道跟同一 Host 节拍 + 共用眼点 + 通道视锥相邻」，不追求显示卡 Genlock / 亚毫秒校时。


| 纳入初步                                                      | 暂不纳入                                     |
| ------------------------------------------------------------- | -------------------------------------------- |
| 连接：TCP HELLO 握手 + UDP 同步面握手（`UDP_SYNC`）           | RTT / NTP 式时钟 offset                      |
| FreeRun：Host 按帧自动发 IGCtrl（不等 SOF）                   | Barrier 等齐再发下一帧（可后加 `frameGate`） |
| Host 在 IGCtrl 填入 `simTimeMs`（毫秒）；IG 侧暂不消费        | IG 对 `simTimeMs` 做矫正 / 外推              |
| 每收到 IGCtrl 回一条 SOF（健康 / 掉帧观察）                   | 可靠 UDP、丢包重传                           |
| 每帧 IGCtrl 可内嵌共用眼点；各 IG 本地 `offsetDeg` 算 frustum | 实体级全量状态同步细则                       |
| 1 主窗（Host+IG）+ N 从窗（仅 IG）Engine 集成                 | 边缘融合 / 几何精标定工具链                  |
| TCP 仅握手（HELLO / HELLO_ACK）                               | TCP 加载/切库/复位等命令面 + ACK/NACK（词义见 [socket总结.md](./socket总结.md)） |
| Host 先挂主窗 Engine（channel0）；独立 Host 进程为后期       |                                              |
| 本地世界系下 Host 驱动 IG 相机（`setCameraPose` 等）          | 椭球 / ECEF 下 Host 驱动 IG 相机（见 §4.8）  |

## 1. 职责划分与角色流程


| 类型               | 职责                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| **IgSync**         | UDP bind、`connect(Host)`（TCP HELLO + UDP_SYNC）、收 `IGCtrl`（含可选眼点）、回 `SOF`                        |
| **HostSync**       | UDP bind + TCP `listen`、收各 IG 的 `SOF`、按帧扇出 `IGCtrl`/眼点；维护 IG **peer 表**（见 §2）              |
| **SynchronSystem** | Engine 门面：挂 loop；持有 **IgSync**；可选持有 **HostSync**；覆盖前采样、回灌 ⊕ `offsetDeg`、无新包/断线策略 |
| **Engine**         | 帧循环 `preFrame / update / render / postFrame`；`mainCamera` / `setCameraPose`；从配置注入偏移与无新包策略   |


```text
Engine::tickOnFrame
  preFrame  → SynchronSystem 收包（入队眼点；处理 IGCtrl 时回 SOF；不写相机）
  update    → handleEvents →【主窗覆盖前采样】→ SynchronSystem::update（写 Host 眼点）→ viewer update
  render
  postFrame → Host 用本帧采样（或重发上一帧）填入 IgCtrlMsg，扇出 → 全体 ready IG（含 A）
```



### 1.1 HostSync 进程边界

- **最终**：HostSync 独立进程；ABC 均为纯 IG，行为一致。  
- **当前**：HostSync 挂主窗 Engine；眼点权威 = 主窗覆盖前采样 → Host 扇出 → 全体 IG 回灌（含 A，≥1 帧延迟），不为 A 开「跳过回灌」旁路。  
- 拆进程后：Engine 侧仅留 IgSync；权威源改为指定输入 IG 上行或 Host 本地输入（见 §5）。

### 1.2 角色流程（摘要）

```text
A（主窗 Host+IG）: HostSync.initialize + IgSync.initialize/connect
B/C（从窗仅 IG）:  IgSync.initialize/connect → Host readyIgCount 增加
每帧: Host.run 后 update(simTimeMs, eye*) 扇出
      → 各 IG preFrame 收包/回 SOF → update 应用眼点
```

TCP 业务命令面（加载 / 切库 / 复位 + ACK/NACK 等）：**尚未实现**，名词见 [socket总结.md](./socket总结.md)，缺口见 §9。

## 2. 双平面与网络拓扑（TCP / UDP）

本节只讲 **两条网络链路怎么连、谁连谁**，不涉及相机语义。

### 2.1 为什么叫「双平面」

「平面」= **一类用途的通信通道**（不是 3D 几何平面）。本模块故意拆成两条，避免互相拖累：


| 平面 | 协议 | 管什么 | 为什么单独一条 |
| ---- | ---- | ------ | -------------- |
| **同步平面 sync** | **UDP** | 每帧节奏与状态：`UDP_SYNC`、`IG_CTRL`（+可选眼点）、`SOF` | 高频、可丢；丢了用下一帧，不必可靠 |
| **命令平面 command** | **TCP** | 接入握手（当前仅 `HELLO`/`HELLO_ACK`）；日后加载/切库/复位等 | 必须送达、要回执；不适合塞进高频 UDP |


「双平面」= **UDP 同步面 + TCP 命令面** 两套并行链路，不是两套独立产品。

> TCP 业务命令（加载/切库/复位）+ ACK/NACK：**尚未实现**，见 §9；词义见 [socket总结.md](./socket总结.md)。

### 2.2 「拓扑」指什么、谁和谁连

**拓扑** = 节点之间的**连接关系图**（谁 listen、谁 connect、包往哪发）。这里没有人「被拓扑」——是描述 **Host 与各 IG 的连线形状**：

```text
                    ┌──────────── HostSync ────────────┐
                    │  TCP :8100  listen ← 各 IG HELLO │
                    │  UDP :8000  收 SOF / UDP 握手      │
                    │  UDP sendto → 各 IG:udpRecv（IGCtrl）│
                    └──────────┬──────────┬──────────┘
                               │          │
              ┌────────────────┘          └────────────────┐
              ▼                                            ▼
         IgSync A（可与 Host 同进程）              IgSync B / C …
         TCP connect → Host:8100                   同上
         UDP bind 本机 udpRecv                     udpRecv 须不同（同机）
```

默认端口：Host UDP 收 **8000**、发 **8001**；TCP **8100**。同机多 IG：`udpRecv` 必须不同（8001/8003/8005…）；多机可同用 8001。

### 2.3 Peer 表（Host 侧）

**Peer（对等端）** = Host 眼里的「某一个已接入 / 正在接入的 IG」。  
**Peer 表** = HostSync 内存里的 IG 名单（实现：`HostSync::IgPeer` 列表），用来知道「该给谁发 IGCtrl、谁算 ready」。

每条大致含：`{ip, udpRecvPort, tcp 连接, tcpReady, udpReady}`。

- 接入时从 TCP **HELLO** 学习对方 `udpRecvPort`（以及 IP）。
- **两端都 ready**（`tcpReady && udpReady`）才计入扇出目标 / `readyIgCount`。
- 通用释义见 [socket总结.md](./socket总结.md)「Peer」。

## 3. 多窗口用法与通道配置

典型：3 Engine——A 主窗（Host+IG），B/C 从窗（仅 IG）；桌面相邻、frustum 相邻。

位姿表示、Host→IG 写相机、椭球演进见 **§4**；本节只保留窗口 / JSON / frustum 标定配置。

### 3.1 通道启动配置（JSON）

每个 Engine 进程一份 JSON（`engine/resources/config/`）；命令行：`engine.exe -c <path>`（省略则默认 `main.json`）。


| 文件 | 角色 | `channelId` | 典型 `offsetDeg.yaw` |
| ---- | ---- | ----------- | -------------------- |
| `main.json` | Host+IG | `0` | 0 |
| `left.json` | 仅 IG | `1` | ≈ +hFOV（样例 +18.05°） |
| `right.json` | 仅 IG | `2` | ≈ −hFOV（样例 −18.05°） |


**角色：** `channelId == 0` → 启 Host+IG（用 `hostLocal`）；`channelId > 0` → 仅 IG（`hostLocal` 可忽略）。不单独配 `enableHost`。

**字段要点：**


| 字段 | 要点 |
| ---- | ---- |
| `channelId` | 是否启 Host |
| `offsetDeg` | 本通道 frustum 偏航/俯仰/滚转（度），回灌时叠加（§4.5） |
| `igLocal` / `hostEndpoint` | IG bind 与 Host 端点；同机多 IG 的 `udpPortRecv` 必须不同 |
| `hostLocal` | 仅主通道：Host bind |
| `model` / `window` | 模型路径；窗口几何（是否显示由 `Engine::showWindow`，不进 JSON） |
| `hostEyeStalePolicy` | `ReuseLast` / `Freeze`（§4.4） |


本地世界系应用：`最终位姿 = Host(pos+euler) ⊕ offsetDeg → setCameraPose`。

联调用三窗并排（非产品部署）：left `(0,0)`、main `(640,0)`、right `(1280,0)`，各 `640×1080`；读配置写入 `WindowTraits`（当前无边框）。



### 3.2 通道 frustum 拼接（标定）

眼点相同（世界系）；投影参数一致时，水平相邻靠偏航：

- `aspect = 宽/高`；`hFOV = 2·atan(aspect·tan(vFOV/2))`
- 三通道硬拼（本引擎 Y-forward、Z-up，`Rz(+yaw)` 转向 −X / 左侧）：中 `yaw=0`，**左** `+hFOV`**，右** `−hFOV`；融合则幅值用 `hFOV−overlap`、符号同上
- 标定存各 IG 本地 JSON `offsetDeg`；同步包只更新共用眼点（见 §4.5）

## 4. 相机位姿驱动

本节整合 Host 驱动 IG 相机相关约定：Engine 位姿 API、本地世界系下的同步写相机、连接态策略，以及椭球 / ECEF 演进。帧内采样与扇出时序细节见 §5；坐标系背景见 [坐标系统总结.md](./坐标系统总结.md)。

### 4.1 目标与范围


| 已实现（本地世界系）                                  | 演进（椭球 / ECEF）                                     |
| ----------------------------------------------------- | ------------------------------------------------------- |
| `Engine::mainCamera` / `setCameraPose`                | 椭球场景下 LookAt 落在 ECEF                             |
| Host 覆盖前采样 → `IgCtrlMsg` 同包眼点 → 全体 IG 回灌 | 同步权威位姿以 **LLA + 姿态** 为对外语义（内部转 ECEF） |
| `Host ⊕ offsetDeg` → `setCameraPose`                  | 通道偏移在 **ENU / 局部** 叠加后再变 ECEF               |
| 无新包 / 断线策略；防回声                             | 模式随场景是否含 `EllipsoidModel` 切换                  |


相机对象：仅主通道 `mainCamera`（Trackball / 同步共用）；**HUD 相机不同步**。

### 4.2 本地世界系位姿约定

- **坐标系**：本地笛卡尔世界系；与 Engine / LookAt / Trackball 一致：**Y-forward、Z-up**。
- **对外接口**：仅 `position`（世界 XYZ，米）+ 欧拉角 **YPR（度）**；不用四元数作为对外 / 同步接口。
- **旋转顺序**：`Rz(yaw) * Rx(pitch) * Ry(roll)`，与 `Engine::setCameraPose`、LookAt↔欧拉互逆一致。
- **LookAt 映射**（设相机）：

```text
eye     = position
forward = R(ypr) * (0, 1, 0)
up      = R(ypr) * (0, 0, 1)
center  = eye + forward * d          // 实现取 d = 1
→ LookAt(eye, center, up)
```

- **LookAt → 眼点**（主窗采样出站）：`position = eye`；由 `forward = normalize(center-eye)` 与 `up` 解出 YPR（`SynchronSystem` 内 `lookAtToHostEye`）。



### 4.3 Engine 位姿 API（已实现）


| API                                            | 说明                                                  |
| ---------------------------------------------- | ----------------------------------------------------- |
| `Engine::mainCamera()`                         | 返回主通道 `vsg::Camera`（viewMatrix 为 `LookAt`）    |
| `Engine::setCameraPose(position, eulerYprDeg)` | 按 §4.2 写入 LookAt；无相机或非 LookAt 时返回 `false` |


实现位置：`engine/source/engine.cpp`。单元标尺：`HostIGTests` 中 `setCameraPose writes LookAt from position and euler YPR`（`[unit][camera]`）。

有图形时 `SynchronSystem::applyHostEye` 调用 `setCameraPose`；无图形路径仍更新 `_lastApplied` 供观测。
### 4.4 Host→IG 写相机链路

```text
主窗 Trackball → update 覆盖前采样 → postFrame 同包扇出（含 A）
各 IG：preFrame 入队 → update：Host ⊕ offsetDeg → setCameraPose
```

**连接态与相机驱动（ABC 相同）：**


| 状态                                 | 相机驱动                                                           |
| ------------------------------------ | ------------------------------------------------------------------ |
| 从未连接 / 独立预览                  | 本地 Trackball / 键盘（可直接写相机）                              |
| 已连接且本帧收到新眼点（`hasEye=1`） | 更新缓存，**Host 位姿为准**（+ `offsetDeg`）                       |
| 已连接、有新 IGCtrl 但 `hasEye=0`    | **不入队新眼点**，等同「无新眼点」，走 `hostEyeStalePolicy`         |
| 已连接但本帧无新包                   | 由 `hostEyeStalePolicy` 决定                                       |
| 断开连接                             | **保留最后一帧 Host 位姿**（+ 标定；不自动跳回断线前的 Trackball） |


**无新包策略**（配置 `hostEyeStalePolicy`，默认 `ReuseLast`；经 `SynchronSystem::setHostEyeStalePolicy`，Engine 启动从 JSON 注入）：


| 策略          | 行为                                      |
| ------------- | ----------------------------------------- |
| **ReuseLast** | `update` 仍用缓存 Host 眼点写相机         |
| **Freeze**    | 本帧不改写 LookAt（停在上一帧已写入结果） |


**覆盖前采样要点**（细节与相位见 §5）：`handleEvents` 之后、回灌之前从 `mainCamera` 采样；与 `_lastApplied` 几乎相同则丢弃（防回声）；未采到则 `postFrame` 重发 `_lastSent`。权威窗 A 同样回灌 → 相对 Trackball **≥1 帧延迟**（与 B/C 一致）。

**刻意不做**：相对初始位姿的 XYZ delta；要求三窗初始 LookAt 一致；权威窗跳过回灌；长期独立 intent buffer（仅 `_lastSent` 供重发）。

### 4.5 `offsetDeg` 合成与 frustum

```text
composed.position     = host.position
composed.eulerYprDeg += offsetDeg.{yaw, pitch, roll}   // 分量相加（度）
→ setCameraPose(composed)
```

实现：`SynchronSystem::compose` / `applyHostEye`。Host 只发**同一主 view 眼点**；左右通道偏航来自各 IG 本地 JSON（§3.2）。

### 4.6 报文中的眼点（本地世界系）


| 项     | 约定                                                   |
| ------ | ------------------------------------------------------ |
| 打包   | 内嵌 `IgCtrlMsg`（`hasEye=1` 时 `pos*` / `*Deg` 有效） |
| 位置   | 世界绝对 XYZ（米）；不是经纬高，不是相对初始 delta     |
| 姿态   | YPR（度），顺序同 `setCameraPose`                      |
| 帧身份 | 同包 `frameCntr`；旧包整包丢弃（含眼点）               |




### 4.7 验收要点（对照 `HostIGTests`）

测试分层：应用契约可用 `queueHostEyePose` 注入；E2E 钉真 UDP 报文。主要场景：


| 场景             | 断言要点                                                       |
| ---------------- | -------------------------------------------------------------- |
| 位姿 API         | `setCameraPose` 后 LookAt 的 eye / center / up 与 YPR 约定一致 |
| 未连接不覆盖     | 注入 Host 眼点后 `update`，相机仍为本地位姿                    |
| 已连接覆盖       | 已连接时注入 → `update` → LookAt = Host 位姿                   |
| `offsetDeg` 合成 | 零偏移与非零偏移下 LookAt = Host ⊕ offset                      |
| ReuseLast        | 无新包时仍写回上一帧 Host 位姿                                 |
| Freeze           | 无新包时不改写 LookAt                                          |
| 断线保末帧       | 断开后仍保持最后 Host 位姿（+ offset）                         |
| 权威窗同样回灌   | A 已连接时也被 Host 眼点覆盖                                   |
| 覆盖前采样 E2E   | A 采样 intent → 扇出 → B 应用 ⊕ offset                         |
| 防回声           | 回灌后未再操作时不把旧位姿当新 intent 发出                     |
| 三通道           | A/B/C 各自 ⊕ 本地 offset 后位姿正确                            |


配置侧：`EngineConfigTests` 覆盖 `offsetDeg` / `hostEyeStalePolicy` 注入 `SynchronSystem`。

### 4.8 椭球 / ECEF 下的相机驱动（演进）

背景与 LLA / ECEF / ENU 分层见 [坐标系统总结.md](./坐标系统总结.md)。当前：`setCameraPose` / 同步**无** LLA↔ECEF 转换；若场景带 `"EllipsoidModel"`，Engine 已切 `EllipsoidPerspective` + 椭球 Trackball，但位姿仍按本地 XYZ 书写，与地球瓦片（几何在 ECEF）尚未对齐。

#### 模式划分


| 模式             | 判定（建议）                                  | 场景 World | 同步权威眼点                         | 通道偏移                          | 写相机                             |
| ---------------- | --------------------------------------------- | ---------- | ------------------------------------ | --------------------------------- | ---------------------------------- |
| **本地**（已有） | 场景无 `EllipsoidModel`                       | 本地笛卡尔 | 世界 XYZ + YPR                       | `offsetDeg` 欧拉相加              | `setCameraPose` 直接写 LookAt      |
| **椭球**（目标） | 场景有 `EllipsoidModel`（如 `readymap.vsgt`） | **ECEF**   | **LLA + 姿态**（或显式 ECEF + 姿态） | 在 **ENU / 局部** 叠加后再变 ECEF | LLA→ECEF（或已是 ECEF）→ 写 LookAt |


「有地球」= 加载椭球瓦片场景（几何已在 ECEF）+ 相机 / 同步与之对齐；不是单独的坐标系开关。

#### 椭球模式位姿语义

- **对外 / Host→IG**：优先 **LLA（lat°, lon°, alt m）+ 姿态**（姿态相对真北 / 天，具体约定实现时钉死）；内部立刻转 ECEF，再写 `LookAt`。
- **渲染工作坐标**：ECEF 米制笛卡尔；`LookAt.eye/center/up` 落在 ECEF。
- **通道偏移**：不宜继续假设「同一本地笛卡尔下只加 yaw」在全球任意点都成立；在参考 LLA 的 ENU（或等价局部系）内施加通道偏航 / 平移，再 `LocalToWorld` 到 ECEF。
- **Engine API 演进方向**：
  - 保留 `setCameraPose(position, eulerYprDeg)` 作为**本地模式**与「已换算到当前 World」的底层写入；
  - 增加椭球友好入口（名称待定），例如 `setCameraPoseLla(lla, ypr)` → `EllipsoidModel::convertLatLongAltitudeToECEF` → 构造 ECEF 下 LookAt（`up` 取局部天向更稳）；
  - 或由 `SynchronSystem::applyHostEye` 在椭球模式下完成换算后仍调用现有 `setCameraPose(ecef, …)`（若姿态也已变到 ECEF 可解释的 YPR）。
- **采样出站**：主窗覆盖前采样在椭球模式下应产出 **LLA + 姿态**（或 ECEF + 姿态）写入报文，避免把 ECEF 大数误当成「本地世界 XYZ」发给仍按本地解释的 IG。



#### 报文演进（建议）

在 `IgCtrlMsg`（或其后继）中区分坐标模式，例如：

- `coordFrame = WorldLocal | LLA`（名称待定）；
- `hasEye` 时：本地模式填 XYZ；椭球模式填 lat/lon/alt（或另增字段），姿态字段语义随模式解释。

乱序仍按 `frameCntr` 整包取新。未实现前，椭球场景勿假设现有 XYZ 眼点字段语义正确。

#### 与本地路径的关系

```text
本地模式（已有）:
  Host 眼点 = 世界 XYZ + YPR
  IG: XYZ ⊕ offsetDeg → setCameraPose → LookAt（本地 World）

椭球模式（目标）:
  Host 眼点 = LLA + 姿态（或 ECEF + 姿态）
  IG: LLA→ECEF；通道偏移在 ENU/局部叠加 → LookAt（World = ECEF）
```

椭球跟拍列入 §9 演进项；落地前本地路径行为不变。

## 5. 权威眼点、回灌与帧内时序

相机位姿语义与 API 见 **§4**；本节只固定 Host 权威源与单帧相位。

#### Host 权威眼点（ABC 作为 IG 行为一致）

目标：A/B/C 均为 IG，**最终渲染位姿一律来自 Host 回灌**；便于日后 Host 拆进程时 IG 侧逻辑不变。

**权威输入源（现阶段）**：带 Host 的主窗（`channelId==0`）。  
**下发方向**：眼点仅 **Host→IG**（内嵌于 `IgCtrlMsg`）。同进程下 Host 用主窗采样结果填充后扇出。

**后期**：Host 独立进程后，「权威 = 带 Host 的主窗」需改为指定输入 IG 上报或 Host 本地输入；上行格式另定。

**断线判据（当前）**：IgSync 轮询 TCP 对端关闭后清除 `tcpConnected` / `udpSynced`。UDP 超时、心跳与 Host 侧 peer 摘除仍待细化，见 §9。

#### IG：单帧写入时机（覆盖前采样 + 回灌）

主窗 A（Host + 权威输入）：

```text
preFrame:   收 UDP IgCtrlMsg → 入队眼点；若处理了 IGCtrl 则回 SOF；不写相机
update:
  handleEvents()                 ← Trackball 可能改 LookAt
  【覆盖前采样】                 ← 从 mainCamera 得本帧 pos+euler（含防回声）
  SynchronSystem::update()       ← Host 眼点 ⊕ offsetDeg → setCameraPose（含 A）
  viewer->update()
render
postFrame:
  用【本帧采样】或【_lastSent 重发】填 IgCtrlMsg，扇出 → 全体 ready IG
```

B/C（仅 IG）：无采样、无 Host；只收包并在 `SynchronSystem::update` 应用。

勿在 `handleEvents` **之前**写 Host 眼点。

#### Loop 相位（`preFrame / update / render / postFrame`）

```text
preFrame:   收 UDP（IgCtrlMsg，含可选眼点）→ 入队；处理 IGCtrl 时回 SOF
update:     handleEvents →【主窗覆盖前采样】→ SynchronSystem::update（应用眼点）→ viewer update
render:     record / present
postFrame:  主窗用本帧采样（或重发上一帧）填 IgCtrlMsg → 扇出全体 ready IG
```

## 6. 时钟、节拍与报文



### 6.1 模拟时间（现阶段）

- Host 在 `postFrame` / `HostSync::update(simTimeMs)` 把模拟时间写入 `IgCtrlMsg.simTimeMs`。
- **单位：毫秒（ms）**。Engine 侧当前按约 `1000/60` ms 每帧递增（与 FreeRun 帧步进一致）。
- **IG 侧暂不消费** `simTimeMs`（不做矫正 / 外推）；位姿跟拍只依赖眼点字段与 `frameCntr`。
- 不做 RTT offset。

乱序/迟到：只接受 `frameCntr` **不小于** 当前已处理帧的包（旧包整包丢弃）。

### 6.2 节拍策略


| 配置项           | 含义                          | 初步默认 / 现状                                        |
| ---------------- | ----------------------------- | ------------------------------------------------------ |
| `igCtrlSendPace` | 何时发下一帧 IGCtrl           | **FreeRun**（按调用方 fps，不等 SOF）                  |
| `frameGate`      | 是否等齐 SOF 再允许下一显示帧 | 配置可写 **BARRIER**，**实现仍按 FreeRun**（不等 SOF） |


```text
setPaceConfig(SyncPaceConfig{ igCtrlSendPace, frameGate, targetFps, barrierTimeoutMs })
HostSync::run() → RUNNING
HostSync::update(simTimeMs, eye*) → 本帧扇出 IGCtrl（FreeRun 不得阻塞等 SOF）
```

- **一次** `update` **= 一轮扇出**（对每个 ready IG 各发一份相同逻辑帧；`igCtrlSentCount` 计轮次，不是 UDP 包总数）。  
- 无独立周期 beacon；保活依赖 TCP 连接存活检测与 UDP 业务包。



### 6.3 报文字段（`sync_proto`）


| 报文        | 方向                           | 字段                            | 用途                                                     |
| ----------- | ------------------------------ | ------------------------------- | -------------------------------------------------------- |
| `IgCtrlMsg` | Host→IG                        | `simTimeMs`（**ms**）           | Host 下发的模拟时间（IG 暂未消费）                       |
| `IgCtrlMsg` | Host→IG                        | `frameCntr`                     | 帧身份；乱序裁决                                         |
| `IgCtrlMsg` | Host→**全体 ready IG（含 A）** | `hasEye` + 世界 XYZ + YPR（度） | 共用主眼点；与帧计数同包（本地系，见 §4.6；椭球见 §4.8） |
| `SofMsg`    | IG→Host                        | `frameCntr` 回显                | 健康、掉帧；**不门控** FreeRun 发帧                      |


握手另有 `HELLO` / `HELLO_ACK`（TCP）、`UDP_SYNC` / `UDP_SYNC_ACK`（UDP）。

同进程权威位姿来源：主窗 **覆盖前采样**（非独立上行报文）。Host 拆进程后的上行格式另定。

SOF：每成功处理一条 IGCtrl 在 **preFrame /** `IgSync::update` 回一条；丢 SOF 不阻塞下一 IGCtrl。

## 7. 配置与 API

```text
EngineChannelConfig (JSON)
  channelId, offsetDeg, igLocal, hostEndpoint, hostLocal?,
  model, window, hostEyeStalePolicy

AddressConfig     { addr, udpPortSend, udpPortRecv, tcpPort }
SyncPaceConfig    { igCtrlSendPace, frameGate, targetFps, barrierTimeoutMs }
SyncRoleConfig    { enableHost←(channelId==0), enableIg=true, hostLocal, igLocal, hostEndpoint }
HostEyeStalePolicy { ReuseLast, Freeze }
```

启动：`engine.exe -c <path-to-channel.json>`（省略则默认 `main.json`）→ 解析 JSON → 填 `SyncRoleConfig` / 窗口 / 模型 / 偏移角 / 无新包策略。


| API                                                | 说明                                                                                         |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `HostSync`/`IgSync::initialize`                    | 本地传输；未连接                                                                             |
| `IgSync::connect(host)`                            | TCP HELLO + UDP_SYNC 握手                                                                    |
| `HostSync::run` / `update(simTimeMs, eye*)`        | `simTime` 单位 **ms**；每轮扇出 IGCtrl（可选眼点）                                           |
| `SynchronSystem::captureAuthorityEye`              | 主窗：`handleEvents` 后、回灌前，从 mainCamera 采 pos+euler（含防回声）                      |
| 眼点扇出                                           | Host：`IgCtrlMsg.hasEye` 与 `frameCntr` 同包 → **全体 ready IG（含 A）**                     |
| `IgSync::update` / 收包                            | preFrame 调用；按 `frameCntr` 取新；处理成功则回 SOF                                         |
| `HostSync::setPaceConfig`                          | 发送节拍 / 进帧门控（Barrier 尚未生效）                                                      |
| `SynchronSystem::setHostEyeStalePolicy`            | 来自配置 `hostEyeStalePolicy`（Engine 启动注入）                                             |
| `Engine` 启动                                      | `-c` → `main`/`left`/`right`.json（省略默认 main）                                           |
| `Engine::mainCamera` / `setCameraPose(pos, euler)` | 本地世界系写 LookAt；已连接时由 Host 回灌调用（§4）                                          |
| `SynchronSystem::update`                           | 全体 IG：Host 眼点 ⊕ `offsetDeg` → `setCameraPose`                                           |
| 计数器                                             | `igCtrlSentCount`、`igCtrlReceivedCount`、`lastIgCtrlFrameCntr`、`sofSent*` / `sofReceived*` |


连接状态：`tcpConnected` / `udpSynced`（IG）；Host `readyIgCount`（`tcpReady && udpReady`）。

## 9. 初步同步仍有疏漏（待补）

按「多通道初步能跟拍」优先级。P0 眼点跟拍主路径（采样、同包扇出、`offsetDeg`、ReuseLast/Freeze、断线保末帧）**已实现**（本地世界系，见 §4）；下列为剩余缺口。

### P0 — 仍影响跟拍闭环完整性

1. **断线判据钉死**
  当前仅 TCP 对端关闭检测；UDP 超时、与 `ready` / peer 摘除的关系仍待约定并实现。



### P1 — 初步可先简陋，但需有约定

1. **IG 消费** `simTimeMs`（矫正 / 外推）及丢包后外推上限（超时后冻结还是继续跑）。
2. **起跑条件**：是否等 `readyIgCount` 再开帧；中途断线 peer 摘除。
3. **TCP 命令与场景一致**（加载/切库/复位 + ACK/NACK；多通道同场景加载完成再开帧）。词义见 [socket总结.md](./socket总结.md) §2.1。
4. **心跳**周期、超时、与 `ready` 的关系（若需要比 TCP 存活检测更细的保活）。
5. **Barrier（`frameGate`）**超时/quorum（配置位已有，实现仍 FreeRun）。
6. **LookAt↔欧拉**奇异附近的数值策略（本地系与椭球系均需约定）。



### P1 — 椭球 / ECEF 相机驱动（§4.8）

1. 模式判定（场景 `EllipsoidModel`）与位姿路径切换。
2. Host→IG 报文：LLA + 姿态（或 ECEF）；IG 侧 LLA→ECEF→LookAt。
3. 通道偏移改为 ENU / 局部叠加后再变 ECEF。
4. 覆盖前采样出站与 `setCameraPose` / 应用层 API 的椭球入口。
5. 椭球路径的 BDD / 系统测试（地球瓦片场景）。



### P2 — 明确不在初步范围（防范围蔓延）

1. 显示同步（VSync 对齐、Genlock、swap 屏障）
2. 精时钟同步（RTT offset / PTP）
3. 边缘融合、非对称分辨率通道的完整光学标定
4. Host 独立进程与发现/配置中心
5. 改走真实 CIGI CCL 线协议（当前为 `sync_proto`）
