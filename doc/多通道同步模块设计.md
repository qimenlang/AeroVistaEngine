面向本项目 **1 Host + 多 IG（IP 可不同，目标约 10 通道）**。  
TCP/UDP、端口与连通性见 [socket总结.md](./socket总结.md)。  
验收规格：`engine/Tests/`（Catch2）。

线协议为自定义 `sync_proto`（`SyncProtocol.h`），**不是** CIGI CCL 上线格式；报文命名沿用 IGCtrl / SOF 语义。

## 0. 初步同步：范围与目标

**初步同步**要先跑通「多通道跟同一 Host 节拍 + 共用眼点 + 通道视锥相邻」，不追求显示卡 Genlock / 亚毫秒校时。

| 纳入初步                                               | 暂不纳入                                     |
| ------------------------------------------------------ | -------------------------------------------- |
| 连接：TCP HELLO 握手 + UDP 同步面握手（`UDP_SYNC`）    | RTT / NTP 式时钟 offset                      |
| FreeRun：Host 按帧自动发 IGCtrl（不等 SOF）            | Barrier 等齐再发下一帧（可后加 `frameGate`） |
| Host 在 IGCtrl 填入 `simTimeMs`（毫秒）；IG 侧暂不消费 | IG 对 `simTimeMs` 做矫正 / 外推              |
| 每收到 IGCtrl 回一条 SOF（健康 / 掉帧观察）            | 可靠 UDP、丢包重传                           |
| 每帧 IGCtrl 可内嵌共用眼点；各 IG 本地 `offsetDeg` 算 frustum | 实体级全量状态同步细则                |
| 1 主窗（Host+IG）+ N 从窗（仅 IG）Engine 集成          | 边缘融合 / 几何精标定工具链                  |
| TCP 仅握手（HELLO / HELLO_ACK）                        | TCP 加载/切库/复位等命令面 + ACK/NACK        |
| 独立 Host 进程（先挂 Engine）                          |                                              |

## 1. 职责划分

| 类型               | 职责                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------- |
| **IgSync**         | UDP bind、`connect(Host)`（TCP HELLO + UDP_SYNC）、收 `IGCtrl`（含可选眼点）、回 `SOF`     |
| **HostSync**       | UDP bind + TCP `listen`、收各 IG 的 `SOF`、按帧扇出 `IGCtrl`/眼点；维护 IG peer 表          |
| **SynchronSystem** | Engine 门面：挂 loop；持有 **IgSync**；可选持有 **HostSync**；覆盖前采样、回灌 ⊕ `offsetDeg`、无新包/断线策略 |
| **Engine**         | 帧循环 `preFrame / update / render / postFrame`；从配置注入偏移与无新包策略                 |

```text
Engine::tickOnFrame
  preFrame  → SynchronSystem 收包（入队眼点；处理 IGCtrl 时回 SOF；不写相机）
  update    → handleEvents →【主窗覆盖前采样】→ SynchronSystem::update（写 Host 眼点）→ viewer update
  render
  postFrame → Host 用本帧采样（或重发上一帧）填入 IgCtrlMsg，扇出 → 全体 ready IG（含 A）
```

### 1.1 HostSync 进程边界

- **最终**：HostSync 独立进程；ABC 均为纯 IG，行为一致。  
- **当前**：HostSync 挂主窗 Engine；眼点权威 = 主窗覆盖前采样 → Host 扇出 → 全体 IG 回灌（含 A，≥1 帧延迟），不为 A 开「跳过回灌」旁路。  
- 拆进程后：Engine 侧仅留 IgSync；权威源改为指定输入 IG 上行或 Host 本地输入（见 §4）。

## 2. 双平面与拓扑

| 平面    | 通道 | 流量（当前实现）                                      | 必达             |
| ------- | ---- | ----------------------------------------------------- | ---------------- |
| sync    | UDP  | 握手（`UDP_SYNC`/`ACK`）、`IG_CTRL`（+可选眼点）、`SOF` | 否；丢了用下一帧 |
| command | TCP  | 目前仅 `HELLO` / `HELLO_ACK`（接入握手）              | 是（握手）       |

> 加载/切库/复位等 TCP 业务命令 + ACK/NACK：**尚未实现**，见 §8。

```text
HostSync UDP :8000  ← SOF / UDP 握手
         sendto → 各 IG:udpRecv（IGCtrl）
HostSync TCP :8100  ← 各 IgSync connect（HELLO）
```

默认端口：Host 收 **8000**、发 **8001**；TCP **8100**。同机多 IG：`udpRecv` 必须不同（8001/8003/8005…）；多机可同用 8001。

Peer 表：`{ip, udpRecvPort, tcp, tcpReady, udpReady}`。两端都 ready 才计入扇出目标 / `readyIgCount`。接入时从 HELLO 学习 `udpRecvPort`。

## 3. 多窗口用法与通道配置

典型：3 Engine——A 主窗（Host+IG），B/C 从窗（仅 IG）；桌面相邻、frustum 相邻。

### 3.1 坐标系与位姿表示

- **默认：世界坐标系**（与当前 Engine / LookAt / Trackball 一致：Y-forward、Z-up）。
- **暂不使用椭球坐标系**。
- `setCameraPose` / 眼点报文：仅 `position` + 欧拉角（euler YPR，度），不用四元数作为对外接口。

### 3.2 通道启动配置（JSON）

每个 Engine 进程一份通道配置；命令行传入路径：

```text
engine.exe --config engine/resources/config/main.json
engine.exe --config engine/resources/config/left.json
engine.exe --config engine/resources/config/right.json
```

目录：`engine/resources/config/`。三通道样例文件：

| 文件         | 角色           | `channelId` | 典型偏移                     |
| ------------ | -------------- | ----------- | ---------------------------- |
| `main.json`  | 主通道 Host+IG | `0`         | yaw/pitch/roll = 0           |
| `left.json`  | 左从通道仅 IG  | `1`         | yaw ≈ +hFOV（640×1080、vFOV30° → +18.05°） |
| `right.json` | 右从通道仅 IG  | `2`         | yaw ≈ −hFOV（−18.05°）                     |

**角色推导（不单独配** `enableHost`**）：**

- `channelId == 0` → `enableHost=true`，并启用 `hostLocal`；同时 `enableIg=true`
- `channelId > 0` → `enableHost=false`，仅 IG；`hostLocal` 可忽略

**配置字段与业务逻辑：**

| 字段                         | 用途                                                                                                      |
| ---------------------------- | --------------------------------------------------------------------------------------------------------- |
| `channelId`                  | 通道号；决定是否启动 Host                                                                                 |
| `offsetDeg.{yaw,pitch,roll}` | 本通道相对主视向的 frustum 偏移（度）；收 Host 眼点后叠加                                                 |
| `igLocal`                    | 本机 IgSync bind：`addr` / `udpPortSend` / `udpPortRecv` / `tcpPort`；同机多 IG 的 `udpPortRecv` 必须不同 |
| `hostEndpoint`               | IG 连接的 Host 端点（IP + 端口）                                                                          |
| `hostLocal`                  | 仅 `channelId==0`：HostSync 本机 bind                                                                     |
| `model`                      | 启动加载的场景/模型路径                                                                                   |
| `window.{x,y,width,height}`  | 窗口位置与分辨率（见下「系统测试专用」）；是否显示由 `Engine::showWindow` 控制（默认显示，不进配置）      |
| `hostEyeStalePolicy`         | 已连接且无新眼点：`ReuseLast` / `Freeze`                                                                  |

应用位姿：

```text
最终位姿 = Host(pos+euler) ⊕ offsetDeg → setCameraPose
```

样例结构见仓库内 `main.json` / `left.json` / `right.json`。格式选用 **JSON**（扁平、无额外 XML 依赖）。

**系统测试专用：三通道窗口铺满桌面（1920×1080）**

> 以下 `window` 布局仅用于本机多进程联调 / 系统测试（三 `engine.exe` 并排铺满桌面），**不是**产品部署或光学标定的正式分辨率方案。正式部署可按现场显示器改写各通道 `window` 字段。

| 配置文件     | 位置 (x,y) | 尺寸 (w×h) | 桌面区域 |
| ------------ | ---------- | ---------- | -------- |
| `left.json`  | (0, 0)     | 640×1080   | 左       |
| `main.json`  | (640, 0)   | 640×1080   | 中       |
| `right.json` | (1280, 0)  | 640×1080   | 右       |

Engine 启动读配置后设置 `vsg::WindowTraits::{x,y,width,height}`（当前 `decoration=false` 无边框，三窗可无缝拼接）。示例：

```text
engine.exe -c engine/resources/config/left.json
engine.exe -c engine/resources/config/main.json
engine.exe -c engine/resources/config/right.json
```

### 3.3 通道 frustum 拼接（标定）

眼点相同（世界系）；投影参数一致时，水平相邻靠偏航：

- `aspect = 宽/高`；`hFOV = 2·atan(aspect·tan(vFOV/2))`
- 三通道硬拼（本引擎 Y-forward、Z-up，`Rz(+yaw)` 转向 −X / 左侧）：中 `yaw=0`，**左 `+hFOV`，右 `−hFOV`**；融合则幅值用 `hFOV−overlap`、符号同上
- 标定存各 IG 本地；同步包只更新共用眼点

## 4. 权威眼点、回灌与帧内时序

#### Host 权威眼点（ABC 作为 IG 行为一致）

目标：A/B/C 均为 IG，**最终渲染位姿一律来自 Host 回灌**；便于日后 Host 拆进程时 IG 侧逻辑不变。

**权威输入源（现阶段）**：带 Host 的主窗（`channelId==0`）。  
**下发方向**：眼点仅 **Host→IG**（内嵌于 `IgCtrlMsg`，不是独立上行包）。同进程下 Host 用主窗采样结果填充后扇出。

```text
主窗 Trackball → LookAt
  →【覆盖前采样】pos+euler
  → postFrame：写入 IgCtrlMsg（hasEye=1），与 frameCntr / simTimeMs 同包扇出
  → 全体 ready IG（含 A）
各 IG：preFrame 入队 → update：Host 眼点 ⊕ offsetDeg → setCameraPose
```

##### 覆盖前采样（方案 B）

- **本帧采样**：`handleEvents()` 之后、`SynchronSystem::update()`（回灌写相机）**之前**，从主窗 `mainCamera`/LookAt 得到本帧 `pos + euler`，存入本帧 `_frameSample`。
- **用途**：仅供本帧 `postFrame` 填充下发眼点；避免读到已被回灌覆盖的相机（回声环 / Trackball 失效）。
- **防回声**：若采样结果与上一帧已写入相机的 `_lastApplied`（Host⊕offset）几乎相同，视为无新 intent，本帧不采用该采样。
- **本帧未采到**（未 init / 无相机 / 防回声丢弃等）：`postFrame` **重发**缓存的上一帧权威眼点 `_lastSent`。
- 权威窗 A 同样在 `update` 应用 Host 回灌 → 相对 Trackball **≥1 帧延迟**（与 B/C 一致，属预期）。

##### `IgCtrlMsg` 眼点字段（`sync_proto`，语义对齐原 EntityPosition「Detach 世界位姿」）

| 项 | 约定 |
|----|------|
| 打包方式 | 眼点内嵌于同一 `IgCtrlMsg`（`hasEye=1` 时 `pos*` / `*Deg` 有效）；**不是**独立 CIGI EntityPosition 包 |
| 位置 | 世界绝对 **XYZ**（`posX/Y/Z`；不是经纬高，也不是相对初始位姿的 delta） |
| 姿态 | LookAt 转出的 **Yaw/Pitch/Roll（度）**；顺序与 `Engine::setCameraPose` 一致（`Rz(yaw)*Rx(pitch)*Ry(roll)`） |
| 与帧身份 | 同包 `frameCntr`；乱序时旧包**整包丢弃**（含眼点） |
| 扇出 | Host 只发 **同一主 view 眼点**；左右偏航来自各 IG 本地 JSON `offsetDeg` |

扇出目标 = **全体 ready IG（含 A）**。频率 = Engine fps（FreeRun）。

**后期**：Host 独立进程后，「权威 = 带 Host 的主窗」需改为指定输入 IG 上报或 Host 本地输入；上行格式另定。

##### 刻意不做

- 不按「相对初始位姿的 XYZ 差值」填眼点。
- 不要求三窗初始 LookAt 一致再算 delta；共享 Host 主眼点 + 本地标定即可。
- 不采用「权威窗不回灌」或「长期独立 intent buffer」（仅有 `_lastSent` 供重发）。

#### IG：连接 / 无新包 / 断线（ABC 相同）

| 状态 | 相机驱动 |
|------|----------|
| 从未连接 / 独立预览 | 本地 Trackball / 键盘（可直接写相机） |
| 已连接且本帧收到新眼点（`hasEye=1`） | 更新缓存，**Host 位姿为准**（+ `offsetDeg`） |
| 已连接、有新 IGCtrl 但 `hasEye=0` | **沿用上一帧眼点**（与 ReuseLast 一致） |
| 已连接但本帧无新包 | 由 **无新包策略** 决定（见下） |
| 断开连接 | **保留最后一帧 Host 位姿**（+ 标定；不自动跳回断线前的 Trackball 状态） |

**无新包策略**（已连接时，来自配置 `hostEyeStalePolicy`，二选一）：

| 策略 | 行为 |
|------|------|
| **ReuseLast（沿用）** | `SynchronSystem::update` 仍用上一帧缓存的 Host 眼点写相机 |
| **Freeze（冻结）** | 本帧不再改写相机 LookAt（停在上一帧已写入结果；已连接时 Trackball 仍被回灌逻辑抑制） |

```text
SynchronSystem::setHostEyeStalePolicy(ReuseLast | Freeze)   // 默认 ReuseLast；Engine 启动时从配置注入
```

**断线判据（当前）**：IgSync 轮询 TCP 对端关闭后清除 `tcpConnected` / `udpSynced`。UDP 超时、心跳与 Host 侧 peer 摘除仍待细化，见 §8。

#### IG：单帧写入时机（覆盖前采样 + 回灌）

主窗 A（Host + 权威输入）：

```text
preFrame:   收 UDP IgCtrlMsg → 入队眼点；若处理了 IGCtrl 则回 SOF；不写相机
update:
  handleEvents()                 ← Trackball 可能改 LookAt
  【覆盖前采样】                 ← 从 mainCamera 得本帧 pos+euler（含防回声）
  SynchronSystem::update()       ← Host 眼点 ⊕ offsetDeg → setCameraPose（含 A）
  viewer->update()
render
postFrame:
  用【本帧采样】或【_lastSent 重发】填 IgCtrlMsg，扇出 → 全体 ready IG
```

B/C（仅 IG）：无采样、无 Host；只收包并在 `SynchronSystem::update` 应用。

勿在 `handleEvents` **之前**写 Host 眼点。  
相机访问：`Engine::mainCamera()`；HUD 相机不同步。

#### Loop 相位（`preFrame / update / render / postFrame`）

```text
preFrame:   收 UDP（IgCtrlMsg，含可选眼点）→ 入队；处理 IGCtrl 时回 SOF
update:     handleEvents →【主窗覆盖前采样】→ SynchronSystem::update（应用眼点）→ viewer update
render:     record / present
postFrame:  主窗用本帧采样（或重发上一帧）填 IgCtrlMsg → 扇出全体 ready IG
```

## 5. 时钟、节拍与报文

### 5.1 模拟时间（现阶段）

- Host 在 `postFrame` / `HostSync::update(simTimeMs)` 把模拟时间写入 `IgCtrlMsg.simTimeMs`。
- **单位：毫秒（ms）**。Engine 侧当前按约 `1000/60` ms 每帧递增（与 FreeRun 帧步进一致）。
- **IG 侧暂不消费 `simTimeMs`**（不做矫正 / 外推）；位姿跟拍只依赖眼点字段与 `frameCntr`。
- 不做 RTT offset。

乱序/迟到：只接受 `frameCntr` **不小于** 当前已处理帧的包（旧包整包丢弃）。

### 5.2 节拍策略

| 配置项           | 含义                          | 初步默认 / 现状                       |
| ---------------- | ----------------------------- | ------------------------------------- |
| `igCtrlSendPace` | 何时发下一帧 IGCtrl           | **FreeRun**（按调用方 fps，不等 SOF） |
| `frameGate`      | 是否等齐 SOF 再允许下一显示帧 | 配置可写 **BARRIER**，**实现仍按 FreeRun**（不等 SOF） |

```text
setPaceConfig(SyncPaceConfig{ igCtrlSendPace, frameGate, targetFps, barrierTimeoutMs })
HostSync::run() → RUNNING
HostSync::update(simTimeMs, eye*) → 本帧扇出 IGCtrl（FreeRun 不得阻塞等 SOF）
```

- **一次** `update` **= 一轮扇出**（对每个 ready IG 各发一份相同逻辑帧；`igCtrlSentCount` 计轮次，不是 UDP 包总数）。  
- 无独立周期 beacon；保活依赖 TCP 连接存活检测与 UDP 业务包。

### 5.3 报文字段（`sync_proto`）

| 报文 | 方向 | 字段 | 用途 |
|------|------|------|------|
| `IgCtrlMsg` | Host→IG | `simTimeMs`（**ms**） | Host 下发的模拟时间（IG 暂未消费） |
| `IgCtrlMsg` | Host→IG | `frameCntr` | 帧身份；乱序裁决 |
| `IgCtrlMsg` | Host→**全体 ready IG（含 A）** | `hasEye` + 世界 XYZ + YPR（度） | 共用主眼点；与帧计数同包 |
| `SofMsg` | IG→Host | `frameCntr` 回显 | 健康、掉帧；**不门控** FreeRun 发帧 |

握手另有 `HELLO` / `HELLO_ACK`（TCP）、`UDP_SYNC` / `UDP_SYNC_ACK`（UDP）。

同进程权威位姿来源：主窗 **覆盖前采样**（非独立上行报文）。Host 拆进程后的上行格式另定。

SOF：每成功处理一条 IGCtrl 在 **preFrame / `IgSync::update`** 回一条；丢 SOF 不阻塞下一 IGCtrl。

## 6. 配置与 API

```text
EngineChannelConfig (JSON)
  channelId, offsetDeg, igLocal, hostEndpoint, hostLocal?,
  model, window, hostEyeStalePolicy

AddressConfig     { addr, udpPortSend, udpPortRecv, tcpPort }
SyncPaceConfig    { igCtrlSendPace, frameGate, targetFps, barrierTimeoutMs }
SyncRoleConfig    { enableHost←(channelId==0), enableIg=true, hostLocal, igLocal, hostEndpoint }
HostEyeStalePolicy { ReuseLast, Freeze }
```

启动：`engine.exe --config <path-to-channel.json>` → 解析 JSON → 填 `SyncRoleConfig` / 窗口 / 模型 / 偏移角 / 无新包策略。

| API | 说明 |
| --- | --- |
| `HostSync`/`IgSync::initialize` | 本地传输；未连接 |
| `IgSync::connect(host)` | TCP HELLO + UDP_SYNC 握手 |
| `HostSync::run` / `update(simTimeMs, eye*)` | `simTime` 单位 **ms**；每轮扇出 IGCtrl（可选眼点） |
| `SynchronSystem::captureAuthorityEye` | 主窗：`handleEvents` 后、回灌前，从 mainCamera 采 pos+euler（含防回声） |
| 眼点扇出 | Host：`IgCtrlMsg.hasEye` 与 `frameCntr` 同包 → **全体 ready IG（含 A）** |
| `IgSync::update` / 收包 | preFrame 调用；按 `frameCntr` 取新；处理成功则回 SOF |
| `HostSync::setPaceConfig` | 发送节拍 / 进帧门控（Barrier 尚未生效） |
| `SynchronSystem::setHostEyeStalePolicy` | 来自配置 `hostEyeStalePolicy`（Engine 启动注入） |
| `Engine` 启动 | `-c` / `--config` → `main`/`left`/`right`.json |
| `Engine::mainCamera` / `setCameraPose(pos, euler)` | 世界系；YPR 度；已连接时由 Host 回灌写入 |
| `SynchronSystem::update` | 全体 IG：Host 眼点 ⊕ `offsetDeg` → `setCameraPose` |
| 计数器 | `igCtrlSentCount`、`igCtrlReceivedCount`、`lastIgCtrlFrameCntr`、`sofSent*` / `sofReceived*` |

连接状态：`tcpConnected` / `udpSynced`（IG）；Host `readyIgCount`（`tcpReady && udpReady`）。

## 7. 角色流程（摘要）

```text
A: HostSync.initialize + IgSync.initialize/connect（主窗）
B/C: IgSync.initialize/connect → Host readyIgCount 增加
Host.run + 每帧 update(simTimeMs, eye*) 扇出
  → 各 IG preFrame 收包/回 SOF → update 应用眼点
```

TCP 业务命令面（带 `seq` 的加载/切库等 → ACK/NACK → 超时重试、幂等）：**尚未实现**，见 §8。

## 8. 初步同步仍有疏漏（待补）

按「多通道初步能跟拍」优先级。P0 眼点跟拍主路径（采样、同包扇出、`offsetDeg`、ReuseLast/Freeze、断线保末帧）**已实现**；下列为剩余缺口。

### P0 — 仍影响跟拍闭环完整性

1. **断线判据钉死**  
   当前仅 TCP 对端关闭检测；UDP 超时、与 `ready` / peer 摘除的关系仍待约定并实现。

### P1 — 初步可先简陋，但需有约定

1. **IG 消费 `simTimeMs`**（矫正 / 外推）及丢包后外推上限（超时后冻结还是继续跑）。
2. **起跑条件**：是否等 `readyIgCount` 再开帧；中途断线 peer 摘除。
3. **TCP 命令与场景一致**（加载/切库/复位 + ACK/NACK；多通道同场景加载完成再开帧）。
4. **心跳**周期、超时、与 `ready` 的关系（若需要比 TCP 存活检测更细的保活）。
5. **Barrier（`frameGate`）**超时/quorum（配置位已有，实现仍 FreeRun）。
6. **LookAt↔欧拉**奇异附近的数值策略。

### P2 — 明确不在初步范围（防范围蔓延）

1. 显示同步（VSync 对齐、Genlock、swap 屏障）
2. 精时钟同步（RTT offset / PTP）
3. 边缘融合、非对称分辨率通道的完整光学标定
4. Host 独立进程与发现/配置中心
5. 改走真实 CIGI CCL 线协议（当前为 `sync_proto`）
