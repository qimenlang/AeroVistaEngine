# Socket 基础：TCP / UDP 与端口

多通道同步相关的通用网络知识。本项目具体选型见 [多通道同步.md](./多通道同步.md)。

---

## 1. UDP 不是“广播协议”

UDP 是无连接数据报，常用三种投递方式：

| 方式 | 含义 | 典型用途 |
|------|------|----------|
| **单播 unicast** | 发到某一个 `IP:port` | 点对点控制与回程（最常见） |
| **组播 multicast** | 一份数据，订阅者都收 | 一对多扇出优化 |
| **广播 broadcast** | 网段内尽量都收 | 少用（吵、受限） |

“用了 UDP”≠“在广播”。Host→多 IG 可以是 **单播扇出 N 次**，也可以是组播；默认单播更简单、更好控。

---

## 2. TCP 与 UDP 如何分工（一般原则）

| 流量特征 | 更合适 | 原因 |
|----------|--------|------|
| 周期性、时效优先、可丢（心跳、帧节奏、每帧状态） | **UDP** | 低延迟；丢了用下一帧补 |
| 必须落地执行（加载、切库、复位、业务指令） | **TCP** 或 UDP+序号/ACK/重传/幂等 | 需回执与重试 |

不建议把整条高频帧同步链路改成 TCP：队头阻塞与延迟抖动不利于显示同步。

TCP 与 UDP **端口号可以相同**（如 `8000/tcp` 与 `8000/udp`）：内核按协议区分，**不会在内核里互相阻塞**。真正要隔离的是应用收发路径（独立 socket / 独立循环），避免一边阻塞读拖死另一边。

---

## 3. 本地端口 vs 发送目标

| 概念 | 含义 |
|------|------|
| **本地 bind 端口** | 本机 `bind`，用来收包 |
| **发送目标** | `sendto(对方IP, 对方端口)` 或 TCP `connect` 的对端 |

收发“端口分离”指的是 **本端收口与对端收口可以是不同端口号**，并不意味着发送方要为每个对端再 `bind` 一个本地发送端口。  
一个 UDP socket 通常：`bind` 一个本地收端口 + 向多个远程 `IP:port` 做 `sendto`。

TCP 服务端：`listen` **一个**端口，`accept` 出 **N 条连接**；不是 N 个 listen。

---

## 4. UDP 单端口双向 vs 双端口交叉

| 方案 | 做法 | 优势 | 劣势 |
|------|------|------|------|
| 单端口双向 | 双方都用同一端口号收发（不同机器 IP 不同） | 端口少、配置简单 | **同机**同时起两端易 bind 冲突；抓包难靠端口区分上下行 |
| 双端口交叉 | A 发→P0 / 收←P1，B 发→P1 / 收←P0 | 同机联调友好；端口可区分方向 | 每链路两个角色端口，配置易配反 |

同机 Host+IG 联调、希望按端口区分上下行时，双端口交叉更合适；纯多机部署时单端口也常见。

---

## 5. “已连接”怎么检查

| 平面 | 仅 socket 就绪（不够） | 建议的连通判据 |
|------|------------------------|----------------|
| **UDP** | `bind` / 能 `sendto` 成功 | 收到对端预期报文（或探测+应答）并在超时内完成 |
| **TCP** | `socket` 创建成功 | `connect`/`accept` 成功；可选应用层握手 ACK |

UDP **没有** TCP 那种握手连接；不能把 `bind` 成功当成“已连上对端”。  
分项状态（如 `udpSynced` / `tcpConnected`）应分开检查，便于判断是哪一平面失败。

客户端连服务端时，**UDP `sendto` 与 TCP `connect` 都需要对方 IP**（或可解析的主机名）。服务端 TCP `listen` 可先不写死客户端 IP；若服务端还要对客户端做 UDP 单播，仍需客户端地址表（配置或接入时上报）。

---

## 6. 主从连接语义（常见）

| 角色 | 典型行为 |
|------|----------|
| 服务端（如 Host） | 初始化：bind / listen，**等待**客户端 |
| 客户端（如 IG） | 初始化：本地 bind，再 **Connect** 到服务端 |

服务端一般不主动 `Connect` 客户端；“全部就绪”由服务端汇总 N 个客户端状态。
